# D4 避免歧义（Grice manner-2, avoid ambiguity）v0.1.1

> talkstyle-skill v0.1 第 4 维度。codex review 第 1 轮后修订版。
> **D4 是 v0.1 六维度里唯一引入"pass / fail / flag"三态的维度**（其他维度都是 pass / fail 二态）。

## D4.1 精确定义

**D4 避免歧义**：句子在当前对话上下文中**有且仅有一种合理理解**，且该理解由**显式文本锚点**支持（不接受常识脑补 / 作者意图推断 / 相邻默认原则）。

D1 管"字面 ≠ 意图"的转义类歧义（反语 / 委婉 / 暗示——意图层歧义）；D4 管"字面本身"的歧义（字面层多解读）。Different domains, 几乎不重叠。

**学术锚点**：Grice 合作原则 · 方式准则之二（avoid ambiguity）。

**注（codex review 修订）**："上下文消歧"必须靠**显式文本锚点**——不能让 LLM 用脑补常识当上下文。例如"他走了"如果上下文只有"他走了"这一句，LLM 不能脑补"按上下文应该是 X"判定 pass。

## D4.2 禁止 3 类

### 类别 1：指代歧义

**定义**：代词 / 指示词 / 称谓存在 ≥2 个合理候选指称物，且当前对话流无显式文本锚点限定到单一候选。

**判定信号（codex review 修订）**：句中出现 他 / 她 / 它 / 这个 / 那个 / 前者 / 后者 等代词或指示词，且当前对话流中**存在 ≥2 个合理候选指称对象**（不是看代词数量，是看候选对象数量），且对话文本中找不到显式语句限定到单一候选。

| 反例 | 正例 |
|---|---|
| "**他**对**他**说，**他**不来。" | "**李四对张三说，李四不来**。" |
| "他刚跟**他的朋友**吵完。**他**很生气。" | "他刚跟朋友吵完。**他自己**很生气。" |
| "**这个**给**那个**了。" | "**苹果**给**李四**了。" |

### 类别 2：句法歧义（多解析树）

**定义**：句子语法结构允许多个 parse tree，对应不同意思。

**判定信号**：修饰语作用域不明 / 并列结构模糊 / 否定范围不清 / 量词作用对象不确定。

| 反例 | 解读分叉 | 正例 |
|---|---|---|
| "**他打人很厉害**。" | a) 他打架很厉害 / b) 他真的打得很重 | "**他打架很厉害**。" / "**他动手很重**。" |
| "**我看见她拿着望远镜**。" | a) 我用望远镜看见她 / b) 她拿着望远镜被我看见 | "**我用望远镜看见了她**。" / "**我看见她手里拿着望远镜**。" |
| "**他跟他姐姐说他不来**。" | a) 李四跟张三的姐姐说... / b) 张三跟李四的姐姐说... | "**李四跟张三的姐姐说，李四不来**。" |

注：例 2 是经典 PP-attachment 歧义（介词短语挂载位置不确定）。

### 类别 3：词汇歧义（多义词无消歧）

**定义**：使用一个多义词，但当前对话文本无显式锚点限定具体义项。

**判定信号**：常见多义词（如 苹果 / 老 / 黄 / 走 / 起 / 完 / 上 / 下 等）出现，**且对话文本中找不到限定义项的显式语句**。

| 反例 | 解读分叉 | 正例 |
|---|---|---|
| "**苹果**最近不好。" | a) 水果苹果 / b) 苹果公司 / c) 别人叫苹果的 | "**苹果手机**最近不好。" |
| "他**走**了。" | a) 离开 / b) 走路 / c) 去世 | "他**刚走出门**。" / "他**三天前走了**（去世）。" |
| "你**老**这样不行。" | a) 一直 / 总 / b) 衰老 | "**你总这样不行**。" |

## D4.3 判定规则（三态：pass / fail / flag）

**codex review 修订**：D4 不像 D2 / D3 那样硬"fail or pass"；引入三态。

```
Step 1【模式扫描】
   句中有无 §D4.2 三类之一？
   - 无 → pass D4
   - 有 → 进 Step 2

Step 2【显式锚点检查】
   当前对话文本（前后几句 / 场景描述 / 角色身份）
   是否含**显式锚点**限定到单一解读？

   "显式锚点"定义：对话文本中存在能直接限定多义 / 指代 /
   句法多解的实名词、限定语、上下文事实。
   **不接受**：常识脑补、作者意图推断、相邻默认原则。

   - 有显式锚点 → pass D4
   - 无显式锚点 → 进 Step 3

Step 3【冲突评估】
   解读分叉里有几个在当前上下文都合理？
   - ≥2 个都合理（双解都说得通）→ fail D4
   - 单句脱离上下文也无法定位（如 ≥3 个代词冲突）→ fail D4
   - 1 个合理 + 其他需要文本外信息才能排除 → flag D4
     （让人审决定）
```

### 三态含义

| 状态 | 含义 | 触发条件 |
|---|---|---|
| **pass** | 显式文本锚点消歧 OK | 上下文里能找到限定词 / 实名指称 |
| **flag** | LLM 不确定但可能可解 | 上下文不足，需要人审才能定 |
| **fail** | 单句明显冲突 OR 双解都合理 | ≥3 个代词无法定位 / 两个解读都符合上下文 |

### 为何 D4 独有 flag（其他维度无此路径）

D4 在 v0.1 六维度里**结构性最难判**：

- 不像 D1 能调 lookup_dictionary 调字典背书
- 不像 D2 / D3 / D5 能命中即砍
- 中文重上下文，绝对无歧义不现实
- 强 fail 立场会大量误杀本可消歧的句子

flag 限定于"上下文不足但可能可解"这个窄场景；其他场景（单句明显冲突、双解都合理）仍硬 fail。

## D4.4 边界

**允许（pass D4）**：

- 显式文本锚点消歧（如"他咬了一口苹果。**苹果**最近不好。" → 上文"咬一口"是显式锚点）
- 角色名第一次出现后用代词指代（只有单一候选，pass）

**flag（让人审）**：

- 上下文不足，LLM 主观觉得"可能可解"但缺乏显式锚点
- 两个解读其中一个明显更合理但不绝对（边缘 case）

**严格 fail**：

- ≥3 个代词无法定位（"他对他说他不来"）—— 单句脱离上下文也明显冲突
- 双解都在当前上下文合理（"他打人很厉害"——两个解读都说得通）
- 多义词且当前上下文不限定义项

## D4.5 prompt 片段

### 生成端

```
[D4 · 避免歧义]
让句子在当前对话上下文中有且仅有一种合理理解，
且该理解由显式文本锚点支持。

禁止：
- 指代不明（代词 / 指示词存在 ≥2 个合理候选指称物，
  且上下文无显式文本锚点）
- 句法歧义（修饰范围 / 并列 / 否定范围多解）
- 词汇歧义无消歧（多义词当前上下文不限定义项）

技巧：
- 用实名代替代词（≥2 个候选时）
- 用语序 / 修饰位置消除句法歧义
- 加限定语 / 上下文锚点限定词汇义项
- 必要时直接拆句重组
```

### Review 端（三态输出）

```
[D4 · 避免歧义 review]

Step 1【模式扫描】3 类歧义模式：
1. 指代歧义：代词 / 指示词存在 ≥2 个合理候选指称物？
   （注意：判定标准是候选数量，不是代词数量）
2. 句法歧义：句子结构允许 ≥2 个 parse tree？
3. 词汇歧义：多义词出现且当前对话不限定义项？
命中任一 → 进 Step 2

Step 2【显式锚点检查】
对话文本中是否含显式锚点限定到单一解读？
- 显式锚点定义：实名词 / 限定语 / 上下文事实，明确限定多义 / 指代 /
  句法多解
- **不接受**：常识脑补 / 作者意图推断 / 相邻默认原则
- 有显式锚点 → pass D4
- 无 → 进 Step 3

Step 3【冲突评估】
- ≥2 个解读都合理 → fail D4
- 单句脱离上下文也无法定位（≥3 个代词冲突）→ fail D4
- 1 个合理 + 其他需文本外信息排除 → flag D4

输出（三态）：
- [D4: pass]
- [D4: fail (命中类别 + 引用具体短语 + 列出解读分叉)]
- [D4: flag (命中类别 + 引用具体短语 + 请人审决定)]
```

## D4.6 跟其他维度的关系

- **D1**：D1 管"字面 ≠ 意图"造成的歧义（反语 / 委婉 / 暗示——意图层）；D4 管"字面本身"的歧义（字面层）。Different domains, 几乎不重叠
- **D2 拒绝装饰**：装饰句通常清晰、不歧义——D2 fail 不带 D4
- **D3 避免晦涩**：D3 的长嵌套句常顺带触发 D4
- **D5 简明**：歧义句通常需要拆开重写——D4 命中常顺带 D5 fail
- **D6 有序**：歧义句有时是结构无序导致——可能跟 D6 重叠

## D4.7 D4-Specific 设计原则总结（codex review 后整理）

D4 是 v0.1 六维度里 LLM 最难判的。设计专门处理：

1. **三态输出**（pass / fail / flag）—— 其他维度无 flag
2. **显式文本锚点**硬要求 —— 不接受 LLM 脑补"常识"
3. **代词数量 → 合理候选数量** —— 判定标准更精确
4. **单句明显冲突仍硬 fail** —— flag 只用于真正模糊场景

这四点是 D4 跟 v0.1 其他五个维度的本质差别。
