# D6 有序（Grice manner-4, be orderly）v0.1.1

> talkstyle-skill v0.1 第 6 维度。codex review 第 1 轮后修订版。

## D6.1 精确定义

**D6 有序**：句子的信息颗粒按合理顺序排列——时间按事件先后、因果按 cause→effect、条件按 condition→consequence、主信息在前 / 次信息在后、问答直接对应。

D1-D5 管"信息正确 / 简明 / 不歧义"；D6 管"信息颗粒的排列顺序"。

**学术锚点**：Grice 合作原则 · 方式准则之四（be orderly）。

**判定核心机制**：A 严格立场 + 白名单。**只允许一种自然口语 reordering 模式——句首短 prepose（≤10 字）**；其他 reordering 一律 fail。代价：失去 afterthought / comment-topic / 长定语前置等口语模式；收益：strict 一致 + 可工程化。

**重要修订（codex review 第 1 轮）**：白名单**只局部豁免**该 reordering 结构，**不**让句子整体短路 pass——白名单允许的句子仍需扫描其他 5 类禁止模式。

## D6.2 禁止 5 类

### 类别 1：时序倒置（事件时间顺序乱）

**定义**：事件本应按时间先后说，但顺序倒置且**无显式时序标记**。

**判定信号**：句子描述 ≥2 个事件，时间状语后置（afterthought 式补充）或先后顺序颠倒，且未用"先 / 然后 / 后来 / 之前 / 之后 / 再"等明确标记。

| 反例（codex review 修订）| 正例 |
|---|---|
| "**他到了，刚才**。" | "**他刚才到了**。" |
| "**她回来了，从超市**。" | "**她从超市回来了**。" |
| "**他下班了，5 点**。" | "**他 5 点下班了**。" |

**允许**：使用"先 / 然后 / 后来 / 之前 / 之后 / 再"等明确时序标记的句子（即使顺序倒置）：

- "**我先吃了，再去的**。" → pass（用了"先...再..."标记）
- "**他下班后，我们去吃饭**。" → pass（用了"后"标记）

### 类别 2：因果 / 条件倒置（无标记）

**定义（codex review 修订——含条件后置）**：事件按 effect → cause 或 main → condition 顺序但**没用"因为 / 由于 / 如果 / 除非"等关系标记**，听者要倒回去理解。

**判定信号**：≥2 个事件先后排列，因果或条件关系隐含倒置，未用关系连词标明。

#### 子类 2a：因果倒置

| 反例 | 正例 |
|---|---|
| "**我哭了。看了那个电影**。" | "**看了那个电影，我哭了**。" / "**我哭了，因为看了那个电影**。" |
| "**他生气了。我说错话**。" | "**我说错话了，他生气了**。" |

#### 子类 2b：条件 / 例外后置

| 反例 | 正例 |
|---|---|
| "**可以去，如果门没锁**。" | "**如果门没锁，就可以去**。" |
| "**我答应，除非他也来**。" | "**除非他也来，我才答应**。" |
| "**给你打折，前提是现金**。" | "**现金的话，给你打折**。" |

**允许**：使用"因为 / 由于 / 所以 / 因此 / 如果 / 除非 / 前提是 / 只要 / 只有"等明确关系连词的句子（即使倒置 reading）。

### 类别 3：主信息埋藏（长 NP 前置）

**定义**：句首 NP（定语 / 状语 / 修饰语）字数 > 10 字，把主信息埋在后面。

**判定信号**：句首至第一个逗号 / 主语之间字数 > 10。

| 反例 | 句首 NP 字数 | 正例 |
|---|---|---|
| "**在那个又下雨又没车的晚上**，他终于决定不来了。" | 12 | "**他不来了。那晚又下雨又没车**。" |
| "**那个一直坚持要来看我的远房表弟**，今天到了。" | 15 | "**远房表弟今天到了。他一直说要来看我**。" |

### 类别 4：答非所问 / 答前铺垫过长

**定义（codex review 修订——加补强）**：对直接问题，主答案被推迟到末尾，前面全是过程 / 铺垫。**即使铺垫内容本身不冗余（不命中 D5），只要直接答案被推迟，也 fail D6**——D5 管冗余 / D6 管顺序，不重叠。

**判定信号（codex review 修订——可量化）**：上文是直接疑问（来不来 / 行不行 / 多少钱 / 是不是等），本句的**主答案首次出现的分句序号**满足以下任一条件：

- 主答案分句序号 > 全句分句数的一半
- 主答案分句序号 > 2（即在第 3 个分句之后）

| 反例（问"他来不来"，本句 5 个分句）| 主答案分句号 | 正例 |
|---|---|---|
| "我刚才去他家，他妈正在做饭，我问他妈他在不在，他妈说他出门了，**他妈说他可能不来**。" | 5 / 5（末尾）| "**不来。我刚去他家问的**。" |

### 类别 5：信息流颠倒（new before given，无锚定）

**定义（codex review 修订——明确上下文窗口）**：使用**定指**词（这 / 那 / 该 / 此）引入对话流中**未曾出现**的新信息，听者无锚定。

**上下文窗口**（codex review 修订）：

- 检查范围：当前对白块内已出现的 NP + 最近一轮对话上下文（前一节点 / 前一对白块）的 NP
- 若工程输入不提供上下文（仅单块审）：退化为"块内是否建立指称"判定

**判定信号**：句中含定指词（这 / 那 / 该 / 此）+ NP，但该 NP 在**上下文窗口内**未出现过。

| 反例（上下文无锚定）| 正例 |
|---|---|
| "**那本书**我朋友的。"（前文未提任何书）| "**这是我朋友的书**。" |
| "**这事**得办。"（前文无具体事件指称）| "**这件事得办**"（需上下文已建立"这件事"指什么）|

## D6.3 自然口语 reordering 白名单

**唯一允许的 reordering 模式（codex review 修订——术语精确化）**：句首短**前置成分**（≤10 字）。

```
[允许格式] 句首短前置成分（≤10 字，含以下类型）+ 逗号 + 完整句

允许的前置成分类型：
- topic NP（话题 / 宾语前置）："苹果，我不吃。" / "这事，我管不了。"
- 时间状语："昨天，他来了。"
- 地点状语："在那边，有个人。"
- 条件状语："等他来了，再说。"
```

**关键约束（codex review 修订）**：白名单**只局部豁免**这一种 reordering 结构。**符合白名单的句子仍需进入 Step 2 扫描其他 5 类禁止**——不允许整体短路 pass。

例："**昨天，他来了，因为我叫他，他又走了之前**。"

- Step 1：句首"昨天"≤10 字 + 逗号 + 完整句，符合白名单 → 局部豁免该 reordering
- Step 2：扫描其他类——"他又走了之前"命中类别 1（时序倒置无标记）
- 整句结果：**fail D6**

## D6.4 判定规则（codex review 第 1 轮修订）

### 输入单位

单个对白文本块（dialogue_graph 节点类型 3 npc_dialogue 或类型 5 player_option 单节点）。通常 1-3 句。

**上下文窗口**（仅类别 5 用）：当前对白块内前文 + 最近一轮对话上下文。

**多句处理**：逐句独立判定，整块结果取**合集**——任一句 fail → 整块 fail。

### 执行步骤

```
Step 1【白名单局部豁免】
   句子是否符合"句首短前置成分（≤10 字）+ 逗号 + 完整句"？
   - 是 → 该 reordering 结构豁免，但**仍进 Step 2 扫描其他禁止类**
   - 否 → 进 Step 2

Step 2【模式扫描】扫 §D6.2 五类禁止模式：
1. 时序倒置：≥2 个事件，时间状语后置或先后颠倒，无明确时序标记？
2. 因果 / 条件倒置：effect → cause 或 main → condition 顺序，无"因为/由于/如果/除非/前提是"等关系连词？
3. 主信息埋藏：句首 NP 字数 > 10？
4. 答前铺垫过长：直接疑问的回答中，主答案首次出现分句号 > 全句分句数一半 或 > 2？
5. 信息流颠倒：定指词 + NP 且 NP 在上下文窗口内未出现？

任一命中 → fail D6（严格 fail，A 立场不留兜底）
允许多类命中
```

### 多类命中示例（codex review 第 1 轮新增）

**反例**（玩家问"他来不来"）：

> "**我刚才去了他家，因为他妈说他出门了，可能不来**。"

- 命中**类别 4 答前铺垫过长**：主答案"可能不来"在第 3 分句（晚于第 2 分句）
- 命中**类别 2 因果倒置**：用了"因为"标记 → 实际上 cause 在中间，effect 在末尾，结构勉强可读；但整体仍属顺序乱
- 主类：类别 4（答案位置严重后置）

正例：

> "**可能不来。我去过他家——他妈说他出门了**。"

### 输出格式

```
[D6: pass]
或
[D6: fail (
  句子 1: 主类 X (+ 其他命中类别 Y, Z) — 引用具体短语
  句子 2: 主类 W — 引用具体短语
)]
```

### 无 flag 路径

D6 严格二态 pass / fail。flag 是 D4 独有特性，D6 不引入。

## D6.5 边界

### 允许（pass D6）

- 句首短前置成分（≤10 字）+ 逗号 + 完整句（**前提：句子其他部分也通过 Step 2 扫描**）
- 使用明确时序标记（"先 / 然后 / 后来 / 之前 / 之后 / 再"）的事件先后表达
- 使用明确因果 / 条件连词（"因为 / 由于 / 所以 / 因此 / 如果 / 除非 / 前提是 / 只要 / 只有"）的倒置表达
- 定指词指向上下文窗口内已出现的 NP

### 严格 fail（不豁免）

- 哪怕 LLM 觉得"这样更口语 / 更地道"，A 严格立场一律砍
- afterthought / comment-topic 等中文自然口语模式 → v0.1 一律 fail（代价已接受）
- 长定语 / 长状语前置（>10 字）→ 不豁免，视为类别 3 主信息埋藏

### 不作为 v0.1 豁免

以下动机只在后续版本解释，**不改变 D6 fail 判定**：

- 角色"想起补充" / 喊话补充 → v0.2 motivation
- 角色"惊叹评价后说主语" → v0.2 motivation
- 角色"夹枪带棒铺垫" → v0.2 motivation
- 角色身份相关的口语习惯 → v0.3 register matching

## D6.6 prompt 片段

### 生成端

```
[D6 · 有序]
让信息颗粒按合理顺序排列。

唯一允许的 reordering 模式：
- 句首短前置成分（≤10 字：topic NP / 时间 / 地点 / 条件）
  + 逗号 + 完整句
  例：苹果，我不吃 / 昨天，他来了 / 这事，我管不了

注意：句首前置只豁免该结构本身，句子其余部分仍要符合全部规则。

禁止：
- 时序倒置（"他到了，刚才" → 应"他刚才到了"），除非用"先/然后/
  后来/之前/之后/再"等时序标记
- 因果 / 条件倒置（"我哭了。看了电影。" / "可以去，如果门没锁。"），
  除非用"因为/由于/如果/除非/前提是/只要/只有"等关系连词
- 长 NP 前置（>10 字）→ 主信息埋藏
- 答前铺垫过长（直接疑问要直接答；主答案分句号 > 句长一半 或 > 2）
- 信息流颠倒（定指词"这/那/该/此" + 前文未出现的 NP）
- Afterthought 后置补充（"我不吃，苹果。"）
- Comment-topic 倒装（"好吃，这个！"）

写句子先想："听者按我的顺序读，每个信息颗粒都能锚定吗？"
```

### Review 端（codex review 修订——含上下文检查步骤独立化）

```
[D6 · 有序 review]

输入单位：单个对白文本块（type 3 / type 5），含 1-3 句。
逐句独立判定，整块取合集。

Step 1【白名单局部豁免】
   句子是否符合"句首短前置成分（≤10 字）+ 逗号 + 完整句"？
   - 是 → 该 reordering 局部豁免，但**仍进 Step 2 扫其他禁止类**
   - 否 → 进 Step 2

Step 2【模式扫描】扫 5 类禁止：
1. 时序倒置：≥2 个事件，时间状语后置或先后颠倒，无时序标记
   （先/然后/后来/之前/之后/再）？
2. 因果 / 条件倒置：effect → cause 或 main → condition 顺序，
   无关系连词（因为/由于/如果/除非/前提是/只要/只有）？
3. 主信息埋藏：句首 NP 字数 > 10？
4. 答前铺垫过长：直接疑问的回答中，主答案首次出现分句号 > 全句
   分句数一半 或 > 2？
5. （独立步骤）信息流颠倒：
   先建立上下文窗口（当前对白块内已出现 NP + 最近一轮对话 NP），
   再判定句中定指词（这/那/该/此）+ NP 是否落在窗口内？
   - 在窗口内 → pass 该项
   - 不在窗口内 → 命中类别 5

任一命中 → fail D6（严格 fail）
允许多类命中

输出（二态）：
[D6: pass]
或
[D6: fail (
  句子: 主类 X (+ 其他命中 Y, Z) — 引用具体短语
)]
```

## D6.7 跟其他维度的关系

- **D1**：D6 的顺序问题通常字面 = 意图——D6 命中不带 D1
- **D2 拒绝装饰**：D2 跨句反复 / 形式装饰；D6 单句内顺序乱——不重叠
- **D3 避免晦涩**：D3 长嵌套句（>30 字）vs D6 类别 3 长 NP 前置（>10 字）——可多类命中
- **D4 避免歧义**：D4 字面多解 vs D6 顺序乱——不重叠
- **D5 简明**：D5 类别 1 客套铺垫 vs D6 类别 4 答前铺垫过长——**关键切分**：D5 看"铺垫内容是否冗余"；D6 看"答案位置是否被推迟"。**即使铺垫不冗余，只要答案被推迟，D6 也 fail**——两个维度可多类命中

## D6.8 已知 v0.1 局限

D6 v0.1 不处理：

- 角色身份特定的"想起补充" / "情绪后置评价"等口语模式 → v0.2 motivation
- 角色身份决定的语序习惯（如老人爱用 afterthought）→ v0.3 register matching
- 跨多句的信息组织顺序（如先描述再总结 vs 先总结再描述）→ v0.4+（更高阶 information structure）

v0.1 D6 一律砍。如果作者觉得"这角色就该 afterthought"或"这段场景该用长定语铺垫"，先在 v0.1 写干净版本，到 v0.2 / v0.3 阶段再按动机 / 身份加回去。
