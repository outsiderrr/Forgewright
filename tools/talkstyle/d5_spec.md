# D5 简明（Grice manner-3, be brief）v0.1.1

> talkstyle-skill v0.1 第 5 维度。codex review 第 1 轮后修订版。

## D5.1 精确定义

**D5 简明**：句子的字数应该跟它承载的信息量成正比；不用冗余结构、不堆同义副词、不加客套铺垫、不重复信息。

D1-D4 管"信息正确"；D5 管"信息密度高 / 用字数对得起信息量"。

**学术锚点**：Grice 合作原则 · 方式准则之三（be brief）。

**注**：D5 不要求"每句最短"。真实人物说话有自然语速、停顿、嗯啊。D5 砍的是**没有信息增量的冗词冗结构**——LLM 写对白特别爱加的"我跟你说"、"进行讨论"、"不是不来"这种。

**判定核心机制**：D5 类别分两组：

- **替换测试组（类别 1、2）**：删除 / 替换冗余结构后，若**信息（命题内容 / 立场强度 / 转折关系 / 时体 / 疑问）均不变**才判 fail。允许字面承载信息的"看似冗余"短语 pass。
- **机械模式组（类别 3、4、5）**：直接 fail，不做替换测试（这类冗余永远不承重）。

## D5.2 禁止 5 类

### 类别 1：客套铺垫（filler openings）

**定义**：句首加的、无信息增量的过渡词组 / 套话。

**判定信号（codex review 修订——含替换测试）**：

句首存在 "我跟你说" / "我想说的是" / "话说回来" / "其实呢" / "老实讲" / "说真的" / "怎么说呢" / "这么说吧" 等，**且**满足以下替换测试：

> 删除该词组后，命题内容、立场强度、转折关系**均**不变 → fail D5
> 任一项变化（如"老实讲"承载"我在纠正我之前可能给的印象"立场信息）→ pass D5（保留为字面承载信息）

| 反例 | 正例 | 替换测试结果 |
|---|---|---|
| "**我跟你说啊**，他不来。" | "他不来。" | 删除后命题不变、立场不变、转折不变 → fail |
| "**其实呢**，我也不清楚。" | "我也不清楚。" | 删除后命题不变（前提下文无对比对象）→ fail |
| "**老实讲**，钱不够。" | "钱不够。" | 删除后命题不变（前提此前未否定）→ fail |

**例外（pass D5）**：

- "我刚说**我有钱**——**老实讲**，钱不够。" → "老实讲"在此**承载**"我之前的陈述需要纠正"的立场信息；删除后转折关系丢失 → pass

**不作为 v0.1 豁免**（codex review 修订）：以下动机只在后续版本解释，**不改变 D5 fail 判定**：

- 角色明确是磨叽 / 啰嗦 / 紧张人设 → v0.3 register matching
- 故意拖延 / 缓和气氛 → v0.2 motivation

### 类别 2：冗余动名词结构

**定义**：用"虚动词 + 名词"代替单个动词，无信息增量。

**判定信号（codex review 修订——含替换测试）**：

使用 "进行" / "加以" / "予以" / "实施" / "作出" / "给以" 等虚动词 + 名词，**且**满足以下替换测试：

> 替换为"该名词的动词形式"后，信息**完全不变** → fail D5
> 替换后信息变化（如"实施手术" ≠ "手术"——前者含"手术行为开展"，后者含"手术"名物）→ pass D5

| 反例（替换后信息不变 → fail） | 正例 |
|---|---|
| "我们**进行讨论**。" → "我们讨论" ≡ 同义 → fail | "我们**讨论**。" |
| "**加以解决**这个问题。" → "解决问题" ≡ 同义 → fail | "**解决**这个问题。" |
| "**予以考虑**他的提议。" → "考虑提议" ≡ 同义 → fail | "**考虑**他的提议。" |
| "**作出回应**。" → "回应" ≡ 同义 → fail | "**回应**。" |

**例外（pass D5——替换后信息变化）**：

- "**实施手术**" → "手术"丢失"手术行为开展"的动作 → pass（institutional 用法）
- "**作出判决**" → "判决"丢失"司法行为做出"的事件性 → pass（法律 institutional 用法）
- "**进行实验**" → "实验"在某些上下文丢失过程性 → 视具体上下文，可能 pass

### 类别 3：副词 / 形容词堆叠

**定义**：同一意思的副词 / 形容词重复 / 堆叠加强语气。

**判定信号（codex review 修订——阈值统一为 ≥2）**：

- **≥2 次重复同一程度副词**（修订前是 ≥3，与例子"非常非常"=2 次不一致；统一为 ≥2）
- **≥2 个同义副词 / 形容词连用**

| 反例 | 正例 |
|---|---|
| "我**非常非常**讨厌他。" | "我**很**讨厌他。" |
| "**好好好**，我去。" | "**好**，我去。" |
| "**深深深**的红。" | "**很深的**红。" |
| "**美丽且漂亮**。" | "**漂亮**。" |
| "**狡猾而奸诈**。" | "**狡猾**。" |

直接 fail，不做替换测试（这类冗余永远不承重）。

### 类别 4：双重 / 多重否定（v0.1 一律展开为正向）

**定义**：用 ≥2 重否定表达正向含义。

**判定信号**：句中出现 "不...不..." / "非...不可" / "无...不..." 的双否定结构。

**正例改为机械等价展开（codex review 修订——保持必要性 / 全称量化等语义强度）**：

| 反例 | 正例（机械等价展开）| 此前不等价正例（已废弃）|
|---|---|---|
| "他**不是不**来。" | "他**来**。"（命题等价；具体语气强度归 v0.2）| ~~"他会来"~~（丢失"原本可能不来但实际来"的确定性变化）|
| "**非**他**不可**。" | "**必须是他**。"（保留必要性）| ~~"只有他可以"~~（丢失必要性，仅保留 ability）|
| "**无人不**知。" | "**人人都**知道。"（保留全称量化）| 同上 |

**注**：双重否定在中文里有"勉强承认"、"语气加强"、"必要性强调"等**语用层含义**——那些是 v0.2 motivation 处理；v0.1 强制展开为命题等价正向。

直接 fail，不做替换测试。

### 类别 5：同义并列 / 句内反复

**定义**：同一信息在单句内重复说一次（≠ D2 类别 6 的跨句反复以强调）。

**判定信号**：单句内同一意思用 ≥2 种说法并列；前后分句信息几乎一致。

| 反例 | 正例 |
|---|---|
| "**这件事这件事**，他不来。" | "这事他不来。" |
| "他不来，**反正他不来嘛**。" | "他不来。" |
| "**很多很多**人。" | "**很多人**。"（也命中类别 3——允许多类命中）|
| "**非常严重，特别严重**。" | "**严重**。" |

直接 fail，不做替换测试。

**跟 D2 类别 6 反复区分**：

- D2 反复 = **跨句**以强调（"我累了。真的累了。太累了。"）
- D5 同义并列 = **单句内**信息重复（"这件事这件事"）

**跟类别 3 的允许重叠**（codex review 修订）：

"很多很多" 同时命中类别 5（句内反复）+ 类别 3（程度词重复）。**D5 允许多类命中**，输出时列出所有命中类别（参考 D2 multi-class fail 模式）。

## D5.3 判定规则（codex review 修订——补完整执行 spec）

### 输入单位

单个对白文本块（dialogue_graph 节点类型 3 npc_dialogue 或类型 5 player_option 单节点）。通常 1-3 句。

**多句处理**：逐句独立判定，整块结果取**合集**——任一句 fail → 整块 fail，并列出哪些句子命中哪些类别。

### 执行步骤

```
Step 1【模式扫描】
   逐句独立扫 §D5.2 五类：
   - 类别 1（客套铺垫）：句首词组匹配？→ 进 Step 2 替换测试
   - 类别 2（冗余动名词）：虚动词 + 名词结构？→ 进 Step 2 替换测试
   - 类别 3（副词 / 形容词堆叠）：≥2 次重复 / 同义连用？→ 直接命中
   - 类别 4（双重否定）：双否定结构？→ 直接命中
   - 类别 5（同义并列 / 句内反复）：单句内信息重复？→ 直接命中

Step 2【替换测试】（仅对类别 1 / 2 适用）
   - 类别 1：删除后命题内容、立场强度、转折关系是否均不变？
     - 都不变 → fail D5（命中类别 1）
     - 至少一项变化 → pass D5（保留为字面承载信息）
   - 类别 2：替换为"该名词的动词形式"后信息是否不变？
     - 不变 → fail D5（命中类别 2）
     - 变化（institutional 用法等）→ pass D5

Step 3【多类汇总】
   - 任一类别 fail → 整句 fail D5，列出所有命中类别
   - 允许一句多类命中（如"很多很多" 命中 3 + 5）
   - 整块（多句）取合集：任一句 fail → 整块 fail
```

### 输出格式

```
[D5: pass]
或
[D5: fail (
  句子 1: 命中类别 X, Y, ... — 引用具体短语
  句子 2: 命中类别 Z — 引用具体短语
  ...
)]
```

**替换建议**（可选，不强制）：D5 review 可附"建议改写"，但 v0.1 不要求 reviewer 必填——人审 / 作者重写即可。

### 无 flag 路径

**D5 严格二态 pass / fail**。flag 是 D4 独有特性（D4 结构性最难判 + 中文重上下文）；D5 不具备该特性，**不引入 flag**。

### 严格 fail 的理由

D5 的冗余永远不承重信息——一定能去掉而保持信息完整。但**类别 1 / 2 的替换测试**让规则不会误杀"看似冗余实际承载字面信息"的短语。

## D5.4 边界

### 允许（pass D5）

- 真实情境的迟疑、口吃（D2 类别 6 例外保留：听错 / 口吃 / 纠正 / 复述指令——D5 跟 D2 共享）
- 类别 1 替换测试通过的句首词组（承载"纠正预期 / 让步 / 转折"字面信息时）
- 类别 2 替换测试通过的虚动词结构（institutional 用法如"实施手术"、"作出判决"）

### 语气粒子（codex review 修订——新增独立边界）

中文语气粒子 **吧 / 啊 / 呢 / 嘛 / 了 / 啦 / 哦** 等不全是冗词。**判定规则**：

> 删除该粒子后，**句类（陈述 / 疑问 / 祈使 / 感叹）+ 时体（完成 / 未完成）+ 确认状态**任一变化 → pass D5（粒子承载语法信息）  
> 全部不变 → fail D5（粒子是冗余）

| 反例（pass D5）| 理由 |
|---|---|
| "你来**吧**。" | 删"吧"→"你来"（祈使强度变 / 从建议变命令）→ 粒子承载语气 |
| "他来**了**？" | 删"了"→"他来？"（完成体丢失）→ 粒子承载时体 |
| "你**啊**！" | 删"啊"→"你！"（感叹强度变）→ 粒子承载感叹 |
| "懂**了吗**？" | 删"了"或"吗"→ 完成体或疑问状态变 → 承载语法 |

| 真冗余粒子（fail D5）| 理由 |
|---|---|
| "他来**啊**他来**啊**。" | 重复"啊"非语气需要 → 命中类别 5 同义并列 |

### 严格 fail

- 哪怕 LLM 觉得"这样更地道 / 更口语"，v0.1 一律砍
- "不是不能" 类双重否定 → 强制展开为命题等价正向
- 角色磨叽 / 紧张 / 啰嗦性格 → **不作为 v0.1 豁免**（codex review 修订措辞）：以下动机只在后续版本（v0.2 motivation / v0.3 register）解释，**不改变 D5 fail 判定**

## D5.5 prompt 片段

### 生成端

```
[D5 · 简明]
让句子的字数对得起它承载的信息量。

禁止：
- 客套铺垫（"我跟你说" / "我想说的是" / "话说回来" / "其实呢"
  / "老实讲" / "说真的" / "怎么说呢"）—— 除非承载字面信息
  （纠正预期 / 让步 / 转折）
- 冗余动名词（"进行讨论" / "加以解决" / "予以考虑" / "作出回应"）
  —— 除非是 institutional 用法（实施手术 / 作出判决 等）
- 副词 / 形容词堆叠（≥2 次重复 "非常非常" / "好好好"
  / "美丽且漂亮"）
- 双重 / 多重否定（"不是不能" → "能" / "非他不可" → "必须是他"
  / "无人不知" → "人人都知道"），机械等价展开
- 同义并列 / 句内反复（"这件事这件事" / "很多很多人"
  / "非常严重，特别严重"）—— 跨句反复以强调归 D2

中文语气粒子（吧 / 啊 / 呢 / 嘛 / 了）：只有在删除后句类
/ 时体 / 确认状态变化时才允许；否则视为冗余。

每句对白先问："这句删了哪一部分还能完整传达信息？"
能删的部分直接删。
```

### Review 端

```
[D5 · 简明 review]

输入单位：单个对白文本块（type 3 / type 5），含 1-3 句。
逐句独立判定，整块取合集。

Step 1【模式扫描】扫 5 类冗余模式：
1. 客套铺垫：句首 "我跟你说" / "我想说的是" / "话说回来"
   / "其实呢" / "老实讲" / "说真的" / "怎么说呢" 等？
2. 冗余动名词：虚动词 "进行 / 加以 / 予以 / 实施 / 作出 / 给以"
   + 名词结构？
3. 副词 / 形容词堆叠：≥2 次重复同程度副词 / ≥2 个同义副词
   形容词连用？
4. 双重 / 多重否定："不...不..." / "非...不可" / "无...不..."？
5. 同义并列：单句内同一意思用 ≥2 种说法？

Step 2【替换测试】（仅类别 1 / 2 适用）
- 类别 1：删除后命题 / 立场 / 转折是否均不变？
  - 是 → fail
  - 否 → pass（承载字面信息）
- 类别 2：替换为对应动词后信息是否不变？
  - 是 → fail
  - 否 → pass（institutional 用法）

Step 3【粒子边界检查】（独立项，非 §D5.2 类别）
- 句中出现 吧 / 啊 / 呢 / 嘛 / 了 / 啦 / 哦 等粒子？
  - 删除后句类 / 时体 / 确认状态变？→ pass（承载语法）
  - 全部不变？→ fail（视为冗余）

Step 4【多类汇总】
- 允许一句多类命中
- 整块（多句）取合集

输出（二态）：
[D5: pass]
或
[D5: fail (
  句子 1: 命中类别 X, Y — 引用具体短语
  句子 2: 命中类别 Z — 引用具体短语
)]

替换建议可选，不强制必填。
无 flag 路径（D4 独有特性，D5 不引入）。
无字典查询需求；纯 LLM 模式识别。
```

## D5.6 跟其他维度的关系

- **D1**：D5 删除的冗余通常字面 = 意图（"进行讨论"="讨论"）——D5 命中不带 D1
- **D2 拒绝装饰**：D2 类别 6 反复 = **跨句**以强调；D5 类别 5 同义并列 = **单句内**信息重复。**两者分工，不重叠**
- **D3 避免晦涩**：D3 长嵌套常顺带 D5 fail（长嵌套句通常有冗余动名词 / 客套铺垫）
- **D4 避免歧义**：歧义句通常需要拆开重写——D4 命中常顺带 D5 fail
- **D6 有序**：D5 跟 D6 几乎不重叠

## D5.7 已知 v0.1 局限

D5 v0.1 不处理：

- **故意磨叽 / 客套缓和 / 紧张拖延** 这些有语用功能的"冗余"——归 v0.2 motivation
- **角色身份特定客套** 如老人 / 官员 / 商务说话方式——归 v0.3 register matching

v0.1 D5 一律砍。如果作者觉得"这角色就该磨叽"，先在 v0.1 写干净版本，到 v0.2 / v0.3 阶段再按动机 / 身份加回去。
