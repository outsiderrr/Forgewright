## 2. 已知硬约束（不可违反）

> 这些来自 CLAUDE.md / ROADMAP.md / DECISIONS.md / 作者明示，不是本档新立的规则。本档只是把它们放在一起便于工程会话查阅。

### 2.1 体裁与定位

- **第一款游戏 = "克苏鲁版极乐迪斯科 spiritual successor"**
- **纯文本驱动**：对话 + 调查 + 物品 + NPC + 检定，**无传统战斗系统**
- **玩家交互模式**：3–6 个预生成选项点击式，**运行时无 LLM**（确定性 JSON 对话图播放器）
- **不存在玩家欺诈问题**（运行时无 LLM，所以不需要反幻觉 / 流式输出对齐等）

### 2.2 明示**不**做的事

- ❌ 传统战斗系统
- ❌ 思维内阁系统（极乐迪斯科的标志机制）
- ❌ 内心独白段落（极乐迪斯科的另一个标志机制）
- ❌ 运行时 LLM 调用
- ❌ Articy:Draft / Ink（作为数据源）/ Fountain / Yarn Spinner 新版（YSPL 许可证）

### 2.3 明示**主做**的事

- ✓ 对话多选项（3-6 个 / 节点）
- ✓ 调查（结构化 NPC 走访 + 线索收集，CoC 风格）
- ✓ 物品系统
- ✓ NPC 系统
- ✓ 技能体系（项目配置层定义，引擎只规范 active_check + passive_injection，详 ADR-029）
- ✓ 检定（NdM + modifier vs DC，具体骰子项目配置层定义，详 ADR-029）

## 5. 元结构判断（本档最重要的内容）⭐

### 5.1 引擎抽象层的核心问题

T-3X-0 会话最有价值的产出 = **识别出"GM 抉择空间结构化"是引擎抽象层的核心问题**。

CoC 模组（Crimson Letters 这类）的设计是 **骨架 + 留白**：

- NPC 描写 / 事实线索 / 角色扮演钩子 / 守秘人笔记 = 骨架
- 真凶选择 / NPC 反应 / 威胁节奏 / 解决路径 / 场景扩展 / 难度调整 / 即兴 = 留白（由 GM 跑团时即兴决定）

而 Forgewright 引擎要求 **确定性 JSON 对话图**——所有"GM 抉择"都必须**预先压成数据**或**由确定性代码即时生成**。

### 5.2 7 种 GM 抉择空间形式 + 候选结构化方案

详 `/docs/reviews/aesthetic/T-3X-0_crimson_letters_reading.md` §5。简要列示：

| 形式 | 候选方案 |
|---|---|
| 真凶选择 | 元参数 |
| NPC 反应 | NPC 状态机 + 反应矩阵 |
| 威胁节奏 | 倒计时机制 |
| 多结局 | world_state → ending 分支 |
| 场景扩展 | 场景模板 + 插件追加 |
| 难度调整 | 难度参数 |
| **即兴** | **不可完全结构化** ⚠️ |

### 5.3 两种工作场景共同点

- **场景一（改编已有模组）** + **场景二（原创）** 共用同一个工作流：**"叙事意图 → 确定性 JSON 对话图"的转换**
- 差别只在输入端（材料库 vs 一句话）；输出端 schema 一致
- 这就是为什么 GM 抉择空间结构化方案值得在 T-3X-1 之前单独立 ADR

### 5.4 核心赌注

Forgewright 工具一期的核心赌注 = **"AI 海量预生成 + 人工审阅 = 给玩家伪即兴体验"**。

如果这个赌注不成立（AI 无法预生成足够丰富的内容覆盖 GM 即兴空间），整个工具一期定位需要重新审视。

> 这是本次会话发掘出的最深层赌注。建议进 DEBATE_NOTES.md（由作者明示授权后单独执行）。
