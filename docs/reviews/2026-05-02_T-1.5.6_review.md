### 3.1 [SAFETY] generator/generate_visual.py:258 — `mode="manual"` 可让付费 API provider 绕过 image_budget

**问题**：`_generate_one()` 用调用方传入的 `mode` 调 `image_budget.check()` 和 `log_charge()`，但没有验证 provider 与 mode 是否一致。如果误把 `OpenAIImageProvider` 传给 `mode="manual"`，`image_budget.check()` 会直接 return，不检查 per-call/daily ceiling，随后仍会真实调用 API 并产生费用；日志还会按 manual mode 写，预算审计也会失真。

**为什么 CRITICAL**：违反 ADR-014 / `/generator/CLAUDE.md` 的硬规则：任何 image API 调用前必须经 `image_budget.check()` 预算拦截。这里是成本安全阀被配置错误绕过。

**建议修复**：
```python
# 当前
estimated_cost = provider.estimate_cost(n=n, size=size)
image_budget.check(estimated_cost_usd=estimated_cost, mode=mode)
gen_result = provider.generate(...)
image_budget.log_charge(mode=mode, ...)

# 改为：付费 provider 不能以 manual mode 运行；provider 返回 mode 也必须匹配
estimated_cost = provider.estimate_cost(n=n, size=size)
if mode == "manual" and estimated_cost > 0:
    return VisualGenerationResult(
        success=False,
        asset_id_stub=asset_id_stub,
        failure_reason=(
            "provider_mode_mismatch: manual mode provider estimated "
            f"${estimated_cost:.4f}; refusing to call provider before budget check"
        ),
        raw_metadata={"target_ref": target_ref, "target_type": target_type,
                      "asset_role": asset_role, "variant_label": variant_label,
                      "estimated_cost_usd": estimated_cost},
    )

image_budget.check(estimated_cost_usd=estimated_cost, mode=mode)
gen_result = provider.generate(...)
if gen_result.mode != mode:
    return VisualGenerationResult(
        success=False,
        asset_id_stub=asset_id_stub,
        failure_reason=f"provider_mode_mismatch: expected {mode}, got {gen_result.mode}",
        raw_metadata=dict(gen_result.raw_metadata),
    )

image_budget.log_charge(mode=gen_result.mode, ...)
```

同时在 `generator/tests/test_generate_visual.py` 增加两条测试：`mode="manual"` + paid fake provider 不应调用 provider；`mode="api"` + manual provider 返回 mismatch failure，且不写成功日志。

**模块边界状态**：✅ 在边界内（可修）

## 4. 应修（🟡 IMPORTANT）

### 4.1 [ARCH] generator/visual_context.py:210 — 背景 prompt 在本体桩存在时反而不会读 `scene.json` narration

**问题**：`assemble_visual_context_for_location_or_scene()` 先从 `waystation.json` 找到 `scene_waystation_of_iron_oath`，就直接使用这个薄桩；真实文件里该桩只有 `id/display_name/type`，没有塔楼、断剑铁环旗、橡木门、油灯、驿站室内等视觉信息。`scene.json` 中有这些叙述，但只有 entity 缺失时才会被 fallback 触达。

**为什么 IMPORTANT**：T-1.5.6 的目标之一是 `generate_scene_background` 产出可用背景 prompt；现在背景英文段只会看到 “Location/scene Waystation of the Iron Oath. Additional registered ontology fields: none.”，会导致 GPT-Image 生成泛化驿站，丢掉《铁誓驿站》的核心视觉锚点。

**建议修复**：
```python
# 当前
ontology = _load_json(ontology_path)
card = _find_entity(ontology, target_ref, ("location", "scene"))
if card is None:
    scene = _load_json(scene_path)
    ...

# 改为：即使 card 存在，也把 scene.json 中同一 location_ref/scene_anchor 的 narration 摘要并入只读 context
ontology = _load_json(ontology_path)
card = _find_entity(ontology, target_ref, ("location", "scene"))
scene = _load_json(scene_path)
scene_narration = _collect_scene_narration(scene, target_ref)

if card is not None and scene_narration:
    card = {**card, "scene_narration": scene_narration}
elif card is None:
    card = _fallback_scene_card(scene, target_ref)
```

测试也要补：用真实或最小 `scene.json` fixture，断言背景 prompt 英文段至少包含来自 narration 的稳定视觉锚点，例如“断剑与铁环 / flag”、“橡木门 / oak door”、“油灯 / oil lamp”之一。

**模块边界状态**：✅ 在边界内（可修）

### 4.2 [OPEN] generator/generate_visual.py:347 — `provider_id` 写 class name，不符合 image_cost_log 契约

**问题**：成功日志用 `provider.__class__.__name__`，因此 manual 行会写 `"ManualImportProvider"`，API fake 行会写 `"FakeApiImageProvider"`。但 T-1.5.5 / image budget 测试中的契约是稳定 provider id：`manual_import` 或 `openai_image_<model>`；后续 metrics / batch 统计不应依赖 Python class name。

**为什么 IMPORTANT**：这是公开日志接口稳定性问题。`image_cost_log.jsonl` 是 T-1.5.8/1.5.10 统计来源，class name 会随实现细节变化，且与已有 `test_image_budget.py` 里的 provider_id 口径不一致。

**建议修复**：
```python
# 当前
image_budget.log_charge(
    mode=mode,
    provider_id=provider.__class__.__name__,
    ...
)

# 改为
image_budget.log_charge(
    mode=gen_result.mode,
    provider_id=_provider_id(gen_result),
    ...
)

def _provider_id(gen_result: ImageGenerationResult) -> str:
    if gen_result.mode == "manual":
        return "manual_import"
    model_id = gen_result.raw_metadata.get("model_id")
    if model_id:
        return f"openai_image_{model_id}"
    return "api_unknown"
```

在 `test_generate_visual.py` 里断言 manual log row 的 `provider_id == "manual_import"`；API fake 可以在 `raw_metadata` 中放 `model_id="fake-image-model"`，断言写成 `openai_image_fake-image-model`。

**模块边界状态**：✅ 在边界内（可修）

### 4.3 [ARCH] generator/generate_visual.py:554 — deterministic stub 没有包含 `asset_role`，且长 target 截断会丢 variant/idx

**问题**：docstring 说 stub 由 `(target_ref, asset_role, variant_label, idx)` 决定，但实现把 `asset_role` 标成 unused，只拼 `target_ref + variant + idx`。另外 `body = body[:64]` 从末尾截断，长 `target_ref` 会把 variant 和 idx 挤掉，多个变体可能得到同一个前 64 字符，出现 `_pending/<asset_id>/` 目录冲突。

**为什么 IMPORTANT**：T-1.5.7 import 依赖 deterministic stub 做 idempotent import。stub 冲突会让后生成的 prompt 包覆盖先生成的 prompt 包，或者让 manifest 误判为同一资产。

**建议修复**：
```python
# 当前
body = f"{short}_{variant}_{idx:02d}".strip("_")
if len(body) > 64:
    body = body[:64].rstrip("_")

# 改为：asset_role 入 stub，并优先保留 role/variant/idx 后缀
role = _normalise_variant(asset_role)
suffix = _normalise_variant(f"{role}_{variant}_{idx:02d}")
prefix_budget = max(0, 64 - len(suffix) - 1)
short_prefix = short[:prefix_budget].rstrip("_")
body = f"{short_prefix}_{suffix}" if short_prefix else suffix
body = _REPEAT_UNDERSCORE_RE.sub("_", body).strip("_")
return f"img_{body}"
```

更新现有 stub 断言，并新增长 target + 两个不同 variant 的测试，断言二者不同且都保留末尾 idx。

**模块边界状态**：✅ 在边界内（可修）

### 4.4 [ERR] generator/generate_visual.py:382 — `n` / variant 数不足时静默少生成

**问题**：`_character_variants()` 和 `_scene_variants()` 只把已有组合 clip 到 `req.n`，但组合不足时直接返回短列表；`req.n <= 0` 时也会返回空列表。调用方会看到“没有失败行”，容易以为 batch 成功，只是生成数变少。

**为什么 IMPORTANT**：阶段 1.5 验收要求 vellin 10–15 张、corvan/aelwin 4–6 张、背景 1–3 张。静默少生成会污染验收统计，也会让 U-CL-3 mini probe / 全量 batch 缺图却没有 failure_reason。

**建议修复**：
```python
# 当前
variants = _character_variants(requirement)
results: list[VisualGenerationResult] = []
for idx, (expression, pose) in enumerate(variants, start=1):
    ...

# 改为：入口处校验需求，不能满足 n 就返回 invalid_requirement failure row
variants = _character_variants(requirement)
if requirement.n < 1 or len(variants) < requirement.n:
    return [
        VisualGenerationResult(
            success=False,
            asset_id_stub=_make_asset_id_stub(
                requirement.target_ref, "character_sheet", "invalid_requirement", 0
            ),
            failure_reason=(
                f"invalid_requirement: requested n={requirement.n}, "
                f"but only {len(variants)} variant(s) are available"
            ),
        )
    ]
```

对 scene background 同样处理；测试覆盖 `n=3` 但只给 1 个 expression/time 的情况。

**模块边界状态**：✅ 在边界内（可修）

### 5.1 [ERR] generator/generate_visual.py:355 — cost log 写失败时没有把错误放进 `raw_metadata`

**问题**：注释写着 cost log OSError 会“flag the log failure in raw_metadata”，但代码只 log error，最后仍返回 `raw_metadata=dict(gen_result.raw_metadata)`，调用方和后续 metrics 看不到这次成功资产其实没有记账。

**为什么 NICE**：这不影响图像生成成功，也不是常见路径；但如果磁盘/权限出问题，作者最好能在 batch result 里直接看到 `cost_log_error`。

**建议修复**：
```python
# 当前
try:
    image_budget.log_charge(...)
except OSError as exc:
    _logger.error(...)

return VisualGenerationResult(..., raw_metadata=dict(gen_result.raw_metadata))

# 改为
metadata = dict(gen_result.raw_metadata)
try:
    image_budget.log_charge(...)
except OSError as exc:
    _logger.error(...)
    metadata["cost_log_error"] = str(exc)

return VisualGenerationResult(..., raw_metadata=metadata)
```
