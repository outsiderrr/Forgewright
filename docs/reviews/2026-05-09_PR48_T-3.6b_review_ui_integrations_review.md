## 3. 必修（🔴 CRITICAL）

### 3.1 [SAFETY] `tools/review_ui/data.py`:633 — `/api/visual/{asset_id}` 可按 manifest 读取 repo root 下任意文件

**问题**：`get_visual_file()` 把 manifest 里的 `file_path` 拼到 `_visuals_file_root()` 上；而 `_visuals_file_root()` 在有 `scenes_dir` 时返回的是 `self.scenes_dir.parent`，也就是 repo root。当前 guard 只保证 `candidate` 没逃出 repo root，没有保证它位于 `content/visuals/`，因此 manifest 中若出现 `.env`、`docs/...` 或其他 repo 内路径，`/api/visual/{asset_id}` 会直接 `FileResponse` 返回该文件。

**为什么是 CRITICAL**：这是边界接口上的文件读取漏洞，且违背 `SCHEMA_v0` 中 visual manifest `file_path` 只能指向 `content/visuals/...(.png|webp)` 的约束；也违反 CLAUDE.md 规则 6“JSON Schema is the only source of truth”。

**修复建议**：
```python
# 当前（问题代码片段）
base = self._visuals_file_root()
candidate = (base / rel).resolve()
base_resolved = base.resolve()
try:
    candidate.relative_to(base_resolved)
except ValueError:
    return None

# 建议
repo_root = self._visuals_file_root()
visuals_root = self.visuals_dir.resolve() if self.visuals_dir else None
if repo_root is None or visuals_root is None:
    return None
candidate = (repo_root / rel).resolve()
try:
    candidate.relative_to(visuals_root)
except ValueError:
    return None
if candidate.suffix.lower() not in {".png", ".webp"}:
    return None
```

并补一个测试：manifest 里 `file_path` 指向 `.env` 或 `content/../.env` 时，`GET /api/visual/<asset_id>` 必须 404，且响应体不能包含文件内容。

### 3.2 [ARCH] `tools/review_ui/data.py`:150 — 本轮明确“不动”的 `data.py` 主框架被扩展成集成层

**为什么是 CRITICAL**：这直接违反本轮 review target 的模块边界严约，也踩到 CLAUDE.md 规则 2“尊重模块边界”。ADR-025 要求 T-3.6a MVP 的 5 个视图 contract 保持稳定；当前实现虽然努力兼容，但变更位置已经超出授权范围。

# 当前方向
class ReviewDataLoader:

        ...

# 2. 若仍按原边界执行，把 T-3.6b reader 收敛到 api.py 的集成 helper

## 4. 应修（🟡 IMPORTANT）

### 4.1 [SCHEMA] `tools/review_ui/data.py`:559 — visual thumbnails 没有从 dep_index sidecar 的 `visual_asset_ids_referenced` 取数

**问题**：`get_visual_assets()` 现在先读 scene graph 的 `character_refs` / `scene_anchor`，再扫整个 visual manifest，用 `target_ref`、`character_ref`、`location_ref` 匹配。这绕过了 T-3.2 sidecar 字段 `visual_asset_ids_referenced`。结果是：只要 manifest 中有同角色或同场景 anchor 的 asset，就会被 UI 展示，即使该 asset 从未被该 scene 的 dep_index 引用；sidecar 缺失时也不会按要求 degrade 为隐藏/placeholder。

**为什么是 IMPORTANT**：本轮 T-3.6b 明确要求“从 dep_index sidecar 读 `visual_asset_ids_referenced` → 调 visual asset manifest → UI 显示 thumbnail；字段缺失则 degrade”。当前实现的数据源与 schema 契约不一致，会在真实内容里展示错误缩略图。

**修复建议**：
```python
# 当前（问题代码片段）
character_refs = list(graph.get("character_refs") or [])
scene_anchor = graph.get("scene_anchor")
...
for asset_id, asset in assets.items():
    if target_type == "character" and target_ref in character_refs:
        characters.append(normalized)

# 建议
sidecar = read_dep_index_sidecar_for_scene(scene_path)  # scene.json -> scene.deps.json
asset_ids = sidecar.get("visual_asset_ids_referenced")
if not isinstance(asset_ids, list):
    return empty_visual_payload(manifest_loaded=manifest is not None)
for asset_id in asset_ids:
    asset = assets.get(asset_id)
    if isinstance(asset, dict):
        bucket_projected_asset_by_manifest_metadata(asset_id, asset)
```

测试也要反过来写：在 `tools/review_ui/tests/test_api_integrations.py`:58 的 happy path 里加入一个 manifest decoy asset，它匹配 `character_refs` 但不在 `scene.deps.json.visual_asset_ids_referenced`，断言它不会出现在响应里。

### 4.2 [ERR] `tools/review_ui/data.py`:172 — playtest 默认扫描位置和 T-3.4 CLI 实际输出位置不一致

**问题**：`ReviewDataLoader` 默认 `self.playtest_root = self.batch_dir`，后续 `get_playtest()` 只扫 `batch_dir/playtest_*`。但 T-3.4 的 `generator.playtest.cli` 默认把 run 写到 `generator/experiments/playtest_NNN/`；review UI 的 `batch_dir` 通常是某个 scene batch 目录（如 `generator/experiments/<timestamp>_...`），不是 experiments root。这样真实 playtest 已经跑过时，UI 仍会显示“未跑 playtest”。

**为什么是 IMPORTANT**：F13 degrade 要求“依赖缺失时不阻塞”，不是把已存在的数据误判为缺失。当前默认路径会让 PR 的核心 playtest worst paths/scenes 视图在正常 CLI 输出下不可见。

**修复建议**：
```python
# 当前（问题代码片段）
self.playtest_root = (
    playtest_root.resolve() if playtest_root else self.batch_dir
)

# 建议
if playtest_root:
    self.playtest_root = playtest_root.resolve()
elif self.batch_dir and self.batch_dir.parent.name == "experiments":
    self.playtest_root = self.batch_dir.parent
else:
    self.playtest_root = self.batch_dir
```

同时把 `tools/review_ui/tests/conftest.py`:371 的 fixture 改成在 batch 目录旁边创建 `playtest_001/`，或额外加一组 production-default 路径测试，避免测试继续固定错误契约。

### 4.3 [SCHEMA] `tools/review_ui/data.py`:810 — chapter 分组没有使用 dep_index sidecar 的 `chapter_id` / `act_id`

**问题**：`get_chapters()` 只返回 ontology 里的 `chapters[].acts[].included_scenes`；前端 `tools/review_ui/static/app.js`:957 也只用 `included_scenes` 建 `sceneAnchorToChapter`。本轮要求是从 `chapter.schema.json` 加 dep_index sidecar 的 `chapter_id` / `act_id` 按 act → chapter → scene 分组，并在 `chapter_id` / `act_id` 缺失时 fallback 到 T-3.6a 平铺列表。当前实现会在 sidecar 缺字段时仍显示 chapter/orphan 信息，也无法反映 sidecar 里的真实场景归属。

**为什么是 IMPORTANT**：`chapter_id` / `act_id` 是 ADR-023/T-3.2 sidecar 的 optional missing-only 字段；T-3.6b 的 degrade 条件也绑定它们。绕开 sidecar 会让 chapter view 的来源变成 ontology 静态列表，而不是生成时记录的 scene 归属。

**修复建议**：
```python
# 当前方向
for chap in ontology.get("chapters") or []:
    for act in chap.get("acts") or []:
        included_scenes = act.get("included_scenes") or []

# 建议方向
# 1. list_scenes / scene detail 层读取 scene.deps.json 的 chapter_id 和 act_id。
# 2. /api/chapters 返回 ontology chapter/act metadata + sidecar placement map。
# 3. 前端只有在 scene sidecar 同时存在 chapter_id 和 act_id 时启用 chapter tree。
# 4. 缺任一字段时回退到 T-3.6a 平铺列表，不显示“未归入 chapter / act”的伪状态。
```
