## 4. 应修（🟡 IMPORTANT）

### 4.1 [ERR] generator/scene_strategies.py:502 — fill 成功后未校验生成节点是否仍匹配 skeleton 的 type / speaker

**问题**：`fill_skeleton()` 只在 `generate_node()` 内检查 `allowed_targets`，成功后直接把 LLM 返回的 node_id 覆盖成 skeleton id。`generate_node()` 当前不会校验返回节点的 `type` 是否等于 `NodeRequirement.node_type`，也不会校验 `speaker_ref` 是否等于 skeleton 的 `speaker_ref`。如果 LLM 对一个 skeleton dialogue 节点返回了 schema 合法的 end 节点，`options=[]` 会绕过 allowed_targets 检查，最终仍可能 `success=True`，但 skeleton 规划出的出边已经丢失。

**为什么是 IMPORTANT**：T-2.5 的核心是 skeleton-first，`allowed_targets` 只能限制“指向哪里”，不能保证“这个节点还是 skeleton 规定的节点类型/说话人”。这会产生隐藏的拓扑偏离，且现有测试没有覆盖。

**修复建议**：
```python
# 当前
node_dict = dict(result.node or {})
node_dict["node_id"] = skel_node.node_id
filled_nodes[skel_node.node_id] = node_dict

# 建议：在 generate_node 的 validator_errors 阶段加入 requirement 检查，确保可重试
validator_errors.extend(
    _check_node_requirement(response.content, node_requirement)
)

# 至少检查：
# - node["type"] == node_requirement.node_type
# - expected_speaker_ref 非 None 时 node["speaker_ref"] == expected_speaker_ref
# - dialogue 节点仍有 options，end 节点仍为空 options（已有 schema 检查，但类型匹配后更稳）
```

### 4.2 [ERR] generator/scene_strategies.py:563 — system_time 丢失，active_clocks 未进入 fill 阶段的 generate_node prompt

**问题**：`generate_scene_skeleton_first()` 把 `system_time` 传给了 skeleton 阶段，但构造 `scene_context` 时没有保留它；`active_clocks` 虽然放进 `scene_context`，随后 `_graph_context_from_scene_context()` 又固定写成 `faction_clocks={}`。结果是每个 fill 节点的 `generate_node()` prompt 看不到 `active_clocks` / `system_time`，只有 skeleton prompt 看得到。

**为什么是 IMPORTANT**：T-2.5 要求各节点输入 prompt 含 `active_clocks` / `system_time` 等 GraphContext 扩展信息；ADR-017 也要求 prompt 注入当前活跃 clocks。当前测试 `test_scenario_6_prompt_includes_context_fields` 只断言 phase-1 skeleton prompt，未覆盖真正产出节点文本的 fill prompt。

**修复建议**：
```python
# 当前
scene_context = {
    "scene_anchor": scene_setting.scene_anchor,
    "location_candidates": location_candidates or [],
    "primary_location_ref": scene_setting.primary_location_ref,
    "involved_characters": list(participating_npcs),
    "active_clocks": active_clocks or [],
    "character_refs": [...],
}

return GraphContext(
    ...,
    faction_clocks={},
)

# 建议
scene_context["system_time"] = system_time or {"scene_count": 0, "long_rest_count": 0}

# 然后让 fill 阶段的 node prompt 明确渲染：
# - active_clocks（字段名不要回退成 faction_clocks）
# - world.scene_count / world.long_rest_count
# 并补一个测试：检查 provider.user_prompts[1:] 的 fill prompts，而不是只查 user_prompts[0]。
```
