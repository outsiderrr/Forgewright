## 3. 必修（🔴 CRITICAL）

### 3.1 [SCHEMA] schema/content_dependency_index.schema.json:44 — state path pattern 接受裸 namespace，未真正落入 ADR-016 五命名空间路径

**问题**：`state_paths_read` / `state_paths_written` 的 pattern 允许 `"world"`、`"flag"`、`"player"`、`"relationship.vellin"` 这类不完整路径通过，因为末尾 `(\.[a-z0-9_]+)*` 可为 0 次。测试还在 `schema/tests/test_content_dependency_index.py:214` 明确把 `"world"` / `"flag"` / `"player"` 当作正样本锁住。

**为什么是 CRITICAL**：ADR-023 / F15 要求 sidecar 自身的 `state_paths_read` / `state_paths_written` 必须落入 ADR-016 五命名空间 path pattern；`generator/protocols/STAGE_2_BASELINE_PROTOCOL.md:91` 也明示裸 namespace 不合法。这里是新 schema 的核心收紧目标，放过非法 path 会让 T-3.7 dep_propagate 的反向传播语义变脏。

**修复建议**：
```json
// 当前
"pattern": "^(world|faction\\.[a-z0-9_]+|relationship\\.[a-z0-9_]+|flag|player)(\\.[a-z0-9_]+)*$"

// 建议：至少拒绝裸 world/flag/player，并让 relationship 至少有 slug + 字段
"pattern": "^(world\\.[a-z0-9_]+(\\.[a-z0-9_]+)*|faction\\.[a-z0-9_]+(\\.[a-z0-9_]+)*|relationship\\.[a-z0-9_]+\\.[a-z0-9_]+(\\.[a-z0-9_]+)*|flag\\.[a-z0-9_]+(\\.[a-z0-9_]+)*|player\\.[a-z0-9_]+(\\.[a-z0-9_]+)*)$"
```

同时把测试改成反向卡口：`world` / `flag` / `player` / `relationship.vellin` 应 fail；保留 `world.scene_count`、`flag.player_knows_letter`、`player.gold`、`relationship.vellin.trust` 正样本。

### 3.2 [SCHEMA] schema/content_dependency_index.schema.json:26 — scene_id pattern 比 ADR-023 要求更窄，未与 graph_id 对齐

**问题**：schema 使用 `^[a-z][a-z0-9_]*$`，拒绝数字开头的 scene id；测试 `schema/tests/test_content_dependency_index.py:279` 还把 `"1scene"` 拒收锁为预期。但 ADR-023 / STAGE_3_TASKS §3.2 明确写的是 `scene_id` pattern 与 dialogue_graph `graph_id` 对齐为 `^[a-z0-9_]+$`。

**为什么是 CRITICAL**：这是 F15 明列的四个 schema 加严项之一。当前写法会让某些合法 graph_id 无法写 sidecar，导致 T-3.5 批量调度器在 “scene.json 合法但 `<scene>.deps.json` 不合法” 的分裂状态失败；JSON Schema 又是本项目唯一 schema 真相源（CLAUDE.md 规则 6）。

**修复建议**：
```json
// 当前
"pattern": "^[a-z][a-z0-9_]*$"

// 建议
"pattern": "^[a-z0-9_]+$"
```

`scene_history_referenced.items.pattern` 也应同步改成同一 pattern。测试里保留大写 / 连字符 fail，但把数字开头改成 pass。

## 4. 应修（🟡 IMPORTANT）

### 4.1 [SCHEMA] schema/content_dependency_index.schema.json:82 — act_id 引用侧 pattern 与 chapter.schema.json 不一致

**问题**：sidecar 的 `act_id` pattern 是 `^act[a-z0-9_]*$`，会接受 `"act"` / `"actarrival"`，但正式 chapter schema 在 `schema/chapter.schema.json:35` 使用 `^act_[a-z0-9_]{1,64}$`。文档 `docs/SCHEMA_v0.3.md:80` 还写“与 chapter.schema.json 形态同源”，但实际没有同源。

**为什么是 IMPORTANT**：这不会立刻破坏 schema 测试，但会让 sidecar 记录一个 chapter schema 不可能解析到的 act id，后续 T-3.9 chapter_assembler 和 T-3.7 dep_propagate 会在跨文件闭合时踩到隐藏不一致。

**修复建议**：
```json
// 当前
"pattern": "^act[a-z0-9_]*$"

// 建议
"pattern": "^act_[a-z0-9_]{1,64}$"
```

补测试：`"act_arrival"` pass；`"act"` / `"actarrival"` fail。

## 5. 可选改进（🟢 NICE）

### 5.1 [STYLE] schema/content_dependency_index.schema.json:2 — 新 schema 的 dialect / $id 体例与现有 schema 文件不一致

**问题**：现有 `/schema/*.schema.json` 都使用 `"$schema": "https://json-schema.org/draft/2020-12/schema"` 和 `https://forgewright.local/schemas/...` 风格 `$id`；本文件使用 draft-07 与 `https://forgewright.dev/schema/...`。当前关键字基本兼容，所以不是阻塞问题。

**为什么是 NICE**：T-3.2 要求与 character / location / clock / chapter schema 同款体例；统一 dialect 与 `$id` 能减少后续 schema registry / datamodel-code-generator 接入时的意外差异。

**修复建议**：改成与同目录 schema 一致的头部：
```json
"$schema": "https://json-schema.org/draft/2020-12/schema",
"$id": "https://forgewright.local/schemas/content_dependency_index.schema.json"
```
