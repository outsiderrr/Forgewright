## 4. 应修（🟡 IMPORTANT）

### 4.1 [ERR] validator/dialogue_validator.py:273 — `reachability_condition` 未进入 C2/C3/C6/C8 检查

**问题**：`_check_condition()` 目前只在 `options[i].condition` 上调用。`Node.reachability_condition` 同样是 `StateCondition`，但不会触发 path namespace、relationship slug、condition op、形态混用这几类机械检查；例如 `reachability_condition.path = "stats.hp"` 会返回 0 issue。

**为什么是 IMPORTANT**：T-2.4 / ADR-020 要求机械预检覆盖 `state_condition.path` 与 StateCondition 形态互斥；SCHEMA_v0.md §3.2 明示 node 级 `reachability_condition` 是 `StateCondition`。漏掉它会让生成内容在 node 入口条件上绕过 R8 机械预检。

**修复建议**：
```python
# 当前（只检查 option.condition）
cond = opt.get("condition")
if cond is not None:
    _check_condition(cond, f"{prefix}.condition", slugs, issues)

# 建议（在 options 循环前也检查 node 级条件）
reachability = node.get("reachability_condition")
if reachability is not None:
    _check_condition(reachability, "reachability_condition", slugs, issues)
```

同时补 1 个测试：`reachability_condition.path = "stats.hp"` 应报 `PATH_NS_INVALID`；再补 1 个 relationship unknown slug 可覆盖 C3 反查链。

### 4.2 [TEST] validator/tests/test_dialogue_validator.py:486 — gold snapshot 未固定“3 处已知 C1”的精确位置

**问题**：`test_gold_scene_only_known_c1_issues` 只断言没有非 `OPT_LEN_OVER` code。它不会断言 C1 的数量和 `(node_id, field_path)`，所以未来 gold scene 若新增第 4、第 5 个长选项，测试仍会通过。

**为什么是 IMPORTANT**：A 阶段报告声称 snapshot 固定 3 处已知 C1 contract，用于防 future 静默退化；当前断言只能防“新 code”，不能防“同 code 新位置”。这会削弱 R3 已知遗留的边界管理。

**修复建议**：
```python
# 当前
other_codes = {
    i.code
    for issues in by_node.values()
    for i in issues
    if i.code != "OPT_LEN_OVER"
}
assert not other_codes

# 建议：不修 gold，只固定已知 C1 快照
known_c1 = {
    ("arrival_waystation", "options[2].text"),
    ("patrol_arrives", "options[0].text"),
    ("patrol_arrives", "options[2].text"),
}
actual_c1 = {
    (nid, i.field_path)
    for nid, issues in by_node.items()
    for i in issues
    if i.code == "OPT_LEN_OVER"
}
assert actual_c1 == known_c1
assert not other_codes
```
