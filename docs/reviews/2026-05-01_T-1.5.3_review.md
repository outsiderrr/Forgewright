## 3. 必修（🔴 CRITICAL）

### 3.1 [SAFETY] /generator/providers/manual_import.py:115 — `asset_id_stub` 可路径穿越写出 `_pending`
**问题**：`generate()` 直接执行 `self.pending_root / asset_id_stub`，随后创建目录并写入 `prompt.md` / `meta.json` / `README.md`。如果上层误传或外部入口传入 `../escaped`、`../../..` 之类的 stub，provider 会把 prompt 包写到 `_pending` 之外；我用临时副本验证过，`asset_id_stub="../escaped"` 会在 `pending_root` 的父目录创建 `escaped/prompt.md`。

**为什么 CRITICAL**：这是文件写入路径穿越。SCHEMA_v0.2.md §2.1 已把最终 `asset_id` 收窄为 `^img_[a-z0-9_]{1,64}$`，而本任务关键决策又明确 `asset_id_stub == final asset_id`；provider 写盘前不复用这条约束，会绕过 schema 侧的路径安全意图。它还可能让生成层越过 ADR/CLAUDE.md 的模块边界，向非 `_pending` 目录落文件。

**建议修复**：
```python
# 当前
package_dir = self.pending_root / asset_id_stub
package_dir.mkdir(parents=True, exist_ok=True)

# 改为
_ASSET_ID_RE = re.compile(r"^img_[a-z0-9_]{1,64}$")

if not _ASSET_ID_RE.fullmatch(asset_id_stub):
    raise ImageProviderError(
        "asset_id_stub must match ImageAsset.asset_id pattern "
        "^img_[a-z0-9_]{1,64}$"
    )

pending_root = self.pending_root.resolve()
package_dir = (pending_root / asset_id_stub).resolve()
try:
    package_dir.relative_to(pending_root)
except ValueError as exc:
    raise ImageProviderError(
        f"asset_id_stub escapes pending_root: {asset_id_stub!r}"
    ) from exc

package_dir.mkdir(parents=True, exist_ok=True)
```

同时在 `/generator/tests/test_manual_import_provider.py` 加一个失败路径测试：传 `asset_id_stub="../escaped"` 期望抛 `ImageProviderError`，并断言 `tmp_path / "escaped"` 没有被创建。

**模块边界状态**：✅ 在边界内（可修）
