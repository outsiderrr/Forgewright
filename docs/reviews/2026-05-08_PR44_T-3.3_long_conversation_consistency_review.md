## 3. 必修（🔴 CRITICAL）

### 3.1 [SCHEMA] generator/context_assembler.py:602 — TokenMetrics 产物不符合 content_dependency_index schema

**问题**：`compute_prior_summary_token_metrics()` 返回的 `truncation_reason` 是 `None` / `"no_truncation"` / `"kept_recent_with_boundary"` / `"kept_recent_only"`，而 T-3.2 已落地 schema 只接受 `"none"` / `"summaries_over_5"` / `"token_budget"` / `"manual_override"`。同一函数生成的 `summary_source_hashes` 也是裸 64 位 hex；schema 要求 `^sha256:[a-f0-9]{64}$`。

**为什么是 CRITICAL**：CLAUDE.md 规则 6 要求 JSON Schema 是唯一真相源；ADR-024 + `schema/content_dependency_index.schema.json` 已锁定这 4 个 metrics 字段的 sidecar 形态。T-3.5 按本 PR 文档“copy same four fields”写 sidecar 时会直接生成 schema-invalid JSON。

**修复建议**：
```python
# 当前（问题代码片段）
if not summaries:
    return [], None
if n <= PRIOR_SCENE_SUMMARY_CAP:
    return list(summaries), "no_truncation"
...
reason = (
    "kept_recent_with_boundary"
    if saw_boundary_in_kept
    else "kept_recent_only"
)
return hashlib.sha256(raw.encode("utf-8")).hexdigest()

# 建议
if not summaries:
    return [], "none"
if n <= PRIOR_SCENE_SUMMARY_CAP:
    return list(summaries), "none"
...
reason = "summaries_over_5"
return f"sha256:{hashlib.sha256(raw.encode('utf-8')).hexdigest()}"
```

同时把 `TokenMetrics.truncation_reason` 改成非 nullable `str = "none"`，并把 `test_prior_scene_summaries.py` 里期待旧枚举/裸 hash 的测试改成 schema 对齐断言。

## 4. 应修（🟡 IMPORTANT）

### 4.1 [ARCH] generator/context_assembler.py:290 — `prompt_token_estimate` 只估 summary block，不是“总 prompt”

**问题**：`TokenMetrics` 文档明确写“not the full prompt's token count”，实现也只用 `render_prior_scene_summaries_block(kept)` 的长度估算。ADR-024 / STAGE_3_TASKS §3.3 / SCHEMA_v0.3 §9.5 要的是“注入 prompt 总 token 估算”，并且说明应含 SceneGraphContext + prior summaries + skeleton/fill 模板渲染段。

**为什么是 IMPORTANT**：不会立刻让 schema validation 失败，但会让阶段 3 用来判断 token 曲线是否发散的指标系统性偏低，T-3.5/T-3.12 的监控结论会失真。

**修复建议**：
```python
# 当前（问题代码片段）
rendered = render_prior_scene_summaries_block(kept)
estimate = max(0, len(rendered) // _PROMPT_CHARS_PER_TOKEN)

# 建议方向
# 在 skeleton/fill prompt 完整渲染后，用实际 prompt 文本求和：
prompt_token_estimate = estimate_tokens(
    SCENE_SYSTEM_PROMPT
    + skeleton_user_prompt
    + "".join(fill_user_prompts)
)
```

如果 T-3.3 不想重接 `scene_strategies` 的回传结构，也至少不要把 summary-only 值写进 `prompt_token_estimate`；可临时保留内部字段名如 `prior_summary_token_estimate`，避免污染 ADR-024 指标语义。

### 4.2 [ERR] generator/scene_summary_writer.py:418 — LLM draft 路径没有执行 summary 长度上限

**问题**：手动编辑路径 `_summary_from_edited()` 会拒绝超过 800 codepoints 的 summary，但 LLM draft 路径 `draft_to_summary()` 直接把 `draft.summary` 提升为 `PriorSceneSummary`，`write_summary_sidecar()` 也不再校验。只要 provider 返回超长摘要，默认 `[A]ccept` 和 `--auto-accept` 都会落盘。

**为什么是 IMPORTANT**：T-3.3 的 C-tier 方案靠“每条摘要短 + 最多 5 条”控制 prompt 膨胀；只靠 prompt 要求 LLM 自觉 ≤200 字不够稳。超长 sidecar 后续会被直接注入 skeleton/fill prompts。

**修复建议**：
```python
# 当前（问题代码片段）
def draft_to_summary(draft: SummaryDraft) -> PriorSceneSummary:
    return PriorSceneSummary(
        scene_id=draft.scene_id,
        summary=draft.summary,
        key_state_paths=list(draft.key_state_paths),
        chapter_id=draft.chapter_id,
        act_id=draft.act_id,
    )

# 建议
def _validate_summary_text(summary: str) -> str:
    body = summary.strip()
    if not body:
        raise RuntimeError("`summary` is required and must be non-empty")
    if len(body) > 800 or count_cjk_chars(body) > 200:
        raise RuntimeError("`summary` exceeds ADR-024 length cap")
    return body

def draft_to_summary(draft: SummaryDraft) -> PriorSceneSummary:
    return PriorSceneSummary(
        scene_id=draft.scene_id,
        summary=_validate_summary_text(draft.summary),
        key_state_paths=list(draft.key_state_paths),
        chapter_id=draft.chapter_id,
        act_id=draft.act_id,
    )
```

建议复用同一个 validator 覆盖 LLM draft、manual edit、write-sidecar 三条入口，并补一个 provider 返回 900 字符摘要的失败测试。

### 4.3 [SCHEMA] generator/scene_summary_writer.py:177 — PriorSceneSummary 的 `scene_id` 未按 ADR-023 pattern 校验

**问题**：`read_summary_sidecar()` 只要求 `scene_id` 是非空字符串；manual edit 和 write path 也没有校验 `^[a-z0-9_]+$`。当前 dialogue_graph `graph_id` 仍允许连字符，`_scene_id_from_graph()` 会原样取 graph_id，因此合法 scene graph 如 `scene-alpha` 会生成不符合 ADR-023 / dep_index `scene_id` pattern 的 prior summary。

**为什么是 IMPORTANT**：ADR-024 明示 `prior_scene_summaries` item shape 的 `scene_id` 要与 ADR-023 dep_index sidecar scene_id 对齐。若这里放过连字符或大写，T-3.5 写 `scene_history_referenced` 时会和 `content_dependency_index.schema.json` 冲突。

**修复建议**：
```python
# 当前（问题代码片段）
if not isinstance(scene_id, str) or not scene_id:
    raise ValueError("...")

# 建议
_SCENE_ID_RE = re.compile(r"^[a-z0-9_]+$")

def _validate_scene_id(scene_id: object) -> str:
    if not isinstance(scene_id, str) or not _SCENE_ID_RE.fullmatch(scene_id):
        raise ValueError("`scene_id` must match ^[a-z0-9_]+$ per ADR-023")
    return scene_id
```

这层校验应覆盖 `read_summary_sidecar()`、manual edit 结果、LLM draft 写入前，以及 `PriorSceneSummary` 直接构造路径（可用 `__post_init__` 或统一工厂函数）。
