### 4.1 [SCHEMA] generator/chapter_assembler.py:78 — chapter / act id 正则被手写成第二份 schema 来源

**问题**：`_CHAPTER_ID_PATTERN` / `_ACT_ID_PATTERN` 在 helper 中手写，测试也只用本地 parametrize 样例覆盖。它们今天碰巧与 `/schema/chapter.schema.json` 一致，但后续 schema 调整时，这里的验证逻辑和测试都可能继续绿，T-3.5 再把 helper 返回值写入 dep_index sidecar，就会重新出现 T-3.2 C 阶段刚修过的 pattern drift 风险。

**为什么是 IMPORTANT**：CLAUDE.md 规则 6 要求 JSON Schema 是唯一 schema 来源；本次 review 目标也特别点名 `act_id` / `chapter_id` pattern 必须与 `chapter.schema.json` 同源严约。

**修复建议**：
```python
# 当前（问题代码片段）
_CHAPTER_ID_PATTERN = re.compile(r"^chap_[a-z0-9_]{1,64}$")
_ACT_ID_PATTERN = re.compile(r"^act_[a-z0-9_]{1,64}$")

# 建议方向：从 schema 或 schema 生成物取得 pattern，并加回归测试
CHAPTER_SCHEMA_PATH = Path(__file__).resolve().parents[1] / "schema" / "chapter.schema.json"
_chapter_schema = json.loads(CHAPTER_SCHEMA_PATH.read_text(encoding="utf-8"))
_CHAPTER_ID_PATTERN = re.compile(_chapter_schema["properties"]["chapter_id"]["pattern"])
_ACT_ID_PATTERN = re.compile(
    _chapter_schema["properties"]["acts"]["items"]["properties"]["act_id"]["pattern"]
)
```

同时在 `generator/tests/test_chapter_assembler.py` 加一条 schema 同源测试：读取 `/schema/chapter.schema.json`，断言 helper 使用的 pattern 与 schema 内 pattern 完全相同。

### 4.2 [ERR] generator/chapter_assembler.py:300 — idempotent skip 会留下 target act 内重复 scene_anchor

**问题**：当前 data repair 只清理“target 之外”的重复引用。若 ontology 已经有 `included_scenes = ["scene_a", "scene_a"]`，再次 assign 同一个 target 会走 `already_in_target and not was_elsewhere` 的 early return，返回 `idempotent_skip` 且不写文件，重复值原样保留。这和 PR 摘要声称的“数据修复全覆盖”不一致，也会让后续 chapter 分组 / dep propagate 把同一 scene 当成重复成员处理。

**为什么是 IMPORTANT**：ADR-016 把 Chapter/Act 作为本体层容器；同一 scene 在同一 act 内重复不是合法业务状态。T-3.9 helper 既然负责 reassign cleanup，就不应在显式遇到该 scene 时报告成功但保留腐败态。

**修复建议**：
```python
# 当前（问题代码片段）
included = _ensure_list(target_act, "included_scenes")
already_in_target = scene_anchor in included
was_elsewhere = _remove_scene_anchor_elsewhere(...)

if already_in_target and not was_elsewhere:
    return ChapterAssignment(..., reason="idempotent_skip")

# 建议
included = _ensure_list(target_act, "included_scenes")
target_count = included.count(scene_anchor)
already_in_target = target_count > 0
was_elsewhere = _remove_scene_anchor_elsewhere(...)

if target_count > 1:
    target_act["included_scenes"] = _dedupe_scene_anchor(included, scene_anchor)
    included = target_act["included_scenes"]

if already_in_target and not was_elsewhere and target_count == 1:
    return ChapterAssignment(..., reason="idempotent_skip")
```

并补一条测试：先把同一 `scene_anchor` 放进 target act 两次，再调用 `assign_scene_to_chapter()`，断言最终只剩 1 次且发生写入。
