### 4.1 [SAFETY] /schema/image_asset.schema.json:85 — `file_path` 只校验非空，挡不住目录穿越或绝对路径

**问题**：`file_path` 的描述写的是“相对仓库根的路径”，但 schema 只要求 `minLength: 1`。我用当前 schema 探针验证过，`"../outside/secret.png"` 也会通过；同理绝对路径、URL、非 `content/visuals/` 路径都能进入 ImageAsset。T-1.5.7 的 import CLI 会围绕这些元数据做落盘 / manifest / 本体写入，schema 源头过宽会把路径安全问题推给后续实现者。

**为什么 IMPORTANT**：这是 SAFETY 维度的“pattern 过宽”。它还没进入运行时代码，所以不升 🔴；但 ImageAsset 是后续视觉资产入库的单一结构契约，越早收窄越便宜。

**建议修复**：

```json
// 当前
"file_path": {
  "description": "相对仓库根的路径（如 'content/visuals/vellin/img_vellin_neutral.png'）。",
  "type": "string",
  "minLength": 1
}

// 改为
"file_path": {
  "description": "相对仓库根、仅允许入库后的 content/visuals 下 PNG/WEBP 路径（如 'content/visuals/vellin/img_vellin_neutral.png'）。",
  "type": "string",
  "pattern": "^content/visuals/[A-Za-z0-9_/-]+\\.(png|webp)$",
  "minLength": 1
}
```

同时在 `/schema/tests/test_image_asset_schema.py` 增加负样本：`../outside/secret.png`、`/tmp/secret.png`、`content/not_visuals/img.png` 应被拒收。

**模块边界状态**：✅ 在边界内（可修）

### 4.2 [SCHEMA] /schema/image_asset.schema.json:90 — `prompt_hash` 声称 sha256 hex，却接受任意字符串

**问题**：`prompt_hash` 的 description 和 SCHEMA_v0.2.md 都说它是 prompt 文本的 sha256 hex，但 schema 只写了 `"type": "string"`。当前 schema 会接受 `"not-sha256"`；SCHEMA_v0.2.md:86 的示例 `"a3f1...e7c9"` 也不是完整 sha256，容易被后续会话复制成“合法示例”。

**为什么 IMPORTANT**：`prompt_hash` 是 manual/API parity、prompt 复现、资产 provenance 的追溯锚点。它不是留给 image_validator 的跨对象语义约束，而是单字段格式约束，应由 JSON Schema 这个单一真相源先挡掉脏值。

**建议修复**：

```json
// 当前
"prompt_hash": {
  "description": "🟡 生成时 prompt 文本的 sha256 hex；用于追溯。",
  "type": "string"
}

// 改为
"prompt_hash": {
  "description": "🟡 生成时 prompt 文本的 sha256 hex；用于追溯。",
  "type": "string",
  "pattern": "^[a-f0-9]{64}$"
}
```

同时：

- 把 `/docs/SCHEMA_v0.2.md:86` 的 `"a3f1...e7c9"` 换成 64 位小写 hex 示例。
- 在 `/schema/tests/test_image_asset_schema.py` 增加 `test_invalid_prompt_hash_rejected`。

**模块边界状态**：✅ 在边界内（可修）

## 5. 可选改进（🟢 NICE）

### 5.1 [STYLE] /docs/SCHEMA_v0.2.md:141 — `manifest.json` “不索引”说法容易误导 T-1.5.7

**问题**：这里写“`manifest.json` 也是全量存（不分文件、不索引）”，但 STAGE_1.5_TASKS.md 的 T-1.5.7 草案把 manifest 设计成 `assets: dict[str, ImageAsset]`，即按 `asset_id` 做索引、值为完整 ImageAsset。当前句子本意应是“不只存 asset_id stub”，不是禁止索引。

**为什么 NICE**：这不会破坏 T-1.5.2 的 schema，但会给后续实现 manifest 的 Claude 会话制造一点歧义。

**建议修复**：把该句改成类似：

```markdown
简化层次。`manifest.json` 也保存完整 ImageAsset 对象（可按 `asset_id` 建索引），而不是只存 `asset_id` stub；与本体中的嵌入对象保持字段一致。
```

**模块边界状态**：✅ 在边界内（可修）
