### 4.1 [ARCH] validator/graph_validation.py:199 — validate_graph_topology 未实际复用 graph_check，2A 会漏报旧结构错误

**问题**：`graph_validation.py` import 了 `graph_check` / `graph_check_layer`，但 `validate_graph_topology()` 没有调用旧的 `graph_check.check()`。它从 `nodes` 自建 DiGraph，且只给存在的 target 加边；因此 dangling `target_node_id`、没有 end 节点、end 全不可达、旧 SCC warning 等既有 graph_check 约束不会进入新的 `TopologyResult`。

**为什么是 IMPORTANT**：T-2.7 / STAGE_2_TASKS §2.7、§8 明确说 `graph_validation.py` 是"包装现有 graph_check.py + 叠加 2A 新逻辑"。现在旧入口未破，但新 2A 双报可能对结构非法图给出 false pass，影响后续 T-2.8/T-2.13 对拓扑健康度的汇总。

**修复建议**：
```python
# 当前：validate_graph_topology 直接从头构图
nodes = graph.get("nodes")
entry = graph.get("entry_node_id")
...
dg = nx.DiGraph()

# 建议：先调用旧 graph_check，再把旧 Issue 映射成 TopologyIssue
legacy_errors, legacy_warnings = graph_check.check(graph)
issues.extend(_legacy_issue_to_topology(i, severity="error") for i in legacy_errors)
issues.extend(_legacy_issue_to_topology(i, severity="warning") for i in legacy_warnings)

# 然后再叠加 ADR-021 的 A2/A3/A4/active clocks 新检查
```

补一组 `validate_graph_topology()` 级测试：dangling target、无 end、end 不可达，都应让 `has_error=True`。

### 4.2 [ERR] validator/graph_validation.py:153 — CONDITION_FORM_INVALID 漏掉 `not: null` 与 leaf 缺 `value`

**问题**：`_check_condition_form()` 把顶层 `condition is None` 视为合法，这没问题；但递归处理 `{"not": None}` 时也会走到同一个 `None -> []` 分支，导致非法复合条件通过。叶条件分支也只检查 `op` 和 `path`，没有验证 `value` 必填，所以 `{"op": "eq", "path": "flag.x"}` 会被 2A 当成合法形态。

**为什么是 IMPORTANT**：ADR-021 的 2A 范围包含 condition 引用形态合法性（path 命名空间 / op 枚举 / 字段结构）。这些结构在 `schema/state_condition.schema.json` 里是非法的，但新 2A 会漏报，后续双报会把坏 condition 表述成拓扑通过。

**修复建议**：
```python
# 当前：not 子条件复用顶层 None 逻辑；leaf 不检查 value
else:
    issues.extend(
        f"not: {sub}" for sub in _check_condition_form(cond.get("not"))
    )

op = cond.get("op")
...
path = cond.get("path")
...
return issues

# 建议：区分 top-level null 与 composite child；leaf 要求 op/path/value 三键齐全
if key == "not":
    child = cond.get("not")
    if not isinstance(child, dict):
        issues.append("condition.not must be a StateCondition object")
    else:
        issues.extend(f"not: {sub}" for sub in _check_condition_form(child))
    return issues

required_leaf = {"op", "path", "value"}
missing = required_leaf - set(cond)
if missing:
    issues.append(f"leaf condition missing required key(s): {sorted(missing)}")
```

建议新增测试：`{"not": None}`、leaf 缺 `value`、effect 缺 `value`（若 2A 也承诺检查 effect 字段结构）。

### 4.3 [ARCH] validator/graph_validation.py:378 — ACTIVE_CLOCKS_OVER_SOFT_LIMIT 只数 ticks_filled，忽略 advance_rule 命中

**问题**：active clock 统计当前只在 `ticks_filled > 0` 时加一。T-2.7 prompt 要求"按 ticks_filled > 0 或 advance_rule 命中判定"，但实现没有任何 `advance_rule` 判定入口；测试也只覆盖了 `ticks_filled`，甚至把所有 0 tick clocks 一律视作 inactive。

**为什么是 IMPORTANT**：ADR-017 D9 的软上限是为阶段 2 的状态空间复杂度预警服务。若一个场景有 11 个 `ticks_filled=0` 但当前事件会触发的 clock，validator 不会报 `ACTIVE_CLOCKS_OVER_SOFT_LIMIT`，实测倒推会低估真实活跃 clock 压力。

**修复建议**：
```python
# 当前：只看 ticks_filled
ticks_filled = c.get("ticks_filled")
if isinstance(ticks_filled, int) and ticks_filled > 0:
    active_count += 1

# 建议：集中成 helper，并覆盖 advance_rule 可判定分支
if _clock_is_active(c, graph=graph):
    active_count += 1

def _clock_is_active(clock: dict, *, graph: dict) -> bool:
    ticks_filled = clock.get("ticks_filled")
    if isinstance(ticks_filled, int) and ticks_filled > 0:
        return True
    return _advance_rule_hits_current_graph(clock.get("advance_rule"), graph)
```

如果当前上下文不足以判断 `advance_rule` 是否命中，也应显式加参数或保守记录 warning，而不是静默把 0 tick clocks 当 inactive。
