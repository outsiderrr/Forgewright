### 4.1 [ARCH] validator/consistency_check.py:121 — 未强制 “非空 dialogue[] ⇒ node.speaker_ref 必为 null” 不变量

**问题**：ADR-040 决策三明确写了：节点携带非空 `dialogue[]` ⇒ `node.speaker_ref` 必为 `null`。当前 `consistency_check` 只检查 `dialogue[].speaker_ref ⊆ character_refs`，没有检查节点级 `speaker_ref`。我用最小反例实测：一个节点同时有 `speaker_ref: "char_vellin"` 和非空 `dialogue`，`validate()` 返回 `passed=True`，schema / graph / cons 均 0 issue。

**为什么是 IMPORTANT**：这不破当前装配器产物，因为 `assemble.py` 三个分支都 emit `speaker_ref=None`；但 validator 是回流文本和手改 JSON 的守门口。漏掉该不变量会让 post-040 新节点重新混入 legacy 单说话人归属，削弱 “narration=旁白、dialogue=对白” 的机器契约。

**修复建议**：
```python
# validator/consistency_check.py，在 dialogue list 分支附近补
dialogue = node.get("dialogue")
if isinstance(dialogue, list):
    if dialogue and speaker_ref is not None:
        issues.append(
            Issue(
                level="cons",
                location=node_id,
                message=(
                    "node has non-empty dialogue[] so speaker_ref must be null "
                    "(ADR-040)"
                ),
            )
        )
    for d_idx, entry in enumerate(dialogue):
        ...
```

同时加一个 fixture/test：`dialogue` 非空、`speaker_ref` 非 null、所有 speaker 都在 `character_refs` 内，期望失败在 `cons` 层。

### 4.2 [SCHEMA] schema/node.schema.json:21 — `narration` 的 schema 源描述仍保留旧语义

**问题**：ADR-040 的核心语义是 `narration` 从“场景/对白文本”改成“旁白”。但 JSON Schema 源头仍写 `玩家看到的场景/对白文本。`，生成模型也继承到 `generator/models/_generated/node.py:95`。虽然新增 `dialogue` 字段的 description 里补了新语义，但主字段自己的描述仍与 ADR-040 冲突。

**为什么是 IMPORTANT**：本项目规则 6 要求 JSON Schema 是唯一 schema 来源。schema description 会进入 codegen，也可能被结构化输出 / prompt 工具读取。这里留旧语义，会继续鼓励把 NPC 对白塞进 `narration`，正好违背本 PR 要拆开的契约。

**修复建议**：
```json
// 当前
"narration": {
  "description": "玩家看到的场景/对白文本。",
  "type": "string"
}

// 建议
"narration": {
  "description": "ADR-040：旁白文本（场景/动作白描，无说话人归属）；带说话人的台词必须进入 dialogue[].line。legacy narration-only 节点可保留旧混合文本。",
  "type": "string"
}
```

修完后重新运行 `generator/scripts/regenerate_models.sh`，让 `generator/models/_generated/node.py` 同步更新。可顺手把 `schema/dialogue_graph.schema.json:5` 的 “speaker_ref ⊆ character_refs” 描述扩成包含 `node.dialogue[].speaker_ref`，与 ADR-040 的 schema 影响判定文字一致。
