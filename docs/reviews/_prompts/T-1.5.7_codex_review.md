# 本任务关键设计决策（不要当 bug 抓）

- **手动触发不监视目录**是 P2 决策（避免 macOS watchdog 边角问题）；**不要建议**加 watchdog / fsnotify / inotify。
- **校验失败移到 `_pending/_rejected/<asset_id>/` 而非删除**是有意（作者复盘）；**不要建议**改成删除 PNG 或写到 `/content/visuals/_failed/`。
- **角色桩 `visual_assets` 直接嵌入完整 ImageAsset 对象**（不通过 asset_id 引用）是 P0.1 决策（路径 A：简化层次；SCHEMA_v0.2.md §3.2）；**不要建议**改成 `[asset_id]` 引用 / 间接索引。
- **manifest.json 是单文件索引，不是分文件**；scale 时再考虑（YAGNI）；**不要建议**按 character / 按日期分文件。
- **character_id 去 `char_` 前缀**是目录命名约定（`content/visuals/vellin/...`）而非 schema 字段；**不要建议**保留前缀做目录名（与 SCHEMA_v0.2.md §2.3 例子一致）。
- **`scene_<X>` 目录名也去前缀**（`content/visuals/<X>/`）；**`location` 类型保留 `target_ref` 全名**作为目录。这是 STAGE_1.5_TASKS.md T-1.5.7 §流程 step 5 的"选一种实现，在测试 fixture 中固定"——本实现选了"strip prefix for character/scene；保留 location 全名"。
- **`add_asset` 在 asset_id 重复时 raise** 是有意（manifest 是 append-only 索引）；CLI 在调用前先 `if stub in manifest.assets: reject` 捕获并发 log 行。**不要建议**改成 upsert / 静默覆盖。
- **manifest.json 使用 2 空格缩进**，**waystation.json 使用 4 空格缩进**——这是 STAGE_1.5_TASKS.md T-1.5.7 §流程 step 8 的明文要求（"写回，pretty-print 4 空格 + 末尾换行"）；waystation.json 现存文件首次 CLI 运行会从 2 空格→4 空格；这是 spec 行为，不是 bug。
- **`import_log.jsonl` 路径 `/generator/import_log.jsonl`** 类比 `image_cost_log.jsonl`；**没有时间分片**；T-1.5.8 visual_metrics / T-1.5.10 验收复算从单文件读，按 `batch_name` 字段过滤。**不要建议**按日期分文件 / 按 batch 分目录。
- **`save_manifest` 用 temp file + `os.replace` + fsync** 是为防止半写入崩溃留下 0 字节文件；**不要建议**改成"直接写"（lose atomicity）或"加 lock 文件"（YAGNI）。
- **`_check_meta_consistency` 在 image_validator 之外、image_import 之内**——是 STAGE_1.5_TASKS.md T-1.5.7 §流程 step 4 的明文要求："target_ref / character_ref / location_ref 一致性校验……image_validator 语义层"。当前 image_validator (T-1.5.4) 只做机械维度（分辨率/格式/alpha），语义维度由本 CLI 显式做。**不要建议**移到 image_validator（除非作者在阶段 2 决定收口语义层；本任务保留 CLI 内）。
- **`add_asset` / `remove_asset` 返回新实例（不可变风格）** 是 STAGE_1.5_TASKS.md §1 明文（"返回新实例（不可变风格）"）。**不要建议**改成原地修改。
- **CLI 中 `target_type=character` 才更新 ontology**，**`location`/`scene` 不写本体**——按 SCHEMA_v0.2.md §3.3 + synthesis §9.4 推荐：scene/location 资产仅在 manifest.json 用 target_ref 索引。**不要建议**给 scene/location 项也加 visual_assets。
- **target_ref / target_type / asset_role 必须从 meta.json 读，缺字段拒收**——是任务"不要做的事"明文。**不要建议**给缺字段的 stub 补默认值。
- **manifest.json empty skeleton 直接 commit** 是 GPT-5.5 L2 critique 4.8 修补（避免首次运行特殊路径）。**不要建议**让 CLI 首次运行时建 skeleton。
- **`Manifest.schema_version` 字段名（不叫 `version`）** 是 GPT-5.5 L2 critique 5.3 修补（与 JSON 字段名统一）。**不要建议**改名 / 简写。

每条 finding 必须归到下列一类：

| 代号 | 类别 | 说明 |
|---|---|---|
| **ARCH** | 架构合规 | 是否违反 ADR / 模块边界 / 跨模块写入 |

| **ERR** | 错误处理 | 边界处校验、内部不过度防御、异常 vs return-result 一致 |
| **TEST** | 测试 | 覆盖关键分支与失败路径；不冗余、不重言；mock 与真实分离；隔离 fixture 真生效 |
| **DEAD** | 冗余 | 死代码、未用 import、过度抽象、为未发生需求设计 |
| **DEPS** | 依赖 | 新增依赖必要、锁版本、许可证风险 |
| **STYLE** | 风格 | 注释只解释 WHY 不解释 WHAT；命名清晰；项目约定遵守 |
| **OPEN** | 开源就绪度 | 作者 hard-code、公开接口稳定性、文档可移植性 |

# 严重度（3 级）

| 标记 | 级别 | 含义 |
|---|---|---|
| 🔴 | CRITICAL | 必修；违反硬规则 / 安全 / 破坏现有测试 |
| 🟡 | IMPORTANT | 应修；技术债 / 隐蔽 bug / 兼容性风险 |
| 🟢 | NICE | 可选改进，作者拍板是否纳入下一轮 |

**校准**：理想报告应有 ≥ 1 条 🔴 或不报 🔴。若 1300+ 行新代码全是 🟢，说明审得太松；停下来确认实现 commit 是否合理。

**特别关注（本任务的高风险面）**：
- **路径遍历 / 越界写**：`_target_dir_for` 是否能被恶意 `target_ref`（如 `char_../../etc`）骗到 `content/visuals/` 之外？file_path Pydantic pattern 是否真挡得住？测试覆盖了吗？
- **本体写入原子性**：`_ontology_append_visual_asset` 是 read → mutate → temp + replace + fsync 路径；中途崩溃会不会留下半写入的 waystation.json？测试覆盖了吗？
- **manifest 与 ontology 双写一致性**：先写 manifest → 再写 ontology；如果 ontology 写入失败，manifest 已记录该 asset_id 但本体没有对应 visual_assets 项——这是已知半失败窗口，是否值得标 🟡？（提示：作者拍板时间窗 vs 复杂度，本任务接受这一窗口；评审可标 🟡 并标 ⚠️ 跨边界——若要硬解决需引入 WAL / 两阶段提交，本阶段不做）。
- **idempotency**：重跑 `--all-pending` 时，已入库的 asset_id 是否被正确识别 + 不重复写本体？测试覆盖了 `test_duplicate_asset_id_in_manifest_skips_without_moving` 但要看是否充分。
- **dry-run 副作用**：dry-run 模式必须**不**写 manifest / 不写 ontology / 不删 _pending；测试覆盖了 `test_dry_run_does_not_mutate_disk`，复核是否覆盖所有路径。
- **edge case：character_ref / location_ref 与 target_type 不一致**：测试 `test_mirror_field_inconsistency_rejects` 只覆盖 character_ref 漂移；location_ref 漂移 / target_type=scene 的镜像约束未直接测——评审可标 🟢 缺测试。
