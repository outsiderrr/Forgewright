# 本任务关键设计决策（不要当 bug 抓）

- **ImageProvider Protocol 与 LLMProvider 同源风格**（ADR-011 + ADR-014）——最小接口（`generate` + `estimate_cost`），budget / retry / prompt 组装一律不在 provider 层。**不要建议**给 Protocol 加 budget 参数 / retry 参数。
- **ManualImportProvider.estimate_cost = 0.0** 是 ADR-014 约定（ChatGPT Plus 订阅是 sunk cost；marginal $0/张）；**不是 bug**。budget 接口仍统一走（由 T-1.5.5 / T-1.5.6 在上层拦截）。
- **占位 prompt** "[PLACEHOLDER from T-1.5.3 — T-1.5.6 will fill]" 是有意的；T-1.5.6 才会替换为真实 prompt 模板内容。**不要建议**本任务实现 prompt 模板。
- **prompt_hash = sha256(prompt 英文段)** 是用于 trace（`meta.json` → `image_validator` 后续可对照），不是密码学用途，**不需要 HMAC** 或加盐。"英文段"约定 = 从 `## English` 标题往下；无该标题则全文 hash（manual 模式作者就一种 prompt 格式，T-1.5.6 模板会贯彻）。
- **`asset_id_stub` 由调用方（T-1.5.6 generate_visual.py）生成 deterministic stub 后传入，provider 不再内部生成**（GPT-5.5 L2 critique 4.9 修补）。这是为了避免 re-run 同一角色时 ID 漂移、破坏已入库 manifest 的引用闭合性。**不要建议**让 provider 自己生成 ID。
- **`target_ref` / `target_type` / `asset_role` / `asset_id_stub` / `variant_label` 进入 Protocol 接口**（GPT-5.5 L2 critique 3.3 修补）——数据流贯穿到 manifest 入库阶段（T-1.5.7）；否则 manifest 只能猜。**不要建议**精简这些参数。
- **datamodel-code-generator 双 entry 方案 A**（两次 codegen 调用 + pass #2 用 `--output OUT_DIR/image_asset.py` 文件路径）是 T-1.5.2 #4.1 carryover 修补的执行落地。原方案"补一行 image_asset.schema.json"会被 wipe 干掉 dialogue_graph 输出。pass #2 用文件路径是因为 image_asset 无 `$ref`，目录模式会触发 `IsADirectoryError`（实测）。
- **ImageAsset roundtrip 测试用 `created_at: "...Z"`**（不是 `+00:00`）——Pydantic AwareDatetime 在 dump 时把 UTC 规范化为尾随 `Z`；fixture 用 `Z` 才能 bit-identical 等价。这是 Pydantic v2 行为，不是测试 bug。
- **dialogue_graph.py / node.py / option.py / state_*.py 文件 git diff 应为零**——pass #1 输入 / 选项与之前完全一致；`_postprocess_models.py` 的 init_py.exists() 块在新流程下变成空 if（保留作 safety net）。**不要建议**删除 _postprocess 的 init_py 块（idempotent + 防回退）。
