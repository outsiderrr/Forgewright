# 本任务关键设计决策（不要当 bug 抓）

- **一致性 C+B 兜底**（容忍细微差异 C + prompt 描述固定特征 B）是 ADR-014 决策；GPT-Image 不支持 ControlNet/LoRA。**不要建议**加 ControlNet / LoRA / 自训本地 SDXL / character reference image 输入分支——这些是 ADR-014 明确否决的方向，或推到后续 PR。
- **`character_features.py` 是 Python dict 而非 YAML 是有意**——阶段 1.5 试点；阶段 2/3 才转 YAML 化由作者在工坊维护（路径 A：不正式化角色 Schema）。**不要建议**改 YAML / 加 JSON Schema / 把它移进 `/state/ontology/`。
- **prompt 模板中英双段一文件是有意**——作者对照方便，决定是否调 prompt。`ManualImportProvider._english_segment` 用 `## English` 作为 marker 切分。**不要建议**拆成两个文件。
- **基准图（`/content/visuals/_reference/`）只在 prompt 文本里引用路径**，不读图片字节—— OpenAIImageProvider（T-1.5.9）决定是否实际上传；manual 模式作者人工对照基准图。**不要建议**让 generate_visual.py 读图片字节进 prompt。
- **partial_failure 模式（不抛异常给调用方）沿用阶段 1 generate_node 模式**——`ImageBudgetExceeded` → 中止剩余 + 返回已成功的部分（带 budget_exceeded 行）；provider 抛错 → 单条失败不影响后续条；任何阶段都**不抛异常给调用方**。**不要建议**改成抛异常或加 strict 模式。
- **provider 失败时不调 `image_budget.log_charge()`**——是 T-1.5.6 编排者职责（消费未发生）；与 STAGE_1.5_TASKS.md T-1.5.5 的"调用顺序"段落一致。**不要建议**在失败路径上写"未发生 charge"占位行。
- **deterministic asset_id_stub**（无 timestamp）——`(target_ref, asset_role, variant_label, idx)` 决定，重跑同输入产出同 stub；与 ImageProvider Protocol docstring 的"deterministic generation + uniqueness is the caller's responsibility"一致。**不要建议**加 timestamp / random nonce / hash 字段（会破坏 T-1.5.7 的 idempotent import）。
- **`generate_visual` 内部对未知 provider 异常用 `except Exception as exc` 兜底**——是 ADR-014 partial_failure 鲁棒性要求；与 generate_node 在 ProviderError 上的窄异常不同（image provider 第三方 SDK 异常类型未稳定）。**不要建议**改成更窄的异常类型（除非能列出未来 OpenAIImageProvider 可能抛的所有具体异常）。
- **`character_features.py` 中 corvan / aelwin 的部分字段标 "(inferred)"**——是有意的：scene.json narration 没固定头发 / 眼睛颜色，依据 ADR-014 一致性策略允许"不矛盾原文的合理推测"；`(inferred)` 标签让作者后续可定向覆盖。**不要建议**删掉 (inferred) 标签 / 删掉这些字段。
- **mini probe gate（U-CL-3 硬闸门）的执行结果在完成报告里**（不在 /docs/CLEANUP.md，因 T-1.5.6 边界禁止 docs 写入）——这是 GPT-5.5 L2 critique §3.2 修补；mini probe 仅评估 prompt 一致性，不做入库（不依赖尚未实现的 T-1.5.7 import CLI）。**不要建议**让 mini probe 走 import CLI。

# 评审维度（10 类）

每条 finding 必须归到下列一类：

| 代号 | 类别 | 说明 |
|---|---|---|
| **ARCH** | 架构合规 | 是否违反 ADR / 模块边界 / 跨模块写入 |
| **SCHEMA** | Schema 来源 | JSON Schema 仍是单一真相之源；Pydantic / TS 不应手写 |
| **RUNTIME** | 运行时纯净 | `/engine` 仍 0 依赖 LLM；`/generator` 不被运行时 import（ADR-002 / 004） |
| **SAFETY** | 安全 | 输入校验、密钥泄露、注入向量、不安全反序列化、路径遍历、并发写撕裂 |
| **ERR** | 错误处理 | 边界处校验、内部不过度防御、异常 vs return-result 一致 |
| **TEST** | 测试 | 覆盖关键分支与失败路径；不冗余、不重言；mock 与真实分离；隔离 fixture 真生效 |
| **DEAD** | 冗余 | 死代码、未用 import、过度抽象、为未发生需求设计 |
| **DEPS** | 依赖 | 新增依赖必要、锁版本、许可证风险 |
| **STYLE** | 风格 | 注释只解释 WHY 不解释 WHAT；命名清晰；项目约定遵守 |
| **OPEN** | 开源就绪度 | 作者 hard-code、公开接口稳定性、文档可移植性 |

- 不要争 if-elif vs match-case 这类风格题
