# 本任务关键设计决策（不要当 bug 抓）

- **image_cost_log 与文本 cost_log 完全分离**——独立文件 `/generator/image_cost_log.jsonl`、独立 env 变量 `FORGEWRIGHT_IMAGE_COST_LOG`、独立模块。这是 STAGE_1.5_TASKS.md "锁定的架构决策"P2 决策（manual 行 cost=0 不污染文本预算算术；T-1.5.8 视觉 metrics 只扫一份文件）。**不要建议**合并两个 cost_log / 复用 `generator.cost_log` 模块 / 共享 env 变量。
- **manual 模式 `cost=0.0` 仍走 budget 接口 + 仍写日志**——是 ADR-014 约定（用于统计 manual 张数 + 接口统一）。`check()` 在 manual 模式下永远 return（无 raise）；`log_charge()` 不区分 manual / api，统一写一行（cost_usd=0.0）。**不要建议**让 manual 模式短路 budget / 跳过日志写入。
- **`check()` 与 `log_charge()` 分离**（不实现"check_and_charge"统一接口）——是 GPT-5.5 L2 critique 4.9 修补：`check()` 时调用方还没有 provider 创造的 deterministic stub，闭环不成立；分离后调用方需 try/finally 安排顺序（T-1.5.6 generate_visual 编排）。**不要建议**重新合并为 `check_and_charge`。
- **per-call 默认 $1.00 / daily 默认 $5.00** 是 ADR-014 数字（API 部分总盘子 $20–$40；单次硬卡 $1.00）；env 变量名 `FORGEWRIGHT_PER_CALL_IMAGE_BUDGET_USD` / `FORGEWRIGHT_DAILY_IMAGE_BUDGET_USD` 与文本侧 `PER_CALL_BUDGET_USD` / `DAILY_BUDGET_USD` 命名故意不同（前缀 FORGEWRIGHT_ + IMAGE_ 区隔，避免误覆盖）。**不要建议**改默认数字 / 改 env 变量名 / 让两套 env 变量共享前缀。
- **`check()` 不写日志 + 比较使用 `>`（严格大于）** —— 与文本侧 budget.py 一致。等于 ceiling 算通过，超过算 raise。**不要建议**改成 `>=`。
- **`log_charge()` 接受 `cost_usd` 由调用方传入**（不在 budget 模块内重新估算）—— estimate_cost 由 ImageProvider 提供，T-1.5.6 编排者在 check 用估算、log_charge 用 provider 实际返回值（API 模式）或 0（manual / 失败）。**不要建议**让 budget 模块直接调 provider 估算。
- **provider 失败时不调 `log_charge()`**（视为"消费未发生"）—— 是 T-1.5.6 编排者的职责约定，本任务文档已写明；本任务暴露的 API 不强制此行为。**不要建议**在 budget 模块内加 status flag / 强制写"未发生 charge"日志。
- **`size` 参数是 `tuple[int, int]` 而非分别两个参数** —— 与 ImageProvider Protocol 返回值一致；调用方天然成对获得 width/height。**不要建议**拆成两个独立参数。
- **导入风格**：`from generator import image_cost_log` 而非 `from generator.image_cost_log import append`（与 budget.py 风格一致，便于 monkeypatch `_now`）。**不要建议**改成 from-import。

# 评审维度（10 类）

每条 finding 必须归到下列一类：

| 代号 | 类别 | 说明 |
|---|---|---|
| **ARCH** | 架构合规 | 是否违反 ADR / 模块边界 / 跨模块写入 |
| **SCHEMA** | Schema 来源 | JSON Schema 仍是单一真相之源；Pydantic / TS 不应手写 |
| **RUNTIME** | 运行时纯净 | `/engine` 仍 0 依赖 LLM；`/generator` 不被运行时 import（ADR-002 / 004） |
| **SAFETY** | 安全 | 输入校验、密钥泄露、注入向量、不安全反序列化、路径遍历、并发写撕裂 |
| **ERR** | 错误处理 | 边界处校验、内部不过度防御、异常 vs return-result 一致 |
| **TEST** | 测试 | 覆盖关键分支与失败路径；不冗余、不重言；mock 与真实分离；隔离 fixture 真生效 |
| **DEAD** | 冗余 | 死代码、未用 import、过度抽象、为未发生需求设计 |
| **DEPS** | 依赖 | 新增依赖必要、锁版本、许可证风险 |
| **STYLE** | 风格 | 注释只解释 WHY 不解释 WHAT；命名清晰；项目约定遵守 |
| **OPEN** | 开源就绪度 | 作者 hard-code、公开接口稳定性、文档可移植性 |

**避免争论**：
- 不要争 if-elif vs match-case 这类风格题
- 不要建议"加一层抽象更优雅"——本项目反对预先抽象（CLAUDE.md "Don't add features...beyond what the task requires"）
- 不要建议拆文件除非真违反 SRP
