### 4.1 [ARCH] /generator/image_budget.py:91 — log_charge 缺 batch_name，后续成本无法按批次过滤
**问题**：T-1.5.8 明确要求 `visual_metrics.total_cost_usd` 从 `/generator/image_cost_log.jsonl` 按 `batch_name` 过滤求和。但当前 `log_charge()` 的签名和写出的 JSON 行都没有 `batch_name`；测试还在 `/generator/tests/test_image_budget.py:174` 用精确 dict 锁住了这个缺字段的行格式。等 T-1.5.8 开始时，`image_budget.py` / `image_cost_log.py` 已是只读依赖，metrics 要么无法只扫 image_cost_log，要么被迫跨边界补字段。

### 5.1 [TEST] /generator/tests/test_image_cost_log.py:51 — image_cost_log 缺并发 append framing 测试
**问题**：文本侧 `/generator/tests/test_budget.py` 已有 `test_concurrent_appends_yield_valid_jsonl`，用来锁定 append-only JSONL 在多线程写入时不撕裂。图像侧实现与文本侧同款，但测试只覆盖了顺序 append，没有把“每行仍是可解析 JSON”这个 safety 属性锁住。
**为什么 NICE**：当前实现使用 Python append 模式 + 单行写入，单进程顺序路径没有可见 bug；T-1.5.5 也禁止异步写入，所以这不是合入阻塞项。只是图像批量实验后续更可能并行化，补一条同款测试成本很低。
**建议修复**：仿照 `/generator/tests/test_budget.py` 的并发测试，启动 16 个线程、每个线程 append 5 行 image cost record，最后断言行数正确且每行 `json.loads()` 成功即可。
**模块边界状态**：✅ 在边界内（可修）
