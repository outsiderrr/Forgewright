## 3. 必修（🔴 CRITICAL）

### 3.1 [SAFETY] /generator/image_import.py:580 — `--asset-id` 可越界指向 `_pending` 外目录

**问题**：`run_import()` 直接把用户传入的 `asset_id` 拼到 `pending_root / asset_id`，没有校验 asset_id pattern，也没有 `resolve().relative_to(pending_root)` 约束。`--asset-id ../some_dir` 会让 CLI 读取 `_pending` 外的目录；如果目录里有 PNG 但 meta 缺失，还会被 `_move_to_rejected()` 移进 `_pending/_rejected/`。`--all-pending` 也会跟随 symlink 目录，因为 `Path.is_dir()` 默认跟随 symlink。

**为什么 CRITICAL**：这违反 T-1.5.7 的路径遍历高风险面和 CLAUDE.md 规则 2 的模块边界精神：import CLI 只能处理 `/content/visuals/_pending/<asset_id>/` 契约目录，不能让命令行参数把任意目录拖入入库/拒收流程。

**建议修复**：

```python
# 当前
if asset_id:
    stub_dirs = [pending_root / asset_id]
elif pending_root.exists():
    stub_dirs = sorted(
        d for d in pending_root.iterdir()
        if d.is_dir() and not d.name.startswith("_")
    )

# 改为
_ASSET_ID_RE = re.compile(r"^img_[a-z0-9_]{1,64}$")

def _stub_dir_for_asset_id(asset_id: str, pending_root: Path) -> Path:
    if not _ASSET_ID_RE.fullmatch(asset_id):
        raise ValueError(
            "asset_id must match ^img_[a-z0-9_]{1,64}$ and contain no path separators"
        )
    root = pending_root.resolve()
    stub_dir = (root / asset_id).resolve()
    try:
        stub_dir.relative_to(root)
    except ValueError as exc:
        raise ValueError(f"asset_id escapes pending_root: {asset_id!r}") from exc
    return stub_dir

if asset_id:
    stub_dirs = [_stub_dir_for_asset_id(asset_id, pending_root)]
elif pending_root.exists():
    root = pending_root.resolve()
    stub_dirs = []
    for d in sorted(pending_root.iterdir()):
        if d.name.startswith("_") or d.is_symlink() or not d.is_dir():
            continue
        try:
            d.resolve().relative_to(root)
        except ValueError:
            continue
        stub_dirs.append(d)
```

同时新增测试：`test_asset_id_path_traversal_rejected_without_touching_outside_dir`、`test_all_pending_skips_symlink_dirs`。

### 4.1 [SAFETY] /generator/image_import.py:114 — `target_ref` 只防逃逸，未防 reserved 目录和非本体目标

**问题**：`_target_dir_for()` 会对最终路径做 `relative_to(visuals_root)` 检查，能挡住 `../../` 逃到 `content/visuals/` 外；但它仍允许 `target_type=location,target_ref="_pending"` 或 `target_type=scene,target_ref="scene__reference"` 写入 `content/visuals/_pending/` / `_reference/` 这类工作流保留目录。并且 `_entity_exists()` 只在 `target_type=="character"` 时调用，scene/location 资产可指向本体里不存在的 target，manifest 会收下孤儿资产。

**为什么 IMPORTANT**：ADR-006 要求生成内容可追溯到本体；SCHEMA_v0.2.md §2.2 也把 `target_ref` 可解析列为语义约束。T-1.5.7 选择 scene/location 只写 manifest，不代表可以跳过 target 闭合性。

**建议修复**：

```python
# 当前
def _target_dir_for(target_type: str, target_ref: str, visuals_root: Path) -> Path:
    ...
    return visuals_root / sub

if target_type == "character":
    if not _entity_exists(ontology_path, target_ref):
        return manifest, reject(...), meta

# 改为
_RESERVED_VISUAL_DIRS = {"_pending", "_rejected", "_reference"}

def _safe_visual_subdir(sub: str) -> str:
    parts = Path(sub).parts
    if any(part in ("", ".", "..") for part in parts):
        raise ValueError(f"unsafe target_ref path segment: {sub!r}")
    if parts[0] in _RESERVED_VISUAL_DIRS:
        raise ValueError(f"target_ref maps to reserved visuals dir: {parts[0]!r}")
    return sub

def _entity_exists(ontology_path: Path, target_ref: str, target_type: str) -> bool:
    ...
    return entity.get("id") == target_ref and entity.get("type") == target_type

target_dir = visuals_root / _safe_visual_subdir(sub)

if not _entity_exists(ontology_path, target_ref, target_type):
    return manifest, reject(
        f"ontology has no {target_type} entity with id={target_ref!r}"
    ), meta
```

测试补上：unknown scene/location target 拒收、reserved target_ref 拒收、合法 `scene_waystation_of_iron_oath` 通过且不写 scene.visual_assets。

### 4.2 [ERR] /generator/manifest.py:57 — 损坏的 `assets: null` / `assets: []` 会被当成空 manifest

**问题**：`raw_assets = raw.get("assets") or {}` 会把现有 manifest 里的 `assets: null`、`assets: []`、`assets: ""` 或缺失 `assets` 都吞成空 dict。下一次成功 import 后 `save_manifest()` 会把这个“空索引 + 新资产”写回，等于静默丢掉原 manifest 形态错误。

**为什么 IMPORTANT**：manifest 是 T-1.5.7 的 append-only 单文件索引；既然 skeleton 已经 commit，文件存在但形态错误时应硬失败，而不是走“首次运行 empty”路径。

**建议修复**：

```python
# 当前
raw_assets = raw.get("assets") or {}
if not isinstance(raw_assets, dict):
    raise ValueError(...)

# 改为
if "assets" not in raw:
    raise ValueError("manifest missing required 'assets' object")
raw_assets = raw["assets"]
if not isinstance(raw_assets, dict):
    raise ValueError(
        f"manifest 'assets' must be an object, got {type(raw_assets).__name__}"
    )
```

新增测试覆盖 missing/null/list 三种坏形态均 raise。

**模块边界状态**：✅ 在边界内（可修）

### 4.3 [SAFETY] /generator/image_import.py:253 — `waystation.json` replace 后没有 fsync 父目录

**问题**：`_ontology_append_visual_asset()` 写 temp file 并 fsync 文件本身，然后 `os.replace()`；但没有像 `save_manifest()` 那样 fsync 父目录。崩溃时通常不会留下半个 JSON，但 rename 的目录项耐久性弱于 manifest 写入路径，两个关键状态文件的 crash 语义不一致。

**为什么 IMPORTANT**：ADR-006 把本体作为真相之源；T-1.5.7 明确要求本体写入走 temp + replace + fsync 路径。当前实现只完成了文件 fsync，没有完成目录 fsync。

**建议修复**：

```python
# 当前
os.replace(tmp_path, ontology_path)

# 改为：复用 manifest.py 的目录 fsync 逻辑
os.replace(tmp_path, ontology_path)
try:
    dir_fd = os.open(str(ontology_path.parent), os.O_RDONLY)
except OSError:
    return
try:
    os.fsync(dir_fd)
except OSError:
    pass
finally:
    os.close(dir_fd)
```

可抽一个本文件内小 helper，或直接按 `manifest.py` 的写法复制，别跨模块重构。

**模块边界状态**：✅ 在边界内（可修）

### 4.4 [ERR] /generator/image_import.py:78 — meta 契约未校验 `asset_id_stub` / `created_at`，还会补默认 `created_at`

**问题**：ManualImportProvider 写出的 `meta.json` 明确包含 `asset_id_stub` 和 `created_at`，但 `_REQUIRED_META_KEYS` 不要求它们；导入时也不检查 `meta["asset_id_stub"] == stub_dir.name`。更关键的是，`ImageAsset.created_at` 缺失时当前代码用 `_now_iso()` 补默认值，掩盖了上游 meta 契约破损。

**建议修复**：

```python
# 当前
_REQUIRED_META_KEYS = (

    "source_mode", "variant_label", "prompt_hash",
)
...
created_at=meta.get("created_at") or _now_iso(),

# 改为
_REQUIRED_META_KEYS = (
    "asset_id_stub", "target_ref", "target_type", "asset_role", "asset_kind",
    "source_mode", "variant_label", "prompt_hash", "created_at",
)
...
if meta["asset_id_stub"] != stub:
    return manifest, reject(
        f"meta asset_id_stub {meta['asset_id_stub']!r} != directory name {stub!r}"
    ), meta
...
created_at=meta["created_at"],
```

新增测试：缺 `created_at` 拒收、`asset_id_stub` 与目录名不一致拒收。
