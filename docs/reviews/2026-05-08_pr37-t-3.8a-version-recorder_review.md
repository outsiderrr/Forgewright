### 4.1 [SAFETY/OPEN] generator/version_recorder.py:112 — git 读取 helper 既过宽，也没有锚定 scene 所在仓库

**问题**：`_run_git(*args)` 是一个通用 git subprocess wrapper，实际在 `subprocess.run(["git", *args])` 上直接透传参数，且没有设置 `cwd` / `git -C`。这有两层风险：第一，按本轮 L2 检查口径，模块代码里已经 grep 命中 `subprocess.run(["git", ...])`；第二，CLI 如果从仓库外目录调用绝对路径 scene，会记录调用进程当前目录的 git HEAD，可能是 `None` 或另一个仓库的 commit。

**为什么是 IMPORTANT**：version sidecar 的核心价值就是 audit trail；记录错 repo/错 commit 会让 T-3.10 “每个入库 scene 有 version sidecar” 变成形式通过。CLAUDE.md 的安全约束禁止自动 git 操作；本任务 prompt 又要求读 HEAD，所以这里至少需要把 git 访问收窄为固定、只读、按 scene path 锚定的实现。

**修复建议**：

```python
# 当前
def _run_git(*args: str) -> str | None:
    out = subprocess.run(["git", *args], ...).stdout.strip()

# 建议：不要保留通用 git wrapper；只暴露固定只读元数据读取
def _run_git_readonly(repo_hint: Path, args: tuple[str, ...]) -> str | None:
    out = subprocess.run(
        ["git", "-C", str(repo_hint), *args],
        capture_output=True,
        check=True,
        text=True,
    ).stdout.strip()
    return out or None

def _git_head_commit(scene_path: Path) -> str | None:
    return _run_git_readonly(scene_path.parent, ("rev-parse", "HEAD"))
```

同时补一个 CLI 测试：从非 repo cwd 调用 `record_version(abs_scene_path, ...)`，断言记录的是 scene 所在仓库的 HEAD，而不是调用进程 cwd。

### 4.2 [ERR] generator/version_recorder.py:277 — sidecar bump 是无锁 read-modify-write，会丢版本

**问题**：当 sidecar 已存在时，`record_version` 先 `_load_sidecar()`，在内存里 `old.version + 1`，最后 `_save_sidecar()`。`os.replace` 只保证单次写入不会半写，不保证整个 read-modify-write 序列互斥；两个并发调用同一 scene 时可能都读到 v1，最后都写 v2，丢掉一次 bump 和一次 `changed_fields`。

**为什么是 IMPORTANT**：阶段 3 的 batch scheduler 是并发模型；虽然正常 DAG 不应重复同一 scene，但手动 CLI、重跑、regenerate、playtest_fix 都可能与调度器或彼此重叠。L2 关注点明确要求 API 对 T-3.5 调用友好、线程安全、失败模式清晰。

**修复建议**：

```python
# 当前
if sidecar.exists():
    old = _load_sidecar(sidecar)
    meta = VersionMetadata(version=old.version + 1, ...)
_save_sidecar(sidecar, meta)

# 建议：围住 load + bump + save 整个临界区
with _sidecar_lock(sidecar):
    if sidecar.exists():
        old = _load_sidecar(sidecar)
        meta = VersionMetadata(version=old.version + 1, ...)
    else:
        ...
    _save_sidecar(sidecar, meta)
```

可用 sibling lock file，例如 `scene.version.json.lock` + `fcntl.flock`（Windows 兼容可沿项目现有策略决定）。测试用 `ThreadPoolExecutor` 对同一个 scene 并发调用 5 次，最终应得到 `version == 5` 且 `previous_versions == [1,2,3,4]`。

### 4.3 [DEAD] generator/version_recorder.py:192 — 原子写实现从 manifest copy-paste，未抽共享 helper

**问题**：`_save_sidecar()` 复制了 `generator.manifest.save_manifest()` 的 tempfile + fsync + `os.replace` + parent fsync 套路。PR 描述说“follows generator.manifest pattern”，但实现是 copy-paste，不是共享调用；后续 `dep_index_writer`、chapter helper、version sidecar 都会继续写 sidecar，重复的 crash-safe 写入代码会变成维护债。

**为什么是 IMPORTANT**：阶段 2 已经用共享 sanitizer / retry policy 的方式收敛重复逻辑；本轮 L2 也明确要求核对“import 调用 manifest helper 还是 copy-paste，实现后者需要抽公共”。这里不是审美重构，而是生产期文件写入可靠性的共同基础。

**修复建议**：

```python
# 建议新增 generator/_atomic_write.py
def write_text_atomic(path: Path, text: str) -> None:
    path.parent.mkdir(parents=True, exist_ok=True)
    fd, tmp_path = tempfile.mkstemp(
        prefix=path.name + ".", suffix=".tmp", dir=str(path.parent)
    )
    ...
    os.replace(tmp_path, path)
    _fsync_parent(path.parent)

def write_json_atomic(path: Path, payload: object) -> None:
    write_text_atomic(
        path,
        json.dumps(payload, ensure_ascii=False, indent=2) + "\n",
    )
```

然后让 `version_recorder` 调 `write_json_atomic()`；如 C 阶段允许顺手收敛，`manifest.save_manifest()` 也改用同一个 helper，并保留现有 manifest 测试。
