## 3. 必修（🔴 CRITICAL）

### 3.1 [ARCH] validator/dialogue_validator.py:18 — 现有机械校验仍按 5 命名空间运行，`knowledge.*` 与 monotonic 未实际生效

**问题**：PR 新增了 `validator/state_path_validator.py`，但现有被生产链路调用的 `validate_graph_mechanical()` 仍硬编码 `("world", "faction", "relationship", "flag", "player")`。`generator/generate_scene.py` 的成功路径继续调用这个旧入口，因此任何 `knowledge.*` effect / condition 会被 `PATH_NS_INVALID` 拒收，同时 `flag.player_*` / `knowledge.*` 上的 `dec` / `remove` 也不会被旧入口按 ADR-034 D11 拦住。

**为什么是 CRITICAL**：ADR-016 v0.4 明确要求 validator 支持第 6 命名空间 + monotonic 规则；ADR-034 D11 要求 schema 层强制 LLM 生成内容不得在 `flag.player_*` / `knowledge.*` 上 `dec/remove`。这是本 PR 的关键产出之一，不是可推迟 follow-up。

**修复建议**：
```python
# 当前（问题代码片段）
_PATH_NAMESPACES = ("world", "faction", "relationship", "flag", "player")

def _check_effect(eff, where, slugs, issues):
    ...
    if isinstance(p, str):
        _check_path_namespace(p, f"{where}.path", slugs, issues)

# 建议
from validator.state_path_validator import validate_effect_namespace, validate_monotonic

def _check_effect(eff, where, slugs, issues, *, generation_source="llm"):
    ...
    for msg in validate_effect_namespace(eff):
        issues.append(ValidationIssue("error", "PATH_NS_INVALID", f"{where}.path", msg))
    for msg in validate_monotonic(eff, generation_source=generation_source):
        issues.append(ValidationIssue("error", "MONOTONIC_VIOLATION", where, msg))
```

同时给 `validate_graph_mechanical()` 补一条集成测试：含 `{"op": "set", "path": "knowledge.foo"}` 应通过；含 `{"op": "remove", "path": "knowledge.foo"}` 在 LLM source 下应失败。

## 4. 应修（🟡 IMPORTANT）

### 4.1 [SCHEMA] generator/models/_generated/dialogue_graph.py:22 — schema 改了，但自动生成 Pydantic 模型仍是旧结构

**问题**：`schema/dialogue_graph.schema.json` 新增了 `scene_metaparams` / `scene_reveals` / `scene_seeds` / `player_known_info`，`schema/node.schema.json` 新增了 `foreground_goal` / `background_seeds`，但 `/generator/models/_generated/` 没有重新生成。现有 `DialogueGraph` 和 `Node` 都是 `extra="forbid"`，会拒绝这些新字段。

**为什么是 IMPORTANT**：`generator/CLAUDE.md` 明确 `_generated` 由 JSON Schema 自动生成；现在 JSON Schema 与派生产物不一致，会让使用 `generator.models.DialogueGraph.model_validate()` 的测试或后续工具链在新字段场景下失败。

**修复建议**：
```bash
# 当前缺口
schema/*.schema.json 已更新
generator/models/_generated/*.py 未更新

# 建议
bash generator/scripts/regenerate_models.sh
pytest generator/tests/test_models_roundtrip.py -q
```

并补一个模型消费测试，断言含 `scene_reveals` 与 `foreground_goal` 的 graph 能通过 `DialogueGraph.model_validate()`。

### 4.2 [SCHEMA] schema/dialogue_graph.schema.json:62 — `reveal_id` 允许大写/连字符，会生成非法 `knowledge.<reveal_id>.stage_n`

**问题**：ADR-034 D5 规定 trigger node 触发 `knowledge.<reveal_id>.stage_<n>`。但当前 `reveal_id` pattern 是 `^[a-zA-Z0-9_-]+$`，PR 自己的测试和 dry-run 使用 `R1_wright_double_life`。这类 ID 一旦拼进 `knowledge.R1_wright_double_life.stage_2`，会违反 ADR-016 v0.4 的 `knowledge.*` pattern（只允许小写 `[a-z0-9_]` 段）。

**为什么是 IMPORTANT**：这是 schema 层自相矛盾：同一 reveal 在 `scene_reveals` 合法，但按 D5 派生出的 state path 不合法。后续 validator 或 dep index 一旦正确支持 `knowledge.*`，这些样本会开始失败。

**修复建议**：
```json
// 当前
"reveal_id": {
  "type": "string",
  "pattern": "^[a-zA-Z0-9_-]+$"
}

// 建议：若 reveal_id 直接进入 knowledge path
"reveal_id": {
  "type": "string",
  "pattern": "^[a-z0-9_]+$"
}
```

同样需要收紧 `node.foreground_goal` 中 reveal 部分，或引入单独的 `knowledge_path_slug`，不要把 display-ish ID 直接拼成 state path。

### 4.3 [SCHEMA] generator/dep_index_writer.py:76 — dependency sidecar 仍拒绝 `knowledge.*`

**问题**：`schema/content_dependency_index.schema.json` 的 `state_paths_read` / `state_paths_written` pattern 仍写 ADR-016 五命名空间，`generator/dep_index_writer.py` 的 `_STATE_PATH_RE` 也同步只允许五命名空间。阶段 3 post-success hook 会写 sidecar；一旦 T-3Y 场景把 `knowledge.*` 放入 effect 或 trace，sidecar 会在写入阶段失败。

**为什么是 IMPORTANT**：ADR-016 v0.4 的工程影响写明“schema 文件如需 pattern 校验，加入第 6 命名空间”。content dependency index 正是 state path pattern schema；不更新会让生成产物通过前面校验后在落盘 sidecar 时炸掉。

**修复建议**：
```python
# 当前
_STATE_PATH_RE = re.compile(
    r"^(world\\.|faction\\.|relationship\\.|flag\\.|player\\.)..."
)

# 建议
_STATE_PATH_RE = re.compile(
    r"^(world\\.|faction\\.|relationship\\.|flag\\.|player\\.|knowledge\\.)..."
)
```

同步修改 `schema/content_dependency_index.schema.json` 两处 pattern，并补 `knowledge.foo` 的 read/write 正样本测试。
