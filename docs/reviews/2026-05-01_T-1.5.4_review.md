## 3. 必修（🔴 CRITICAL）

### 3.1 [SAFETY] /validator/image_validator.py:132 — 超大畸形图片会绕过返回契约并直接抛异常

**问题**：`validate_image_asset()` 在拿到 `img.size` 并判定 `RESOLUTION_TOO_HIGH` 之前先进入 `Image.open()` / `img.load()` 路径。对一个 magic bytes 合法但 IHDR 尺寸极大的 PNG，Pillow 会在 `Image.open()` 阶段抛 `PIL.Image.DecompressionBombError`；当前 `except (UnidentifiedImageError, OSError)` 接不住，调用方拿不到 `ImageValidationError` 列表，后续 T-1.5.7 import CLI 会被单个文件中断。  
**为什么 CRITICAL**：T-1.5.4 的存在理由就是 R8 的“机械可检测维度必须由机械层硬卡”；安全维度也明确要求看 `Path.open` / 图像解析是否会爆炸。机械预检器面对不可信下载图时抛未捕获异常，违反“边界处校验并返回结构化错误”的任务契约。  
**建议修复**：

```python
# 当前
try:
    with Image.open(image_path) as img:
        img.load()
        width, height = img.size
        mode = img.mode
        exif = img.getexif()
except (UnidentifiedImageError, OSError) as exc:
    ...

# 改为
try:
    with Image.open(image_path) as img:
        width, height = img.size
        mode = img.mode
        exif = img.getexif()

        # 先用 header 尺寸做硬卡；超上限时不要 load 像素，避免解压炸弹/内存浪费。
        should_decode = width <= cfg.max_width and height <= cfg.max_height
        if should_decode:
            img.load()
except Image.DecompressionBombError as exc:
    errors.append(
        ImageValidationError(
            code="RESOLUTION_TOO_HIGH",
            message=f"Pillow refused image as decompression bomb: {exc}",
            severity="error",
        )
    )
    return errors
except (UnidentifiedImageError, OSError) as exc:
    ...
```

同时加测试：构造一个只含 PNG header / IHDR 的超大尺寸小文件，断言 `validate_image_asset()` 不抛异常，并返回 `RESOLUTION_TOO_HIGH`。

**模块边界状态**：✅ 在边界内（可修）

## 4. 应修（🟡 IMPORTANT）

### 4.1 [SCHEMA] /validator/image_validator.py:115 — 只校验 magic bytes，漏掉扩展名与 ImageAsset.file_path 契约

**问题**：任务表写的是 `FORMAT_NOT_ALLOWED = 文件扩展名 / magic bytes 不在 allowed_formats`，SCHEMA_v0.2 也要求 `file_path` 只能是 `content/visuals/... .png|.webp`。当前代码只看 magic bytes；一个 PNG 内容但文件名是 `wrong_extension.jpg` 的文件会返回空列表。这会让 image_validator 通过一个后续 ImageAsset `file_path` schema 会拒收的路径形态。  
**为什么 IMPORTANT**：这不是要信任扩展名替代 magic bytes，而是“扩展名和 magic bytes 都必须落在允许集合”。否则 T-1.5.4 机械预检与 SCHEMA_v0.2 §2 的 `format` / `file_path` 机械字段不一致，风险会推迟到入库阶段才爆。  
**建议修复**：

```python
# 当前
detected = _detect_format_by_magic(image_path)
if detected not in cfg.allowed_formats:
    errors.append(...)

# 改为
detected = _detect_format_by_magic(image_path)
extension = image_path.suffix.lower().lstrip(".")
if detected not in cfg.allowed_formats or extension not in cfg.allowed_formats:
    errors.append(
        ImageValidationError(
            code="FORMAT_NOT_ALLOWED",
            message=(
                f"detected format {detected!r} and extension {extension!r} "
                f"must both be in allowed formats {cfg.allowed_formats}"
            ),
            severity="error",
        )
    )
```

并新增测试：用 Pillow 保存 PNG 内容到 `wrong_extension.jpg`，断言触发 `FORMAT_NOT_ALLOWED`；保留现有 `jpeg_disguised.png` 测试，确保 magic bytes 防伪造仍在。

**模块边界状态**：✅ 在边界内（可修）

## 5. 可选改进（🟢 NICE）

### 5.1 [TEST] /validator/tests/test_image_validator.py:38 — 默认允许的 WebP 路径没有正向覆盖

**问题**：`ImageValidationConfig.allowed_formats` 默认包含 `webp`，SCHEMA_v0.2 也把 `format` 枚举定为 `png` / `webp`，但测试只覆盖 PNG 正向和 JPEG 伪装失败，没有证明默认配置下真实 WebP 能通过。  
**为什么 NICE**：当前代码的 WebP magic bytes 判断看起来合理，全量测试也通过；这是防未来 Pillow 编译选项或 magic 判断回归的小补强，不阻塞本轮修复。  
**建议修复**：在 `conftest.py` 现场生成一个 `perfect_background.webp`（如当前 Pillow 支持 WebP），新增 `test_perfect_webp_background_passes_default`；若本地 Pillow 不支持 WebP，可用 `pytest.skip` 明示原因。

**模块边界状态**：✅ 在边界内（可修）
