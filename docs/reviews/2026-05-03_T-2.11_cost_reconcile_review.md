### 4.1 [ERR] generator/generate_node.py:160 — `request_not_sent` 没有接入 `generate_node` 生产路径

**问题**：`generate_node` 在 `check_and_charge()` 写入 record 后，只要 provider 抛 `ProviderError` 就一律走 `request_sent_failure`，保留 estimated charge。`budget.refund_estimated(..., reason="request_not_sent")` 只在预算层 API 和直接测试里被调用，`test_t211_request_not_sent_refund_via_direct_api` 也明确说明不是 `generate_node` 端到端路径（`generator/tests/test_generate_node.py:367`）。

**为什么是 IMPORTANT**：T-2.11 §8 要求三态 refund 串到 `generate_node` hook，其中 `request_not_sent` 应 refund 全额 estimated_cost；当前实现让“请求确实未送出”的生产场景仍无法自动退款。R2.1 可以继续负责 provider 差异化异常体系，但本 PR 不应把 direct API 覆盖称为三态端到端接入。

**修复建议**：
```python
# 当前（所有 ProviderError 都保留 estimated charge）
except ProviderError as exc:
    _log_refund_deferred(record_id, str(exc))
    attempts.append(AttemptRecord(..., cost_usd=estimated_cost))
    total_cost += estimated_cost
    return GenerationResult(success=False, failure_reason="provider_error", ...)

# 建议（只加 provider-neutral hook；不要在本 PR 做 Gemini 专属异常分类）
except ProviderError as exc:
    if _is_request_not_sent(exc):
        budget.refund_estimated(record_id, reason="request_not_sent")
        attempts.append(AttemptRecord(..., cost_usd=0.0))
        return GenerationResult(success=False, failure_reason="provider_error", ...)

    _log_refund_deferred(record_id, str(exc))
    attempts.append(AttemptRecord(..., cost_usd=estimated_cost))
    total_cost += estimated_cost
    return GenerationResult(success=False, failure_reason="provider_error", ...)
```

如果本轮坚持“不存在任何可判定的 request_not_sent 信号”，则应把 PR body 和测试说明改成“`request_not_sent` 仅预算 API 已有，生产路由留 R2.1”，不要把它算作 T-2.11 三态 hook 已完成。

### 4.2 [ERR] generator/llm_provider.py:21 — `actual_cost_usd` / provider usage 链路未落地

**问题**：`StructuredResponse` 仍只有 `input_tokens` / `output_tokens`，没有 `actual_cost_usd`；`generator/providers/gemini.py:117` 也只读取 `usage_metadata` 的两项 token count。实际 reconcile 成本是在 `generate_node.py:182` 用 `provider.estimate_cost(response.input_tokens, response.output_tokens)` 重新推算，而不是由 provider 返回的 response 字段承载。

**为什么是 IMPORTANT**：T-2.11 §8.3 明示要在 `GeminiProvider` 加 `actual_cost_usd`。当前实现能做基础成本算术，所以不算阻塞级别；但它让 “Gemini SDK usage_metadata -> StructuredResponse -> reconcile” 的链路少了一环，后续 cached / billable / reasoning 子字段也只能再改接口。

**修复建议**：
```python
# 当前
@dataclass
class StructuredResponse:
    content: dict
    raw_text: str
    input_tokens: int
    output_tokens: int
    model_id: str
    finish_reason: str

# 建议的最小层，不要求本 PR 做完整 cached/billable/reasoning 子字段
@dataclass
class StructuredResponse:
    content: dict
    raw_text: str
    input_tokens: int
    output_tokens: int
    model_id: str
    finish_reason: str
    actual_cost_usd: float | None = None
```

然后 `GeminiProvider` 用自身 `estimate_cost(input_tokens, output_tokens)` 填 `actual_cost_usd`，`generate_node` 优先使用 `response.actual_cost_usd`，缺省时再 fallback 到 `provider.estimate_cost(...)`。如果 `llm_provider.py` 仍被视为本任务禁区，则应把 T-2.11 完成状态降级为“基础 reconcile 已完成；actual_cost_usd 字段留 R2.1”，避免和 §8.3 字面冲突。

### 4.3 [SAFETY] generator/cost_log.py:27 — read-modify-write 只在单进程内安全

**问题**：`_LOG_LOCK = threading.Lock()` 只能保护同一 Python 进程；`_rewrite_one()` 还使用固定临时文件名 `cost_log.jsonl.tmp`。两个进程同时 reconcile/refund 时，可能都读取旧快照，再争用同一个 tmp 路径并 `replace()`，导致某一方更新丢失或 tmp 被覆盖。

**为什么是 IMPORTANT**：ADR-012 的预算硬卡依赖 `cost_log` 的 running total。Forgewright 已有并行会话工作流，后续 batch/CLI 也可能同时写成本日志；一旦跨进程 RMW 丢更新，R7 的“反向校准”会重新变成不可信账本。

**修复建议**：
```python
# 当前
_LOG_LOCK = threading.Lock()
...
tmp = path.with_suffix(path.suffix + ".tmp")
with open(tmp, "w", encoding="utf-8") as f:
    ...
tmp.replace(path)

# 建议
with _LOG_LOCK, _file_lock(path.with_suffix(".lock")):
    fd, tmp_name = tempfile.mkstemp(
        dir=path.parent,
        prefix=path.name + ".",
        suffix=".tmp",
    )
    try:
        with os.fdopen(fd, "w", encoding="utf-8") as f:
            ...
        os.replace(tmp_name, path)
    finally:
        ...
```

如果作者明确接受“成本日志只允许单进程 dev runner 写入”，也至少应在 PR body / docstring 写清这是限制，不要把 module-level lock + atomic rename 表述成一般并发安全。
