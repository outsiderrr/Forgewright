## 3. 必修（🔴 CRITICAL）

### 3.1 [ERR] tools/dep_propagate.py:139 — `*.namespace` 输入不会命中任何子路径

**问题**：CLI help 和模块说明都把 `faction.iron_oath.*` 当作“改了某个 namespace 子树”的常见输入，但 `_state_path_intersect()` 只做 `ch + "."` 前缀匹配。传入 `changed_state_paths=["faction.iron_oath.*"]` 时，sidecar 里的 `faction.iron_oath.reputation` 不会命中，报告会错误显示 0 个 stale scene。

**为什么是 CRITICAL**：ADR-023/F5 和 `docs/STAGE_3_TASKS.md` §3.2 要求 content dependency trace 用 conservative over-approx，目标是“宁可误报 stale 也不漏依赖”。这里是核心反向 propagate 路径的静默 false negative，作者会以为无需重审。

**修复建议**：
```python
# 当前（问题代码片段）
if ref == ch or ref.startswith(ch + ".") or ch.startswith(ref + "."):
    hits.append(ref)

# 建议
def _normalize_changed_path(path: str) -> str:
    if path.endswith(".*"):
        return path[:-2]
    return path

for raw_ch in changed_set:
    ch = _normalize_changed_path(raw_ch)
    if ref == ch or ref.startswith(ch + ".") or ch.startswith(ref + "."):
        hits.append(ref)
        break
```

同时加测试覆盖：`changed_state_paths=["faction.iron_oath.*"]` 应命中 sidecar `state_paths_read=["faction.iron_oath.reputation"]`。

## 4. 应修（🟡 IMPORTANT）

### 4.1 [ERR] tools/dep_propagate.py:375 — 删除整个 ontology JSON 文件时 `--since` 会漏掉所有旧实体

**问题**：`diff_ontology()` 只遍历当前工作树仍存在的 `ontology_path.glob("*.json")`。如果作者删除或重命名了 `state/ontology/world.json` 这类文件，`files` 为空，旧 commit 中的实体完全不会进入 `changed_ontology_ids`，hook/CLI 会报告无 stale scene。

**为什么是 IMPORTANT**：T-3.7 DP-2 的语义是“自 since_commit 以来 ontology entities 变更”，删除文件是最强的一类本体变更。当前 pre-commit hook 正是用 `--since HEAD` 自动跑，漏报会让作者错过必须重审的场景。

**修复建议**：
```python
# 当前（问题代码片段）
files = _ontology_files_to_diff(ontology_path)
for f in files:
    old_text = _git_show(repo_root, since_commit, f)
    ...

# 建议
# 目录模式下取 union：当前工作树 *.json + since_commit 下同目录 *.json。
# 对只存在于 old 的文件，解析 old_payload，将其中所有 entity id 标 changed；
# 如有 state_path_slug，也补 relationship.<slug>。
```

建议加一个 tmp git repo 测试：commit 里有 `state/ontology/world.json` + `char_vellin`，工作树删除该文件后，`diff_ontology(ontology_dir, rev)` 应返回 `char_vellin`。

### 4.2 [SCHEMA] tools/dep_propagate.py:207 — schema-invalid sidecar 会让整次扫描崩掉

**问题**：`_load_sidecar()` 只处理文件读写和 JSON 解析错误；读到 dict 后直接 `set(sidecar.get("ontology_ids_read", []))` / `list(sidecar.get("state_paths_read", []))`。如果某个 sidecar 违反 T-3.2 schema（例如 optional missing-only 字段被写成 `null`，或必填数组字段是 `null`），会抛 `TypeError` 并中断整个 content_root 扫描，后续正常 sidecar 也拿不到 stale 结果。

**为什么是 IMPORTANT**：`schema/content_dependency_index.schema.json` 已明确字段约束和 missing-only 语义，并把部分跨文件/语义兜底留给 dep_propagate。生产期工具不能因为一个坏 sidecar 让整批 stale report 失效；应当至少 warn + skip，保持其余场景可审。

**修复建议**：
```python
# 当前（问题代码片段）
ontology_hits = changed_ontology_set & set(sidecar.get("ontology_ids_read", []))
sidecar_state_paths = list(sidecar.get("state_paths_read", [])) + list(
    sidecar.get("state_paths_written", [])
)

# 建议
def _list_field(sidecar: dict, deps_path: Path, key: str) -> list[str] | None:
    value = sidecar.get(key, [])
    if not isinstance(value, list):
        print(f"[dep_propagate] WARN invalid sidecar {deps_path}: {key} must be a list", file=sys.stderr)
        return None
    return [str(item) for item in value]

# 任一必需数组字段 invalid 时 skip 当前 sidecar，不中断全局扫描。
```

测试建议：一个 `ontology_ids_read: null` 的坏 sidecar 排在正常 sidecar 前面时，函数应 warn 并仍返回后续正常 scene。
