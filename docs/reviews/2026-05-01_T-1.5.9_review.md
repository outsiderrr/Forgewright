## 3. 必修（🔴 CRITICAL）

### 3.1 [ARCH] generator/visual_parity_smoke.py:157 — parity smoke 绕过 image_budget，且成本日志不计入今日花费

**问题**：`run_parity_smoke()` 在有 API provider 时直接进入 `_run_api_half()` 付费生成，没有先调用 `image_budget.check()`。更糟的是 `_append_cost_log()` 在 `generator/visual_parity_smoke.py:332-337` 写的是 `total_cost_usd`，而现有 `image_budget.today_total_usd()` 只读取每行的 `cost_usd`；也就是说 smoke 花掉的钱不会进入后续 daily budget 汇总。

**为什么 CRITICAL**：`/generator/CLAUDE.md` 阶段 1.5 硬规则要求任何 image API 调用前必须经过 `image_budget.check()`；ADR-012 / ADR-014 的核心就是防止 API 成本失控。当前实现既没有调用前硬卡，也让已发生成本对后续预算不可见。

**建议修复**：

```python
# 当前
api_image_path, api_status, api_cost = _run_api_half(
    api, entry=entry, api_dir=api_dir
)
api_total_cost += api_cost

record = {
    "timestamp": timestamp,
    "source": "visual_parity_smoke",
    "run_dir": str(run_dir),
    "n_api_calls": sum(1 for p in pair_results if p.api_status == "ok"),
    "total_cost_usd": round(api_total_cost, 6),
}

# 改为（示意；保持“一行汇总日志”的任务约束）
from generator import image_budget

_SMOKE_SIZE = (1024, 1024)

if api is not None:
    estimated_total = sum(
        api.estimate_cost(n=1, size=_SMOKE_SIZE) for _ in prompts
    )
    image_budget.check(estimated_cost_usd=estimated_total, mode="api")

# ...之后再逐条 _run_api_half(...)

record = {
    "timestamp": timestamp,
    "source": "visual_parity_smoke",
    "mode": "api",
    "provider_id": "openai_image",
    "run_dir": str(run_dir),
    "n_api_calls": sum(1 for p in pair_results if p.api_status == "ok"),
    "n": sum(1 for p in pair_results if p.api_status == "ok"),
    "cost_usd": round(api_total_cost, 6),
    "total_cost_usd": round(api_total_cost, 6),
}
```

同时补测试：mock `image_budget.check()` 断言有 API provider 时会先调用；构造预算超额时断言不会触发 fake API；成功路径断言 JSONL 含 `cost_usd`，且 `image_budget.today_total_usd()` 能读到这笔钱。

**模块边界状态**：✅ 在边界内（可修）

## 4. 应修（🟡 IMPORTANT）

### 4.1 [ERR] generator/providers/openai_image.py:91 — SDK client 构造异常会绕过 ImageProviderError

**问题**：`_client` 属性在 `OpenAI(...)` 构造失败时不会包装异常；`generate()` 的 `except OpenAIError` 也接不到这类错误。实测本机 `openai==2.33.0` 在存在 `all_proxy=socks5://...` 且未安装 `socksio` 时，`OpenAI(api_key='sk-test')` 会直接抛 `ImportError`，这会违反 provider 统一抛 `ImageProviderError` 的契约。

**为什么 IMPORTANT**：调用方和 parity smoke 都按 `ImageProviderError` 做边界处理。这里漏掉的是常见环境/SDK 初始化失败，不是模型内容失败；它会让 smoke 从“partial fail 写报告”退化成未包装崩溃。

**建议修复**：

```python
# 当前
if self._client_cache is None:
    self._client_cache = OpenAI(
        api_key=self._api_key,
        timeout=_HTTP_TIMEOUT_SEC,
    )
return self._client_cache

# 改为
if self._client_cache is None:
    try:
        self._client_cache = OpenAI(
            api_key=self._api_key,
            timeout=_HTTP_TIMEOUT_SEC,
        )
    except Exception as exc:
        raise ImageProviderError(f"OpenAI client setup failed: {exc}") from exc
return self._client_cache
```

补一个 unit test：monkeypatch `generator.providers.openai_image.OpenAI` 抛 `RuntimeError` 或 `ImportError`，访问 `provider.generate(...)` 时断言得到 `ImageProviderError` 且 `__cause__` 保留。

**模块边界状态**：✅ 在边界内（可修）

### 4.2 [SAFETY] generator/visual_parity_smoke.py:256 — CLI 只校验 prompt_id，其他字段可带着坏类型/坏枚举进入生成

**问题**：`validate_prompts()` 只检查必填字段和 `prompt_id` 正则，没有验证字段类型、`asset_kind` / `target_type` / `asset_role` 枚举、`asset_id_stub` 的 `img_...` 形态，也没有保证 `prompt` 是非空字符串。比如 `prompt_id=123` 会在 `fullmatch()` 处抛未捕获 `TypeError`；`asset_id_stub="../escape"` 依赖 ManualImportProvider 后置报错，CLI 不能给出干净的 `ValueError`。

**为什么 IMPORTANT**：任务说明把 CLI 文件读取 + 校验放在 `visual_parity_smoke.py`，`run_parity_smoke()` 只接受已校验 prompt 列表。现在“已校验”的含义过窄，坏输入会产生不一致的错误边界，或者写出无效 prompt package/meta。

**建议修复**：

```python
# 当前
if not _PROMPT_ID_RE.fullmatch(entry["prompt_id"]):
    raise ValueError(...)
return raw

# 改为（示意）
_ASSET_ID_RE = re.compile(r"^img_[a-z0-9_]{1,64}$")
_ASSET_KINDS = {"character_sheet", "scene_background"}
_TARGET_TYPES = {"character", "location", "scene"}
_ASSET_ROLES = {"character_sheet", "scene_background"}

def _require_nonempty_str(entry: dict, key: str, i: int) -> str:
    value = entry[key]
    if not isinstance(value, str) or not value.strip():
        raise ValueError(f"prompt entry [{i}] field {key!r} must be a non-empty string")
    return value

prompt_id = _require_nonempty_str(entry, "prompt_id", i)
prompt = _require_nonempty_str(entry, "prompt", i)
asset_id_stub = _require_nonempty_str(entry, "asset_id_stub", i)

if not _PROMPT_ID_RE.fullmatch(prompt_id):
    raise ValueError(...)
if not _ASSET_ID_RE.fullmatch(asset_id_stub):
    raise ValueError(...)
if entry["asset_kind"] not in _ASSET_KINDS:
    raise ValueError(...)
if entry["target_type"] not in _TARGET_TYPES:
    raise ValueError(...)
if entry["asset_role"] not in _ASSET_ROLES:
    raise ValueError(...)
```

补测试：`prompt_id` 非字符串、`prompt` 空字符串、非法 `asset_kind`、非法 `target_type`、非法 `asset_role`、非法 `asset_id_stub` 都应返回 `ValueError`；`main()` 应继续把这些变成 exit code 2。

**模块边界状态**：✅ 在边界内（可修）

### 4.3 [ERR] generator/providers/openai_image.py:119 — `n > 1` 会付费生成多张但只返回第一张

**问题**：`generate()` 把调用者传入的 `n` 原样传给 OpenAI，但 `_extract_image_bytes()` 只读取 `response.data[0]`，`ImageGenerationResult` 也只有一个 `image_bytes` 字段。调用者如果传 `n=2` 或更高，会被计费多张、raw metadata 写 `n` 张，但实际只拿到第一张，其余图片静默丢失。

**为什么 IMPORTANT**：这是隐蔽的成本/数据丢失 bug。当前 Protocol 是单结果返回，不能在本任务内改成 list；边界内最安全的修法是 API provider 暂时只接受 `n=1`，直到后续 PR 明确多图返回契约。

**建议修复**：

```python
# 当前
final_prompt = _compose_prompt_with_ref_paths(prompt, ref_images)
size_str = _size_tuple_to_openai(size)

# 改为
if n != 1:
    raise ImageProviderError(
        "OpenAIImageProvider currently supports n=1 because "
        "ImageGenerationResult carries a single image_bytes payload"
    )

final_prompt = _compose_prompt_with_ref_paths(prompt, ref_images)
size_str = _size_tuple_to_openai(size)
```

补测试：`provider.generate(..., n=2)` 不应调用 `mock_client.images.generate`，并抛 `ImageProviderError`。`estimate_cost(n=4, ...)` 可以继续保留线性估算，供上游预算预估使用。

**模块边界状态**：✅ 在边界内（可修）
