### 4.1 [ARCH] generator/scene_review_cli.py:395 — `sampling_pass` 把“至少一条路径到达 end”误记为 2B 通过

**问题**：`scene_review_log.jsonl` 的 `sampling_pass` 当前只判断 `reached_end_count > 0`。这会把 `1/100` 条路径到达 end、`99` 条 deadlock 的场景写成 `sampling_pass=True`，后续 T-2.12 或验收报告读 review log 时会误以为 2B 抽样通过。

**为什么是 IMPORTANT**：ADR-021 的阶段 2 口径是“N=100 路径抽样 + 未发现反例/死锁”，不是“至少一条路径可通”。这是持久化评审日志字段，污染后续指标比终端显示错误更难排查。

**修复建议**：
```python
# 当前（问题代码片段）
"sampling_pass": (summaries.get("sampling") or {}).get("reached_end_count", 0) > 0,

# 建议
samp = summaries.get("sampling") or {}
sample_count = int(samp.get("sample_count", 0) or 0)
reached = int(samp.get("reached_end_count", 0) or 0)
deadlocks = int(samp.get("deadlock_count", 0) or 0)

"sampling_pass": (
    sample_count > 0
    and reached == sample_count
    and deadlocks == 0
),
```

同时补一个 review_cli 非交互测试：构造 `sample_count=100 / reached_end_count=1 / deadlock_count=99`，断言写出的 `sampling_pass` 为 `False`。

### 4.2 [ARCH] generator/scene_experiment.py:150 — 2A 拓扑 summary 丢掉了 condition 形态合法性双报

**问题**：`_summarise_topology()` 只输出一个整体 `pass` 和 `error_codes`，`scene_review_cli.py:151` 也只显示 `topology PASS/FAIL`。但 T-2.8 要求终端显示 T-2.7 2A 双报：纯拓扑 pass + condition 形态合法性。`validator.graph_validation.TopologyResult.condition_form_issues` 已存在，却没有写进 `validator_summaries`。

**为什么是 IMPORTANT**：ADR-021 明确把 2A 拆成“纯拓扑 + condition 引用形态合法性”，避免把 condition-aware 能力说得过满。当前输出把两者合成一个 pass，作者无法区分“图结构坏了”还是“condition 形态坏了”。

**修复建议**：
```python
# 当前（问题代码片段）
return {
    "pass": not res.has_error,
    "error_count": len(errors),
    "warning_count": len(warnings),
    "error_codes": sorted({i.code for i in errors}),
    "unreachable_nodes": list(res.unreachable_nodes),
    "deadlock_nodes": list(res.deadlock_nodes),
}

# 建议
condition_form_errors = [i for i in errors if i.code == "CONDITION_FORM_INVALID"]
pure_topology_errors = [i for i in errors if i.code != "CONDITION_FORM_INVALID"]
return {
    "pass": not res.has_error,
    "pure_topology_pass": not pure_topology_errors,
    "condition_form_pass": not condition_form_errors,
    "condition_form_issue_count": len(res.condition_form_issues),
    "error_count": len(errors),
    "warning_count": len(warnings),
    "error_codes": sorted({i.code for i in errors}),
    "unreachable_nodes": list(res.unreachable_nodes),
    "deadlock_nodes": list(res.deadlock_nodes),
}
```

然后在 `scene_review_cli.py` 的 validator summary 中显式显示 `pure_topology=PASS/FAIL` 与 `condition_form=PASS/FAIL`，并加 smoke 断言。

### 4.3 [ARCH] generator/scene_ai_judge.py:97 — AI judge JSON/公开字段缺少 `informational only` 机器可读标记

**问题**：模块 docstring、Markdown 报告和 CLI 描述已经说明 advisory 非接受率分子，但 `AIJudgeReport.advisory_recommendation` 字段本身没有注释，`_serialise_report()` 输出的 `AI_JUDGE_REPORT.json` 也只有 `advisory_recommendation`，没有任何 `informational_only` / `non_binding` / `acceptance_source` 元数据。T-2.12 若程序化消费 JSON，会失去 ADR-020 §6 的权威说明。

**为什么是 IMPORTANT**：ADR-020 §6 锁定“AI 判官只是辅助参考；接受率分子只能来自作者 [A]”。JSON 正是 A 阶段主动加的程序化消费格式，最需要把 non-binding 语义写进机器可读层。

**修复建议**：
```python
# 当前（问题代码片段）
@dataclass
class AIJudgeReport:
    advisory_recommendation: dict[str, Advisory] = field(default_factory=dict)

def _serialise_report(report: AIJudgeReport) -> dict:
    return {
        "pass1_lenient_scores": report.pass1_lenient_scores,
        "pass2_strict_scores": report.pass2_strict_scores,
        "weakest_dimensions": report.weakest_dimensions,
        "advisory_recommendation": report.advisory_recommendation,
        ...
    }

# 建议
@dataclass
class AIJudgeReport:
    # Informational only; never used as ADR-020 acceptance-rate numerator.
    advisory_recommendation: dict[str, Advisory] = field(default_factory=dict)

def _serialise_report(report: AIJudgeReport) -> dict:
    return {
        "metadata": {
            "advisory_authority": "informational_only",
            "acceptance_source": "scene_review_cli_author_A_R",
            "adr": "ADR-020 §6",
        },
        "pass1_lenient_scores": report.pass1_lenient_scores,
        "pass2_strict_scores": report.pass2_strict_scores,
        "weakest_dimensions": report.weakest_dimensions,
        "advisory_recommendation": report.advisory_recommendation,
        ...
    }
```

同时让 `test_scene_ai_judge_smoke.py` 断言 JSON metadata 存在，避免后续改动把标注拿掉。
