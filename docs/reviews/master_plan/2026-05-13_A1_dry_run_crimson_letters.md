### 0.3.1 v2.1 dry-run 期作者临场决策（2026-05-13 步 3 完成后）

#### 决策 1：节拍 = GM 抉择空间入口（理解层 · 确认）

每个节拍是一个潜在 GM 即兴空间入口。节拍结束时"哪些状态被改变了"是 GM 创作裁量空间。该理解对齐 T-3X-0 §5 + ADR-031 v0.1 §核心赌注。

#### 决策 2：节点上限升级 v2.1（dry-run 破例）

- v2 约束：3-6 节点
- v2.1 升级：**6-15 节点**（dry-run 破例）
- 完整生产期：v2 约束 3-6 是否同步升级 → **待 ADR**（不在本 dry-run 范围内拍板）
- 理由：调查类场景信息密度高 + NPC 反应多 + 多 ending 拆细需要更深节点

#### 决策 3：方向 A · 拆细 ending（v1 → v2 重设计）

- v1 设计：2 个 end 节点（end_ally / end_cold）+ effects 差异化

#### 决策 5：NPC 关系多维（v2.1）

原 schema 单维（`relationship.<npc>.trust` 信任度）→ v2.1 多维。

```yaml
relationship.<npc>:
  trust: <int>             # 信任度（情感 / 长期）
  cooperability: <int>     # 可合作性（利益对齐 / 目的对齐 / 短期合作意愿）
  fear: <int>              # 恐惧度（NPC 怕玩家）
  affinity: <int>          # 亲和度（NPC 对玩家情感倾向）
  cooperation_events:      # 可合作事件列表（作者建议）
    - event_id: <string>
      type: deal | favor | promise | threat   # 协议 | 帮助 | 承诺 | 威胁
      value: <int>         # 对 cooperability 的增益
      preconditions: ...   # 触发条件
      triggers_state_change: ...   # 触发的 NPC 状态机转移
```

**典型案例**（作者举例）：奥克斯+肖纳西（讨债人）= cooperability 主导 + trust ≈ 0。玩家承诺利益分成 → 触发 `gangster_profit_split_promise` → cooperability +5 → npc.oakes_shaughnessy.state 转移：`extortion` → `partnership`。

**应用到 Crimson Letters**（按 culprit_vick 配置 · 主导维度差异化）：

| NPC | 主导维度 |
|---|---|
| 露西（情妇）| trust 主导（情感 + 双重支配）+ cooperability 次要 |
| 法伦（委托人）| trust + cooperability 双主导（雇佣关系）|
| 考特（助理）| respect 主导（智力对决）+ cooperability 次要（如果调查员配合她抹黑罗奇/弗林德斯）|
| 罗奇（学术对手）| cooperability 仅当玩家承诺帮抹黑法伦时激活 |
| 弗林德斯（痴迷者）| affinity 主导（玩家配合他的痴迷）+ fear 次要 |
| 维克（食尸鬼）| **cooperability 主导**（要文档）+ fear 次要 |
| **奥克斯+肖纳西（讨债人）**| **cooperability 主导**（作者举例）|
| 萨默塞特（探长）| respect 主导（专业互动 · 阈值反派工具）|

**A1 字段集顶层洞察**（写到这里发现）：

1. **钩子和守秘人笔记**模组里**嵌在 NPC 卡内**——独立成集会重复。schema 设计："钩子 / 守秘人笔记"应该是 NPC schema 的子字段，不是顶层集合。
2. **事实与线索集**是个**图结构**（NPC ↔ 事实 ↔ 获取方式）——平表存不下，要拆 3 张表（NPC / fact / acquisition）+ 一张关系表。
3. **时间线**模组写得已经结构化（日期 + 事件），可直接 1:1 压成 JSON。schema 最简单的部分。
4. **多嫌疑人结构** = 元参数（culprit_id）+ 4 个嫌疑人 NPC 的"若被选为真凶"字段。**这字段一旦设到 NPC schema 上，所有非嫌疑人 NPC 也得有这字段（optional）**——这是 schema 一致性问题。
5. **GM 即兴空间清单**才是真正 A1 难点——模组 §17 写"守秘人即兴"是开放的，无法穷尽。AI 顶不动，必须作者来界定哪些算"AI 可预生成的伪即兴"哪些必须留白。

### 1.2 钩子集

> **A1 候选 schema 洞察**：钩子分两类——
> - **介入钩子**（intro_hook）：把调查员引进案件的开局动因。模组只有 1 个（法伦委托），故事级 singleton。
> - **角色扮演钩子**（roleplay_hook）：每个 NPC 各自的行为模式 / 主动倾向 / 反应模式。模组里**嵌在 NPC 卡里**——独立成集会重复，schema 设计上应该作为 NPC 的子字段（已在 §1.1 各 NPC 卡内呈现）。

#### 1.2.1 介入钩子（唯一）

| 钩子 ID | hook_summary | 委托人 NPC | 触发场景 | 报酬 |
|---|---|---|---|---|

#### 1.2.2 角色扮演钩子（聚合视图）

11 个独立 NPC + 2 张成对 NPC 卡里共聚合约 **30 个角色扮演钩子**——每个 NPC 卡 2-4 条不等。schema 上是 NPC.roleplay_hooks: list[hook]。完整清单见 §1.1 各 NPC 卡的"角色扮演钩子"段。

**A1 洞察**（钩子层）：
- 介入钩子是"故事级"singleton，schema 上是 story.intro_hook 字段
- 角色扮演钩子是"NPC 级"list，schema 上是 npc.roleplay_hooks 字段
- 模组的 30 个 NPC 钩子里大量是"NPC 主动行为倾向"（A 想抹黑 B / C 想拿到 X）—— **这本质是 NPC 状态机的入口条件**（ADR-031 §状态机抽象的实证案例）
- 但模组里**钩子没有显式条件**——什么时候触发要 GM 即兴判断。这是 GM 抉择空间的形式之一（"NPC 反应"，T-3X-0 §5 表中第 2 行）

**A1 洞察**（时间线层）：
- 模组结构化最好的部分。schema 字段 `story.timeline` 直接 1:1 映射。

- **现在 + 未来事件**（10 月 1 日 - 10 月若干日）= 玩家行动期间 · 由 world_state 动态推进。
- schema 应该用 `event.phase` enum 区分：`past_fixed / present_player_active / future_conditional`。

### 1.6 多嫌疑人结构（**GM 抉择空间核心形式 #1**）

> **A1 候选 schema 洞察**：多嫌疑人 = 元参数（meta_parameter）。schema 上是 `story.culprit_id: enum[npc_id]`，元参数在生成期由作者/L2 设定，**运行时不变**。
>
> **结构**：模组列 4 候选 + 1 自定。每个候选嫌疑人 NPC 有"若被选为真凶段"（npc.if_culprit）。模组明示只有当 `npc.if_culprit != null` 才能作为真凶候选。

| culprit_id | NPC | 嫌疑动机 | 难度 / 戏剧性 |
|---|---|---|---|
| `culprit_court` | 艾米莉亚·考特 | 知文书异界本质 · 密谋杀莱特拿文书 · 或为"保住"文档而盗 | 高（表面不太可能 + 可深挖世家背景）/ 戏剧性最强 |
| `culprit_roach` | 哈兰德·罗奇 | 学术竞争 · 抹黑莱特 · 不知情下陷极端危险 | 低（最 obvious）/ 戏剧性低 |
| `culprit_flinders` | 安东尼·弗林德斯 | 撒旦崇拜痴迷 · 跟踪到亨特公寓取文档 · 现骑虎难下 | 中（已展示行为模式可信）/ 戏剧性中（神秘+暴力） |
| `culprit_vick` | 阿布纳·维克 | 派手下从亨特处抢 · 准备仪式安抚束缚那存在为己用 | 高（最强反派 + 神话知识）/ 戏剧性最强 |
| `culprit_custom` | 守秘人自定 | （未列出） | 完全开放 |

**A1 洞察**（多嫌疑人层）：
- 真凶选择 = 在 5 候选里 GM 拍板。本 dry-run 我**不该自决**（这是 GM 抉择 = 作者抉择）。
- 即使运行时不暴露 culprit_id · 但 generator 期需要它 = **生成不同剧本变体的元参数**。
- AI 不能写一个"真凶未定"的 dialogue_graph——任何场景一旦写出来，某个 NPC 的反应就锁定。所以**步 2 之前作者必须先拍板 culprit_id**（lessons learned 维度）。

**待作者拍板**：步 2 启动前请作者明示 culprit_id。AI 推荐 `culprit_vick`（最强反派 + 戏剧性最强 + 与维克古董店场景候选 C 自然衔接）。但若场景选 B（露西）→ culprit 选择会影响露西"很可能会死"的具体形式（被维克 vs 被弗林德斯 vs 被恐怖之物）。

### 1.7 倒计时机制（**GM 抉择空间核心形式 #2**）

> **A1 候选 schema 洞察**：倒计时 = "通路征兆"5 级 + 触发条件。schema 上是 `story.countdown.stages: list[stage]`，每个 stage 含 `stage_id, severity, manifestations, triggers, world_state_delta`。
>
> **触发条件**：模组里**没有明示具体行动数 / 事件 / 时间**——"由守秘人决定 · 应快速升级"。这是 GM 抉择空间的另一形式（"威胁节奏"，T-3X-0 §5 表第 3 行）。

| stage_id | severity | manifestations 摘要 | 模组建议触发 |
|---|---|---|---|
| `stage_1_storm` | 低 | 收音机/电池/电器干扰 · 反常风暴突起又消散 · 局部温度骤降呼吸结雾 | 早期 |
| `stage_2_witchfire` | 低-中 | 远处诡异红光（梅森女巫屋 / 霍布豪斯宅邸 / 亨特工作室 / 莱特小屋）· 目击者后疾病/疲惫/头痛 | 早-中期 |
| `stage_3_night_noises` | 中 | 近曾接触文书之人 · 存在感 · 走进屋回头空无 · 楼上脚步 · 电话低语 | 中期 |
| `stage_4_possession` | 中-高 | 附身曾接触文书者（死活皆可）· "灵魂灼烧"+ 受害者本身攻击 · 尸体被附身则僵尸行动 | 中-后期 |
| `stage_5_partial_manifestation` | 高 | 最终完全显现前部分显现 · 沿途留疯狂与死亡 · 目睹要 san check | 后期 |
| `stage_complete` | 极高 | 完全显现 · 抓取拥抱 · 灵魂灼烧 · 无上限理智损失 · 一场龙卷风般浩劫 + 大量死亡 | 终局（若调查员失败） |

**A1 洞察**（倒计时层）：
- 5 级显现是**线性升级**——schema 上是 list ordered by severity，玩家世界状态每次推进就增加 stage_index。
- 但模组明示**显现位置 + 频率由 GM 决定**——schema 字段 `story.countdown.trigger_strategy` 需 enum：`event_count_based / time_based / world_state_threshold_based / gm_discretion`（最后一项无法结构化）。
- AI 不能写"具体 X 个行动后触发 stage_2"——这是项目配置层 + GM 即兴决定。**AI 顶不动**。
- A1 dry-run 这个字段层我**只压枚举值** + **留 trigger_strategy 字段 TBD**。

### 1.8 多解决路径（**GM 抉择空间形式 #3**）

> **A1 候选 schema 洞察**：解决路径 = 3 种主手段 + 1 个失败。schema 上是 `story.solutions: list[solution]`，每个含 `solution_id, summary, success_condition, risk, ending_state`。

| solution_id | 摘要 | 成功条件 | 风险 | 结局状态 |
|---|---|---|---|---|
| `solution_hide` | 把图示部分 + 半成品副本拿走 · 藏到不会直接伤人的地方 | 调查员取得文档 + 找到合适藏匿点 | 相当于送炸弹到别人家 · 不局限于一个地点 · 也会针对长期接触者 | 表面胜利 + 后续遗祸 |
| `solution_destroy` | 销毁文书图示部分 | 调查员取得文档 + 有手段执行销毁 | 立即在狂乱中显现 · 攻击 + 在以太中解体崩散若干回合 · 留血腥焦油残渣 | 胜利 + 高伤亡风险 |
| `solution_mythos_skill` | 克苏鲁神话技能临场使用（可在文书初步研读 1 晚后获得几点）· 把怪物从文书中驱散 | 神话技能成功 / 推动检定 | 推动失败 → 严重后果 + 剧本恐怖收尾 | 胜利 / 灾难（推动失败） |
| `solution_failure` | 调查员失败 / 恐怖之物在阿卡姆某处完全显现 | 调查员失败 / 不作为 | 大量死亡 · 每人 san check · 阿卡姆境内则伤亡可观 | 失败结局 |
| `solution_vick_only` | 维克是本剧本中**唯一能成功封印并处理它**的人物 | 调查员把文档交给维克 · 维克要求所有权交换 + 方法是调查员宁可不知情 | 文档落入食尸鬼之手 · 长期遗祸 | 灰色结局 |

**A1 洞察**（多解决路径层）：
- 3 + 1 + 1 = 5 个 ending state · schema 上是 `world_state → ending` 映射。每个 ending 是 dialogue_graph 的一个 end_node。
- 但实际 ending **没有 1:1 对应** world_state——同一 world_state 下，玩家选 hide vs destroy vs mythos 是 dialogue option 选择（不是 world_state）。
- 实际 mapping：`(world_state.has_documents, world_state.horror_stage, dialogue_choice) → ending_id`。**这是 3 维矩阵**——schema 上是 endings.preconditions: condition_predicate。

### 1.10 GM 即兴空间清单（**A1 最难压成字段的部分**）

> 任务 prompt §1 完成判定要求"GM 即兴空间清单：每个具体留白点 + GM 怎么填"。这是 A1 dry-run 最有诚实记录价值的字段层。
>
> 对照 T-3X-0 §5 的 7 种 GM 抉择空间形式 + 本模组里的具体留白点：

| 形式（T-3X-0 §5） | 模组里的具体留白点 | A1 候选 schema | AI 能否预生成？ |
|---|---|---|---|
| **真凶选择** | 4 候选 + 自定（§1.6） | 元参数 culprit_id | ✓ 生成期选定 |
| **NPC 反应** | 30+ 角色扮演钩子里的"NPC 主动行为"无显式触发条件（§1.2 + §1.1 各 NPC） | NPC 状态机 + 反应矩阵（state × event → next_state + response）| ⚠️ **部分**——常见触发可预生成，长尾要 GM 即兴 |
| **威胁节奏** | 5 级显现触发时机由 GM 决定（§1.7） | trigger_strategy enum（含 gm_discretion） | ✗ **不可完全预生成**——具体节奏要 GM 拍板 |
| **多结局** | 5 ending（§1.8） | ending preconditions（3 维矩阵） | ✓ 预生成可枚举 |
| **场景扩展** | "守秘人可以加入自己的剧情线 / 派系" (§1) · 多个 NPC 卡里"剧本之后"段（§1.1 法伦 / 维克）· 红鲱鱼临场变（§5 §19 试玩示例） | 场景模板 + 插件式追加 | ⚠️ **部分**——常见扩展可预生成，临场变不能 |
| **难度调整** | "对瓷器店里横冲直撞的莽夫不该手软"（§3）· 露西初始魅惑难度"困难"（§9）· 大西洋城打手让他们罢手"极难"（§15）· 但具体 DC 数值未给定 | 难度参数（影响检定 DC / NPC 警觉度） | ✓ 预生成可枚举 + 项目配置层定义 |
| **即兴（不可结构化）** | 试玩示例：调查员第三次造访尸体时尸体抓住肖纳西手腕；霍布豪斯宅邸临场变黑帮入场点（§19）；阿卡姆疗养院电报作为调查员僵局补充线索（§19）；维克晚宴邀请的"采集情况"（§19）·守秘人临场建议 §17：玩家走得太快 → 抛假线索 / 让人物出城 / 突如其来杀人物 / 制造意外险境 | **不可完全结构化** ⚠️ | ✗ **完全不可预生成**——必须 AI 在审阅期参与 / 作者最终判断 |

**A1 最深层洞察**（GM 即兴空间层 · v2 术语）：
- 模组 §17 "守秘人临场建议"是 Crimson Letters 的运行核心——明示线索 + 遭遇 + 关键事件应出现在守秘人选择安排的地点与时刻，不是冰冷印进纸张。
- **这恰好就是 ADR-031 v0.1 §核心赌注挑战**（原话引用："AI 海量预生成 + 人工审阅 = 给玩家伪即兴体验"；v2 术语清算后表达：**生成期 schema 字段必须能容纳 GM 即兴空间七形式中可 schema 化的部分；接受率 + 完成率作为度量指标**）。
- 本 dry-run 在步 4（节点骨架 → 完整 narration）会真正实测：AI 生成的内容**接受率**有多高（红鲱鱼临场变 / NPC 主动反应 / 多嫌疑人下不同反应）？哪些必须人工补？这是 ADR-030 / ADR-031 量化矩阵的第一个实证数据点。
- A1 字段集 schema 最大盲区：**"即兴"字段无法穷尽 schema 化**——必须保留 GM 抉择空间 = 让作者审阅期介入 = 这就是 ADR-031 §10 §11 的本意。

#### 1.11.3 字段表格式偏好（实测）

| 字段类型 | 哪种格式最适合 | 理由 |
|---|---|---|
| 短字段 / 枚举 / 简短描述 | **markdown 表** | 紧凑 · 易扫读 · 字段一致性 |
| 段落 / 多句子描述 | **bullet 列表** | 表格里 word-wrap 难看 · bullet 易读 |
| 守秘人笔记 / 长段落 | **嵌套段落（无表）** | 段落连续阅读 · 表格强行切碎丢语境 |
| 图结构（NPC ↔ fact）| **markdown 表 + 关系说明** | 平表 + 描述图结构 · 真正 schema 化时拆 3 表 |
| 时间线 | **markdown 表** | 已经是结构化数据 · 1:1 映射 |
| 状态机 / 事件序列 | **markdown 表 + 流程描述** | 5 级显现这种线性升级用表 + AI 自评描述限制 |
| 多嫌疑人对照 | **markdown 表（高/中/低/戏剧性维度）** | 横向对比清晰 |

**总结**：A1 字段集**不存在"一种最优格式"**——根据字段类型混合用：
- 表格用于**结构化短字段** + **关系/对比**
- bullet 用于**事实清单 + 钩子清单**
- 段落用于**守秘人笔记 + GM 即兴空间洞察**
- 这意味着 schema 验证工具要**对不同字段类型容忍不同呈现格式**，或所有 schema 字段都规范化为 JSON（表/bullet/段落只是 markdown 渲染层）。

### 3.4 步 3 自评（lessons learned 实时记录）

#### 3.4.1 节拍 → 节点的映射比 / 类型

| 维度 | 实测 |
|---|---|
| 节拍数 | 6 |
| 节点数 | 6（4 dialogue + 2 end）|
| **节拍 : 节点** | **1:1 整体 · 5 dialogue 节拍 → 4 dialogue 节点 = 1.25:1** |
| **节拍合并方式** | beat_1 + beat_2 合并到 node_1（场景设置 + NPC 首反应都属"入口"节奏）；beat_6 的 4 出口（A/B/C/D）合并到 2 个 end 节点 + effects 差异化（C 合并到 A · 用 `flag.cache_known` 区分；D 合并到 B · 用 `flag.gangs_alerted_to_player` 区分）|

#### 3.4.2 state effects 设计粒度

| effect 类 | 出现次数 | 用途 |
|---|---|---|
| `flag.<key>` 布尔 | 11 次 | 标记一次性事件 / 玩家获得物 / 信息状态 |
| `flag.<key>` 整数计数 | 1 次 | flag.eye_noticed（眼线显著度计数）|
| `relationship.<npc>.trust` 增减 | 5 次 | 露西关系信任度（-1/+1）|
| `player.cash` 减 | 1 次 | 贿赂消耗 |
| `relationship.<npc>.trust` 减 999（"清零"惯用）| 1 次 | node_3.opt_betray 模拟"信任彻底崩溃"——但实际 schema 应该有专门的 `set` op 用 -∞，不是 dec 999 |

**A1 schema 洞察**：`relationship.<npc>.trust` 增减用 dec 999 是 hack——schema 应该支持 `op:set, value:-∞` 或 `op:reset`。

#### 3.4.3 选项数量分布

| 节点 | options 数 |
|---|---|
| node_1_arrival_inn | 3 |
| node_2_wright_name | 3 |
| node_3_info_offer | 4（信息密度最高 · 含追问 / 警告 / 深挖 / 出卖 4 类）|
| node_4_eye_tension | 3 |
| **平均** | **3.25 / dialogue 节点** |
| **范围** | **3-4**（v2 约束 3-6 ✓）|

**A1 schema 洞察**：信息密度高的"信息揭露节点"（node_3）需要 4 个 options 才能涵盖玩家行为空间；其他节点 3 个够。**schema 不应强制所有节点同等 options 数**。

#### 3.4.4 选项 diverge 度（v2 修订 3 实测）

| 节点 | 总 options | 收敛主线 | diverge | diverge 子树深度 |
|---|---|---|---|---|
| node_1 | 3 | 2 | 1（→ node_4 跳级）| 2 步（node_4 → end 或 node_3）|
| node_2 | 3 | 2 | 1（→ node_4 跳级）| 2 步 |
| node_3 | 4 | 3 | 1（→ node_6 早 end）| 1 步（直接 end）|
| node_4 | 3 | 2 | 1（→ node_6 早 end）| 1 步（直接 end）|
| **平均** | **3.25** | **2.25** | **1.0** | **1.5 步** |

**A1 schema 洞察**：
- **diverge ≠ 简单"非主线"**——本场景所有 diverge 都是"加速跳到 end"或"跳到张力升级节点"。**真 diverge（导向完全独立子树）需要更深的场景**（多 dialogue 节点）。
- 本场景 dialogue 节点深度只有 4 层 → diverge 子树深度只能 1-2 步——这是 v2 约束 3-6 节点带来的天然结果。**若要更深 diverge 子树要把节点上限放宽到 8+**。
- gold scene.json 5 节点同样深度低 → 同款现象。

### 3.5 v2 设计版本说明（按 §0.3.1 v2.1 临场决策升级）

**v2 升级范围**（vs v1）：
- 节点上限：3-6（v2 约束）→ **6-15**（v2.1 升级）
- ending 数：**2 → 5**（方向 A 拆细）

- NPC 关系维度：**单维 trust 信任度** → **多维**（trust / cooperability 可合作性 / fear 恐惧度 / affinity 亲和度 + cooperation_events 可合作事件列表）

**v2 设计目标**：
1. 验证 v2.1 升级后能否实测出"玩家选不同选项 → **真正不同结果**"体验（解决 v1 主问题）
2. 验证 8 类 effects 在单场景里都能用到（说明不是过度设计）
3. 验证多维关系在 culprit_vick 配置下的应用（露西 trust 主导 + cooperability 边际触发）
4. 验证 cooperation_events minimal example：`appeal_avenge_wright`（承诺为莱特复仇）→ cooperability +2

### 4.2 步 4 自评（实时 lessons learned）

| 项 | 实测 |
|---|---|
| AI 单次可写长度 | 本次一次性写完 10 节点成稿（5 dialogue + 5 end + 19 option text），约 3200-3800 中文字，未触发上下文或工具限制 |
| 最难写的节点 | `node_3_info_offer` 和 `node_5_deep_probe`：既要吐足信息，又不能把露西写成线索机器；还要避免直接剧透 culprit_vick |
| 最容易写偏的地方 | 露西语气。太硬会像黑帮片 femme fatale，太软会变成纯受害者；当前一稿选择“会算账但仍被莱特牵动” |
| v2.2 多维关系呈现 | `affinity` 可自然落在共情选项；`fear` 可自然落在展示武力选项。四维全部塞进同一场景可行，但有一点“为了示例而示例”的人工感 |
| 8 类 effects 呈现 | inventory / npc.state / world_state 很自然；location.state 与 conditional narration 的关系暴露 schema 问题：若结局文本要按地点状态变化，当前 gold schema 需要模板字段或拆更多 end 节点 |
| AI 顶不动 | 作者真实接受率、逐节点返工率、审阅速度都不能由 AI 自填；必须等作者 [A]/[R]/[S] 后补 |

## 5. lessons learned 总段（4 步完成后已填）

> **状态**：4 步 markdown 已齐。作者逐节点验收仍待补，因此“接受率 / 作者审阅速度”只能诚实标为待测。

| 问题 | 实测答案 |
|---|---|
| 每层 input/output 长什么样 | 步 1 input = 模组全文；output = 9 大字段类 + 12 张 NPC/背景卡 + 事实图/时间线/场景/GM 即兴空间。步 2 input = 字段集 + 作者拍板 scene/culprit；output = 6 节拍清单。步 3 input = 节拍；output = 10 节点骨架（伪 YAML）。步 4 input = 节点骨架；output = 完整 narration + option text 一稿。|
| 每层耗时 | 步 1 ≈ 53min（详 §1.11.4）/ 步 2 ≈ 25min（详 §2.4.3）/ 步 3 v1 ≈ 36min + v2 ≈ 57min（详 §3.4.5 + §3.9.4）/ 步 4 ≈ 35-45min（含 v2.2 小修 + 成稿 + lessons learned 落档，AI 估算）|
| AI 顶不动的地方 | culprit_id / 场景选择 / 倒计时触发 / GM 即兴杀人时机 / DC 数值 / 作者真实接受率 / 审美最终取向都不能由 AI 自决。步 4 里尤其顶不动“露西语气是否正中作者口味”。|
| 作者负担过重的地方 | 目前已出现两类负担：一是步 3 拓扑校对需要作者理解 node / diverge / effects；二是步 4 若逐节点 A/R/S，预计要读 10 节点约 3000+ 字。实测接受率待作者反馈。|
| 中间格式选择 | 字段集适合混合 markdown 表 + bullet；节点骨架适合伪 YAML；步 4 成稿仍适合伪 YAML，但 conditional narration 暴露字段不足。|
| NPC 状态机假设验证（ADR-031 推荐 D） | 验证通过但需要 enum 标准化。露西从 `alarmed/opened_up/warned/cautious/doomed/abandoned/ally_basic/alerted_ally` 等状态切换，能表达 NPC 反应，但状态值很容易由 AI 临场乱造。|
| 审美偏好注入假设验证（ADR-030） | 部分验证。AESTHETIC_PREFERENCES.md 只给“暗黑 + 灰色为主，明朗 + 戏谑为辅”的粗基线；AI 可以据此写出可审的一稿，但无法保证作者听感。需要后续 demo 文本反馈建立更细颗粒度。|
| 总评 | A1 dry-run 证明“CoC 模组 → dialogue_graph”端到端可以手工跑通；真正困难不在 JSON 字段，而在 GM 即兴空间如何预先拆成可审阅分支，以及 conditional narration 是否应进 schema。|
| 量化数实证（节点数 + 耗时） | 原 3-6 节点约束对调查类场景偏紧；本场景最终用 10 节点更舒服。单场景从全文阅读到步 4 一稿累计约 3 小时级别（不含作者完整审稿）。|
| **【v2 追加 1】选项 diverge 度实测** | v2.2 仍是 5 dialogue 节点 / 19 options / 9 diverge，平均 1.8 diverge / dialogue 节点。`node_3_info_offer` 达到 3 diverge 上限，是主分歧 hub。|
| **【v2 追加 2】路线分支密度可行性** | 本轮密度 = 1（单入口）已经有 10 节点工作量。若做 2-3 个入口，预计 narration 与 condition 成本至少 +30%-60%，建议第二轮 dry-run 再测，不建议本轮扩。|
| **【v2 追加 3】量化矩阵 vs 实测差距** | v2 3-6 节点预期 vs 实测 10 节点，说明调查类 NPC 场景若要“选项真正不同结果”，节点上限应考虑 8-12 或 6-15。|
| **【v2 追加 4】候选稿数效益** | 本轮候选稿数 = 1。若跑 2 稿，AI 写作成本几乎翻倍，作者挑稿负担也显著增加；在 schema 尚未稳定前，1 稿 + send-back 可能比 2-3 稿更经济。|
| **【v2.1/2.2 追加】多维关系实测** | v2.2 后 trust / cooperability / fear / affinity 四维都能在单场景触发；但 fear / affinity 明显是为了示例补入。完整生产期不应强制每场景用满四维。|
