## 2. Anti-pattern 黑名单（v0.1；10 条）

> generator prompt 应该把本节作为"禁用模式"清单直接 inject。validator / 审阅工具应能按这些条目高亮 flag。

### AP-1: AI 对仗式 / 重复对应感过强

- **现象**：A like X; B like Y 的对仗结构频率过高；前后两半语义重复
- **A1 例**：§4.1.1 第一段「前厅摆着...像一张给警察和好人看的脸；真正的热闹从后门那条窄楼梯往下漏」—— 前半已暗示"另一面"，后半的对仗结构是冗余
- **诊断**：典型 AI 文本签名；这种"两半呼应"是 RLHF 优化的副作用（让结构看起来"工整"）
- **规则**：单段内避免成对对仗式结构；前半已暗示的，后半不要重复明示

### AP-2: 修辞失底（喻体与本体无共同点）

- **现象**：用比喻 / 类比 / 修辞但喻体和被描写对象之间**没有可识别的共同点**
- **A1 例**：
  - §4.1.1「托盘在她指尖稳得像变戏法」—— "变戏法" 暗示眼花缭乱 / 精准操作，但托盘只是稳，无共同点
  - §4.1.5「她把名片推给你，又把手收回去，像刚碰过一枚不干净的硬币」—— "碰过不干净的硬币" 没有可识别的动作 / 心理特征
  - §4.1.4「你别摆那副法官脸」—— "法官脸" 究竟指什么（正义？程序？审视？怀疑？）—— 无线索
- **规则**：用修辞前必须明示喻体和本体的共同点；如果共同点说不清，**直接白描**，不要用修辞

### AP-3: 修辞方向 / 物理逻辑错误

- **现象**：修辞或动词的物理 / 方向逻辑与场景实际相反
- **A1 例**：§4.1.1「真正的热闹从后门那条窄楼梯往下漏」—— "漏" 意味着从上方往下泄，但热闹是**从地下传上来**的，方向相反
- **规则**：用动词 / 修辞前检查物理方向 / 逻辑是否与场景一致

### AP-4: 假靶子否定

- **现象**：竖一个读者本来**没预期**的靶子，然后用否定句式去否定它
- **A1 例**：§4.1.2「名字落下去时，露西脸上的笑没有碎」—— 没人预期笑会"碎"，竖假靶子去否定没说服力。直接写"露西脸上的笑只是停了一拍"即可
- **诊断**：AI 用否定句式制造"反转 / 戏剧性" 的偷懒模式
- **规则**：否定句必须否定读者真实预期的靶子；如果靶子需要先建立，**直接正向描写**

### AP-5: 总结代细节

- **现象**：用总结性评价代替具体行为描写，没给读者论据
- **A1 例**：
  - §4.1.1「眼神却老练得不像二十五六岁的人」—— "老练" 是评价，没有可观察的细节支持
  - 反例（同节点是好的）：「她扫了你一眼，先看鞋，再看手，再看你有没有像常客那样急着找酒」—— 这是具体行为描写
- **规则**：先给具体行为 / 物理细节，避免直接给评价；如果必须给评价，前后要有具体细节铺垫

### AP-6: 锚定未说明的标准

- **现象**：引入读者不知道的"一般标准"作为对比基准
- **A1 例**：§4.1.1「她的金发颜色新得过分」—— "金发的一般标准" 是什么？读者不知道
- **规则**：要么写具体细节（如"她的金发还有刚染过的化学气味"），要么不写；不要锚定假标准

### AP-7: 旁白抢 NPC 的台词

- **现象**：把本该 NPC 自己说的话用第三人称旁白概括，让玩家失去通过对话获取信息的体验
- **A1 例**：§4.1.3 node_3_info_offer 的 narration「她说莱特在人前是教授，人后是另一种人...」「他带她去过大西洋城...」—— 这些信息本应让露西自己说，AI 偷懒用旁白扔出来
- **诊断**：违反 CRPG 文本工程事实标准；破坏玩家"通过对话与 NPC 互动获取信息"的核心代入感
- **规则**：信息属于 NPC 的，必须用 NPC 直接说的话呈现；旁白只描写**物理现象 + 客观环境 + 玩家可观察的细节**

### AP-8: 选项第三人称化

- **现象**：option text 写成"玩家意图的第三人称概括"，而不是"玩家此刻要说的话或要做的动作本身"
- **A1 例**：
  - §4.1.3「先追问赌债和维克名片，把浅层线索坐实」—— 这是意图描述，玩家本人不会用这种话说
  - §4.1.5「追问那个大学生：给我名字或住址」—— "追问那个大学生" 是第三人称
- **规则**：option text 必须是玩家本人的第一人称语言；`[skill_name]` 检定标记可保留在前
- **生成期校验提示**：validator 检查 option.text 是否以"追问 / 共情 / 警告 / 离开 / 先 / 把"等动词或动作概括开头 → flag

### AP-9: 读不懂的省略

- **现象**：留白过多 / 关键信息省略，读者无法 fill in
- **A1 例**：§4.1.5「有些人欠钱会怕打手，莱特怕的不是打手」—— 莱特怕的是什么？读者不知道；如果是"莱特怕维克的另一面"，应该有别的细节铺垫
- **规则**：留白前必须确保读者有线索能 fill in；如果线索还没出现，**直接交代**

### AP-10: 指代不清 / 用单字代称自己

- **现象**：用"女孩 / 男孩"等单字代称自己（尤其在中文里读起来奇怪）
- **A1 例**：§4.1.5「女孩也得活下去，你别摆那副法官脸」—— 露西用"女孩"指代自己
- **规则**：第一人称对话避免用"女孩 / 男孩 / 小孩"等代称自己；写"我"或具体名字

## 3. 三分类角色守则 v0.1

> 作者于 2026-05-14 提出的核心架构原则：每个场景的文本严格分为 3 类，每类有不同的工程契约。这是后续 schema / prompt / generator 设计的基础。

### 3.1 旁白（Narration）

- **主语**：第三人称（叙述者视角）
- **可写范围**：
  - ✓ 物理环境描写（光线 / 声音 / 气味 / 场景布置 / 时间）
  - ✓ 客观物理动作（NPC 的肢体动作 / 道具操作 / 移动）
  - ✓ 玩家可直接观察到的细节
- **禁止写**：
  - ✗ NPC 的内心活动（应通过 NPC 自己的话或动作暗示）
  - ✗ NPC 的台词信息（必须由 NPC 自己说出来）
  - ✗ 玩家的内心活动 / 价值判断（应通过选项让玩家自己做）
  - ✗ 总结性评价（"她很狡猾"——用具体行为代替）

### 3.2 NPC

#### 3.2.1 子型 a：旁白带 NPC 名字 / 代词的主谓宾

- **主语**：NPC 名字 / 代词
- **写**：NPC 的动作 / 表情 / 视线 / 物理姿态
- **例**：「露西把空杯子往水槽里一放」/「她的指尖按着那张名片」

#### 3.2.2 子型 b：NPC 直接说的话（引号内）

- **形态**：中文 `"..."` 或 `「」` 包裹的引述
- **写**：NPC 此刻说的话本身（必须是 NPC 角色会说的语言 / 措辞 / 节奏）
- **例**：「教授的朋友可真多。」露西低声说。
- **工程契约**：NPC 直接说的话**必须包含场景的关键信息**（不能让旁白替代）
- **参考**：业界 CRPG 普遍使用引号区分 NPC 直接说的话（极乐迪斯科 / BG3 中文版 / Pillars of Eternity / Pathfinder 等）

### 3.3 玩家

#### 3.3.1 子型 a：旁白以玩家为主语

- **主语**：「你」/ 玩家代词
- **写**：玩家的物理感受 / 不可控的反应（疲倦 / 寒意 / 心跳 / 视野模糊）
- **例**：「你感到酒精在血液里慢慢散开」
- **限制**：**不要替玩家做价值判断或决定**（"你决定要..." 是错的，应该给玩家选项）

#### 3.3.2 子型 b：玩家说的话或做的动作（选项本身）

- **形态**：node.options[].text
- **写**：玩家此刻要说的话 / 要做的动作本身（第一人称语言）
- **例**：
  - ✓「我不是来审你。我想知道他到底怎么死的。」
  - ✓「[观察入微] 先把酒馆里不喝酒的人记下来。」（检定标记 + 第一人称动作）
  - ✗「先追问赌债和维克名片，把浅层线索坐实。」（第三人称意图描述）
- **检定标记**：可保留 `[skill_name]` 前缀作为"激活该选项所需技能"提示，但**主体必须第一人称**
