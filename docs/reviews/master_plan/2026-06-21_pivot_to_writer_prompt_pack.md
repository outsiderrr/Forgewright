# 设计提案 · 战略转向：从「AI 生成正文」到「输出写作提示词包 + 验收校验」

> 性质：**项目级战略转向**（架构层）。作者 2026-06-21 在本会话发起 + 五点拍板 + 明示授权落 L1 文档。
> 设计先行（ADR-037 软地基纪律）：本提案先成文 → 作者已口头拍板 → 落 ADR-039 + CLAUDE.md + ROADMAP → 再施工。
> 起草：2026-06-21 执行会话（worktree agitated-bhabha-3adde6）。
> 代号：**写作提示词包转向（Writer Prompt-Pack / BYOM pivot）**。

---

## 0. TL;DR（一句话）

Forgewright 不再自己用 LLM 写对白正文。**我们的产出变成：每个场景一份"结构锁定 + 格式契约 + 文风指南"的写作提示词；正文由游戏制作人雇的编剧用他自己选的模型（BYOM, bring your own model）写出来，再回流进我们的引擎。** 我们负责"可玩的结构 + 格式契约 + 验收校验"，编剧负责"文字质感"。卡了几个月的正文质量环，被诚实地切出去了。

---

## 1. 背景与触发

**卡点**：结构层（Phase 1，多 pass + 动态拓扑）2026-06 已"有条件生产就绪"，但**文本质感/文风（Phase 2）反复卡壳**——多轮 prompt 重写、锚点库、14 维 taxonomy、judge、A/B 评估都做了，仍未稳定达到"作者少改即可用"。

**作者 2026-06-21 的新判断**（触发转向）：
1. **国内模型中文长文创作能力已经够用**——不必我们自建生成管线去追模型质量。
2. **专业文字创作者已有成熟 AI 工作流**——真实生产里制作人会雇编剧；编剧本就驾轻就熟地用 AI 写作（写提示词、调风格、人工润色）。
3. **作者本人不具备"用 AI 创作"的能力**，因此也无法基于这种能力去开发对应的创作提示词。这条最关键——"自建正文生成"对作者是能力错配。

**结论**：把"正文怎么生成、文字质量好不好"整环交给编剧 + 他的模型。我们做编剧上游真正需要、且我们已经做得好的东西——**把"可玩场景结构"压成"写作提示词包"**，并在文本回流时把住格式与一致性的闸。

## 2. 作者五点拍板（2026-06-21）

1. **路线 A**：我们锁结构，编剧只填正文（旁白 / NPC 对白 / 选项台词）。✅
2. **回流形态**：编剧（或其模型）交回"按 node_id + 选项序号对齐的填空"，我们**确定性合并**进锁定骨架。✅
3. **交付形态**：只做**手动 loop**（编剧在自己的聊天框里一场一场生成）；它是效率辅助、非核心功能。不做自动 agent loop。✅
4. **跨场景连续性做"费工版"**：NPC 跨场景状态增量 + 台词级 callback 都做。理由：既然我们只产提示词、文本质量不归我们管，提示词就要**一步到位**——把"编剧拿到 AI 初稿后人工修改"理解成一个"完美 AI"，所以提示词必须把该交代的全交代。✅
5. **Pass 2 正文引擎退役为生成路径；文风资产（role_rules / AP 规则 / 14 维 taxonomy / 锚点库）重打包为"编剧提示词包 + 可选 judge"，不删除。** ✅

## 3. 核心转向：项目的输入/输出重定义

| | 转向前 | 转向后 |
|---|---|---|
| **项目输出** | AI 生成的对白正文（scene.json 含 narration/dialogue/option.text） | **每场景一份写作提示词包**（结构骨架 + 格式契约 + 文风指南 + 跨场景连续性摘要） |
| **正文由谁写** | 我们的 generator 调中转站 LLM | **编剧用自己选的模型（BYOM）写，人工润色** |
| **文字质量谁负责** | 我们（卡点） | **编剧**（我们不负责） |
| **引擎的输入** | 我们自己的产物 | **编剧回流的正文**（按格式契约填空） |
| **我们把的闸** | 生成 + 校验 | **格式契约 + 回流校验 + 一致性**（更纯粹的"真相之源守门人"角色） |

这次转向**强化**了项目最深的几条架构原则，而非违背：
- **ADR-001（预生成选项式，运行时无 LLM）**：不变。玩家交互模式完全不动。
- **ADR-002/004（运行时 vs 生产期分离）**：不变。⚠️**诚实更正**（评审反方）：LLM **并非**彻底移出系统——生产期我们仍保留 2–3 处 LLM 调用：① Pass 1 结构引擎（contract/topology/skeleton，仍走中转站，且正是受 502 超时折磨最深的部分）；② 跨场景摘要 `scene_summary_writer`（LLM 产出）；③ 可选 judge。转向只是把 LLM 从"写正文"挪到"写结构 + 摘要"，**未消除对中转站/模型质量的依赖**。真正的赌注分界线（必须写进 ADR）= **结构（可玩分支设计）值得我们自建，因为它是工具的工程杠杆、且可被确定性校验；正文质感不值得自建，因为它是手艺 + 主观 + 受模型换代折腾 + 作者本人做不了**。
- **ADR-008（LLM 不能直接写状态）**：被推到极致——LLM 现在连"结构槽位"都不碰，只产正文文本填进我们锁定的槽；所有结构与状态由确定性代码拥有。
- **ADR-006（世界本体 = 真相之源；违反本体的内容被校验器拒收）**：更重要——回流的人类正文必须过本体一致性校验。

## 4. 架构：路线 A 的回流闭环

```
①世界观/场景意图 ──→ ②结构引擎(复用 Pass 1) ──→ ③结构骨架(锁定)
                                                      │
                                                      ▼
④写作提示词包渲染器 ──→ 每场景一份提示词(结构槽 + 格式契约 + 文风锚点 + 连续性摘要)
                                                      │
                          [编剧 + 他的模型 BYOM，系统外] ←┘
                                                      │  按 node_id+序号对齐的填空
                                                      ▼
⑤回流合并器(确定性) ──→ ⑥scene.json ──→ ⑦验收校验(schema+图+本体+机械, source=human)
                                                      │  + 可选文风 judge(QA)
                                                      ▼
                                              落地 /content/ ──→ 引擎播放
```

**关键不变量**：结构字段（node_id / target_node_id / routes / reveals / condition / effects / skill check）**全部由我们锁定**；正文字段（narration / dialogue / option.text）**全部由编剧填**。

⚠️**诚实更正**（评审）：回流合并器（P-B）是**新建模块**，不是"改几行 assemble.py"。assemble.py 消费的是同源、已知 plan 的强类型 prose dict，按**位置索引**对齐 + **静默容错**（route 缺失回退、选项数不符截断）；回流要消费**编剧自由发挥、可能漏拍/多拍/改选项数的文本**，需要：解析器（标签文本→dict）+ **node_id 主键 + 显式选项序号**对齐（位置索引对手填太脆）+ **硬报错**（语义与 assemble.py 的静默容错相反）。可复用的只是 assemble.py 的"机械字段确定性填写"那半（`_mk_option` / `target_map`），"对齐 + 容错"那半要重写。

**填空单位 = 整个场景（一次给编剧整场的节点树），不是逐节点**（评审更正：作者方案本就是"一次一个场景"）。这同时解决两件事：① 场景内节点承接——编剧/其模型看到整树、能让下游 NPC 开场白承接自己写的上游玩家台词（路线 A 下渲染提示词时尚无任何 prose，逐节点注入"玩家刚说某句"不可行）；② beats 节点逐拍呈现（见 §6a）。

## 6. 格式契约设计（回流的命门）

编剧/其模型交回的，是**按结构 key 对齐的填空**，不是自由文本——这样回流是确定性的、不需要脆弱的自然文本解析器（现仓库里本就没有这种解析器）。

**编剧提示词包内的"输出格式"段**（写进提示词，正如作者要求）形态示例：

```
请只填正文，按下面 key 原样返回（不要改 node_id、不要增删节点、不要改选项数量与顺序）：

[node: opening]
narration: <你的旁白，250-400字，白描，玩家称"你"，不替NPC转述>
dialogue:
  - <露西此刻说的话，关键信息由她自己说>
options:
  1: <对应"软化接触"意图的玩家第一人称台词，≤25字>
  2: <对应"用钱承认风险"……>
  3: <……>
  4: <……>

[node: soft_confide_b1]
narration: <……>
...
```

回流合并器按 `[node: X]` + `options.N` 反查锁定骨架的对应槽位，确定性填回。**任何 key 对不上 / 节点缺失 / 选项数不符 → 验收报错，列清单退给编剧**（不静默吞掉，复用 assemble.py 容错告警思路但作硬报错）。

> 形态二选一（施工时定，作者已同意"由我们的提示词规定"）：上面的轻量带标签格式，或直接要求模型返回"填好正文的 JSON"。两者解析都 trivial（有 key），区别只是编剧/模型的手感。倾向轻量标签格式（对聊天框手动模式更友好），JSON 作为可选严格模式。

## 7. 跨场景连续性（费工版，决策 4）

目标：让单场景提示词"一步到位"，编剧无需自己拼接前情。每份场景提示词自动注入：
1. **前序场景摘要**（复用现成 `prior_scene_summaries`）——已建立的事实、已揭露线索。
2. **NPC 跨场景状态增量**（新）——本场景 NPC 因前序玩家选择而改变的 trust/fear/affinity 等（衔接 ADR-031 NPC 状态机；本场景生成时记录 → 后续场景读取）。
3. **台词级 callback**（新）——前序场景关键对白原句片段，供编剧在本场景呼应/回收（摘要会丢口吻，原句不丢）。

**Schema 影响判定（重要，软/硬地基边界）**：第一版倾向把(2)(3)做成 **generator 侧的连续性 sidecar + 提示词注入**，**不动 `/schema`**（连续性数字只进提示词、不持久化进 dialogue_graph 运行时）。**若评审判定必须落持久化 schema 字段（如幕内场景序号、跨场景状态版本），则该子项升为硬地基**——停下、单独 schema-only ABC、作者批准后再做（ADR-037 §二 + 安全阀）。本提案先按"不动 schema"设计，把 schema 影响作为 P-D 的第一个待裁决点显式标出。

## 8. 模块边界与红线

- **只在 `/generator`（含其测试）+ `/tools`（编剧工坊辅助）施工**。运行时 `/engine` 不沾。
- **`/validator` 只读调用**（验收复用现成校验器；不改 validator 语义——若要改是软地基，单独审）。
- **`/schema` 默认不动**（见 §7 schema 影响判定；要动 = 硬地基，停下报作者 + 单独 ABC）。
- **结构层逻辑不动**（拓扑/路由/承接/组装保持现状；只是把消费端从 Pass 2 换成"渲染提示词 + 回流合并"）。
- LLM 调用（仅剩结构引擎 Pass 1 的 contract/topology/skeleton）仍走 `LLMProvider` + `budget.check_and_charge()`。
- **运行时永远无 LLM**（CLAUDE.md 架构共识 4）；编剧的模型在系统外，与运行时无关。
- **版权红线**：锚点库只收项目自产已接受文本或作者自写文本（不变）。

## 10. 阶段重构（落 ROADMAP）

转向落在 ROADMAP 阶段 3（完整内容生产流水线 + 审阅工具）内，重定义其"内容生产"含义：
- **退役**：阶段 3 内非正式的"Phase 2 文风/质感层"作为 in-house 生成路径。
- **新工作主线**（阶段 3 内）：P-A 提示词包渲染器 → P-B 回流合并+验收 → P-C 幕级打包+手动 loop → P-D 跨场景连续性（费工版）→ P-E 文风资产重打包。
- **保留**：审阅工具、批量调度（repurpose 为"批量提示词包生成 + 回流验收看板"）、一致性维护、版本控制集成。
- **对开源（阶段 4）的增益**：BYOM 形态比"绑定特定中转站的生成管线"通用得多、不受模型换代折腾——更好的 framework 故事。

## 11. 诚实的代价与风险

- **放弃"一键生成整局游戏"的演示叙事**——换成人在环里的创作步骤。但作者本就认定需雇编剧、自己做不了 AI 创作，对真实用例不是损失。
- **依赖编剧遵守格式**——由路线 A（结构锁定，编剧改不崩分支）+ 验收闸（source=human）+ key 对齐硬报错 三重缓解。
- **风格一致性从"我们控制"变为"编剧 + 我们的锚点/指南 + 可选 judge"**——这是诚实的责任划分，不是退步。
- **跨场景连续性费工版有真实工程量**（NPC 状态增量 + callback）——但作者明确要"一步到位"，接受该成本。
- **schema 影响未完全排除**（§7）——作为 P-D 第一个待裁决点显式拎出，避免偷偷动硬地基。
