## §1 ADR-015 正文（以下整段进 DECISIONS.md）

## ADR-015：游戏规则系统作为可替换插件，与编剧理论平行

**状态**：已接受（2026-05-XX，待作者签字日填）

**背景**：

- 项目短期目标是作者本人一款类博德之门 3 风格的中小型 RPG（采用 DND 5e 规则）；长期目标是开源剥离为通用"叙事内容生成 + 校验 + 导出"框架。
- ADR-005 已规定**编剧理论**（Save the Cat / 起承转结 / Egri / Story Circle 等）作为可替换插件，核心层保持中立。
- 但**游戏规则系统**（DND 5e / Pathfinder / FATE / 武侠点数 / 无规则纯叙事）——一类与编剧理论正交、但在 RPG 领域同样关键的可插件层——至今没有 ADR 显式规定其位置。
- SCHEMA_v0.md §5.7 显式排除"技能检定 / 掷骰子结构"作为 v0 字段，并把 `Option.skill_check` 推到 🔵 阶段 1+ 字段（§3.3）——这是**无 ADR 支撑的隐式决策**。若 skill_check 在阶段 1+ 真的以原形态进入核心 Schema，DND 概念就会被硬编码进框架核心，违反开源中立性。
- 2026-04-30 第 5 轮综合评审（Claude × GPT-5.5 → 见 `/docs/reviews/master_plan/2026-04-30_synthesis.md`）发现这一 GAP；2026-05-01 作者发起 L1 讨论后立项。
- 当前现状：核心 Schema（DialogueGraph / Node / Option / StateEffect / StateCondition）**事实上已经不含任何 DND 概念**；状态总线（`/state/`）的 `path` 是 schema-less key-value，DND 规则若需要 `player.stats.dexterity` 这类路径，是**内容层**选择而非引擎层假设。本 ADR 是把现状从"隐式中立"升级为"显式中立"。

**决策**：

1. **核心层中立**：框架核心层（`/engine` / `/schema` / `/state` / `/validator` / `/generator` 顶层模块）对**游戏规则系统**保持中立——与 ADR-005 对编剧理论的中立性平行。

2. **规则系统作为插件**：游戏规则系统以插件形态存在：

   ```
   /generator/plugins/
   ├── narrative_theory/<name>/   编剧理论（ADR-005 原意）
   │   └── 例：save_the_cat / kishotenketsu / story_circle / egri
   └── rule_system/<name>/        游戏规则（本 ADR 新增）
       └── 例：dnd_5e / pathfinder_2e / fate_core / wuxia_points / none
   ```

3. **`Option.skill_check` 字段降级**：从 SCHEMA_v0.md §3.3 的 🔵 阶段 1+ **核心字段**降级——不进核心 Schema；规则相关数据通过 `Option.plugin_metadata["rule_system.<name>"]` 表达（与编剧理论用 `plugin_metadata["narrative_theory.<name>"]` 形态一致）。

4. **作者本人 DND 游戏的安置**：作者 BG3 风格游戏所需的 DND 5e 规则数据进 `/generator/plugins/rule_system/dnd_5e/`（阶段 2+ 视需要建立）；该插件目录的内容**与作者私有游戏内容（`/content/`）分离**——`/content/` 仍是数据，规则插件是工具。阶段 4 开源剥离时具体决定 DND 插件是随框架附带为 example 还是仅作者私有，本 ADR 不预先决定。

5. **状态总线 path 用法澄清**：`/state/` 状态总线的 `path` 字段（D5 决议，点分字符串）由内容层自由使用——`player.dnd.dexterity` / `player.fate.aspects.high_concept` / `player.wuxia.qi` 都是合法用法。状态总线不校验路径语义，规则插件自行约束。本条与现状一致，本 ADR 仅显式确认。

**替代方案及否决理由**：

- **A. 把 DND 5e 概念硬编码进核心 Schema**（`Option.skill_check` 进核心；状态总线含 STR/DEX/HP/AC 等命名字段）
  - 违反 ADR-005 中立精神
  - 阶段 4 开源时框架失去"通用 RPG 叙事工具"价值，沦为"DND 5e 内容生成器"
  - 非 DND RPG 用户被迫接受死字段或派生分支

- **B. 不做 ADR，沿用 SCHEMA_v0.md §5.7 的隐式排除**
  - SCHEMA_v0.md §5.7 的"技能检定推到阶段 1+"是无 ADR 支撑的设计决定，阶段 1+ 真落地时仍可能犯 A 的错误
  - 阶段 2 generate_scene() / 阶段 3 审阅 UI 任何"给 Option 加规则字段"的提议都需要架构层硬约束兜底，仅靠 SCHEMA 设计文档的措辞不够

- **C. 把规则系统跟编剧理论合并到同一插件目录**
  - 两者职能不同：编剧理论决定**叙事结构如何生成**（节拍、张力、价值轴）；规则系统决定**机械检定如何裁决**（DC、骰点、抗性）
  - 合并后插件接口要同时承载两类语义，反而增加复杂度
  - 一款游戏常见组合是"Save the Cat 编剧 × DND 5e 规则"——两者是正交可乘积的，应分别插件化

**后果**：

- 开源框架卖点更清晰：从"AI 辅助分支叙事内容生产流水线"扩展到"任何规则系统的 RPG 都能用"。
- 阶段 1.5 / 2 / 3 / 4 任何"想给 Option / Node / DialogueGraph 加新字段"的提议都需要先回答一个二分问题：**这字段是核心叙事还是插件特化？** 后者一律走 `plugin_metadata`。
- 作者本人 DND 游戏需要在阶段 2+ 维护 `dnd_5e` 规则插件目录——这是新增工作量，但不在阶段 1.5 内。
- **无破坏性变更**：当前 schema 已经不含 DND 概念；本 ADR 只是固化现状 + 把 SCHEMA_v0.md §3.3 的 `skill_check` 🔵 字段降级为"非核心，由 plugin_metadata 承载"。
- SCHEMA_v0.md 需做 PATCH 更新（详见下方 §2 配套补丁）；schema_version 不 bump（结构未变，沿用 T-1.0 commit `c47c9cf` 先例）。
- 与已结案的 DEBATE_NOTES 主题不冲突——本 ADR 是 ADR-005 的扩展同位决策，不是替换。
