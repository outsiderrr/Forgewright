# 待落地点

## A. 渲染器核心（`/generator/promptpack/render_pack.py` 新建）

1. 输入（**一律经 T-3P-0 的 `promptpack/io.py` loader 读，禁止自写解析**——critique F-3）：`load_design_artifact(design.json)`（wrapper 顶层含 `design` key，loader 返回内层 dict，校验 `beats_plan` + `run_config` 齐备；图级配置从 run_config 读，**不另收配置参数**）+ `load_scene_spec(spec.json)`（现有 `{config, spec}` wrapper，返回 spec 段；loader 自动 cross-check config↔run_config；lucy 实物 `/generator/experiments/multipass_structure/specs/lucy.json`）+ 可选 prior summary sidecar 路径列表。
2. 输出：`<graph_id>.pack.md` 单文件，六段结构（拆解文档 §5.2 pack 结构逐段落地）：
   - 任务头（结构锁定声明：不改节点名 / 不增删节点 / 不改选项数量顺序去向）
   - 场景契约（design.contract 的 player_goal / npc_goal / npc_fear / forbidden）
   - 故事至此（prior summaries 复用 `render_prior_scene_summaries_block` + `character_state` 一行透传；无摘要时显式写"本场景为首场/无前情"）
   - 逐节点树序填空单：choice = function / situation / choice_pressure / 本节点揭露(reveals) / 不能给(hides) + 每选项〔intent〕+ 去向；beats 链 = 逐拍"本拍揭露"清单（beats_plan）+ 承接规则提示；end = 收束要求（80-200 字等）
   - 文风段：role_rules 编剧版重述 + 普适 AP（2/3/4/6/9）+ 白描预设（AP-1/5 + PROSE_STYLE_RULES）+ 按角色挑锚点 few-shot（narration / npc_dialogue / player_option 各若干条，带防搬运守卫文案）+ 量化契约（各字数上限 / 人称约定 D 两套 / 关键信息由 NPC 自己说）
   - 输出格式段：由 format_spec 生成——含标签语法示例 + 本场每个节点应交的 key 清单（choice 的精确选项数 / beats 拍的 continue / end 无选项）
3. CLI：**独立模块入口** `python -m generator.promptpack.render_pack --design <design.json> --spec <spec.json> [--summaries <sidecar>…] [--out <pack.md>]`（T-3P-0 CLI 约定：v1 不建共享 `__main__.py`，避免与 T-3P-2 并行冲突；argparse / kebab-case / 退出码按 format_spec 三态约定）。
