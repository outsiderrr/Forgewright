# 待落地点

## A. 确定性拆拍器（`/generator/multipass/beat_split.py` 新建）

1. 输入：topology beats 节点（`node_id` / `reveals: list[str]` / `next`）。输出锁定拆拍计划（单链）：
   ```python
   list[BeatSlot]  # BeatSlot = {beat_id: f"{pid}_b{i}", reveals: list[str], is_last: bool}
   ```
2. **不变量（测试断言）**：确定性（同输入同输出）；每条 reveal 恰好落一拍（无遗漏无重复）；保序；`beat_id` 与 `assemble.entry_graph_node_id` 的 `{pid}_b1` 约定一致；末拍 `is_last=True`。
3. 拆拍数值规则由你设计（起点参考：每拍 ≤2 条 reveals，沿用 beat_pacing.py system prompt 现行约定；0 条 reveals 的链给 1 个过场拍）。规则要**参数化**（per-beat 上限可配），默认值写死在常量。

## B. structure-only 运行模式（`/generator/multipass/engine.py`）

4. `run_multipass_scene` 增加开关（形态你定）：开启时只跑 **contract + topology + skeleton** 三类 LLM 调用，**跳过 prose / beats / end 正文调用**（ADR-039 决策五：Pass 2 退役为生成路径，代码不删）。
5. **design 增两个 key（载体形态在此锁死，P1 两任务共同消费）**：
   - `design["beats_plan"] = {beats_pid: list[BeatSlot]}`（**dict 按链分组**，不是 flat list——lucy 有 5 条 beats 链）
   - `design["run_config"] = {graph_id, scene_anchor, speaker_ref, character_refs, npc_name}`（⚠️ 关键：这些字段现状只在内存 `SceneRunConfig`，从不落盘——P-B 合并产 scene.json 的图级字段全靠它，必须随 design.json 持久化）
6. structure-only 模式不产 scene.json（无正文可装配）；`write_artifacts` 落 design.json（含上述两 key）+ metrics.json；status/failure 语义沿现状。
