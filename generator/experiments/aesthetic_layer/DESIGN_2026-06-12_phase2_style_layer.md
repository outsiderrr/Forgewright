## 1. 决策 A：文风维度 taxonomy 提案（14 维）

每维配真实正/反例句（出处标注：✅ = 作者已接受样本；❌ = 被拒样本/canonical 反例；
〔构造〕= 无真实存档、构造示意）。judge 按维打 1–5 分（除标注"描述性"者）。

### 旁白组（narration）

**S1 白描密度** —— 细节先于评价；评价必须有可观察细节铺垫。
- 正例 ✅（whitcroft v2 开场）：「他清了两次嗓子，目光从你的证件、手套、衣袖依次扫过，最后停在你是否带了记录本的位置。」
- 反例 ❌（AP-5 canonical）：「眼神却老练得不像二十五六岁的人」
- 关联：AP-5（预设层，见决策 B）。

**S2 修辞质量与克制** —— 比喻少而准；用喻必有锚（喻体与本体共同点清楚）。
- 正例 ✅（whitcroft v2）：「视网膜组织遭高温损伤，像有什么把玻璃体液煮沸了。」（高温 + 液体，锚清楚）
- 反例 ❌（AP-2 canonical）：「托盘在她指尖稳得像变戏法」
- 校准存档（PHASE2_INPUT §3）：「像有人在墙后拖动沉重的抽屉」判 OK；「像是把话也压在那里」borderline。

**S3 感官层次** —— 视觉之外有听/嗅/触觉分布，不是纯视觉陈设罗列。
- 正例 ✅（whitcroft v2）：「你闻到消毒水、旧纸和低温金属混在一起的气味。」「隔壁传来冷机低沉的震动，门框随之轻轻发颤」
- 反例〔构造〕：连续多句只罗列家具陈设与颜色，无声音/气味/温度。

**S4 物理动作词汇多样性** —— 道具动作不跨节点复读；同一道具要有状态演进。
- 正例 ✅（whitcroft v2 全场）：死亡证明副本在不同节拍呈现不同物理状态（压在病历夹下→翻到签名页→按出折痕→推回桌角）。
- 反例 ✅⚠️（lucy c1 ——**已接受样本中仍存在**的可提升项）：「她把空杯推到水槽旁/边」全场出现 ≥4 次；复核观察 #1 抹布/报纸翻页跨链反复。
- 注：规则难治（复核结论），锚点样例 + judge 盯防是主路径。

**S5 异常呈现克制度** —— 超自然以可复核物理细节出现（最好经 NPC 之口），不堆形容词。
- 正例 ✅（lucy c1）：「他只说过一句怪话：屋子外面量只有二十步宽，进屋量却多出四步。」
- 反例〔构造〕：「一股说不清道不明的诡异寒意爬上你的脊背」（形容词堆砌型）。

**S6 句长节奏** —— 长短句交替；短句用在压力点，不连续等长句。
- 正例 ✅（lucy c1 end）：「门在身后合上，冷气从门缝里退回去。」（短句收拍）
- 反例〔构造〕：连续四个 20+ 字等长句的描写段。

**S7 收束质感**（end 节点专用）—— 物理收束 + 清点带走之物；不抒情总结、不评判。
- 正例 ✅（lucy c1 end_soft_depart）：「你把第七码碑、断了半截的电线杆、雨桶和小铁盒几个词按顺序记在票根背面。」
- 反例 ❌（vick c2 end，预筛 AP-7 属实项）：「桌上的名片、酒杯和那只未点燃的雪茄仍按原位摆着，像一场谈话刚被收进抽屉。」（比喻总结收束）

### NPC 对白组（dialogue）

**S8 角色声纹** —— 措辞/句长/职业腔区分 NPC，不同 NPC 不可互换台词。
- 正例 ✅：露西的酒馆短句防御腔「要喝什么就说清楚，别站在柜台前挡路。」 vs 惠特克罗夫特的从句职业腔「我已经签过死亡证明，官方说法也很清楚。」
- 反例〔构造〕：两个 NPC 的台词调换主语后读不出差别。

**S9 潜台词浓度** —— 话里有未说尽的东西；动机靠行为与省略呈现，不自我剖白。
- 正例 ✅（whitcroft v2，答"你为什么这么着急？"）：「因为它在那儿。」
- 反例〔构造〕：「我很害怕，因为那具尸体让我想起自己掩盖真相的罪恶感。」（动机说尽）
- 邻接反例 ❌（whitcroft v1，作者点名的 AP-4 漏网）：「别把我的停顿当成迷信」（虚空立靶否定，预防性自我剖白的变体）。

**S10 对白口语质感** —— NPC 说话像说话，不像书面公文/翻译腔；允许角色化文雅（维克式）但不对仗成文。
- 正例 ✅（lucy c1）：「钱我收了，你也别在这里喊那些词。」
- 反例〔构造〕：「我无法向你透露更多信息，这超出了我的职权范围。」（公文腔）

### 玩家选项组（options / continue）

**S11 选项自然口语度** —— 自然口语优先于"短"；反电报体（作者口径 1，已是 beat prompt 规则，升格为锚点维度持续盯）。
- 正例 ✅（whitcroft v2）：「你为什么这么着急？」
- 反例 ❌（作者拒收原型）：「为什么急？」

**S12 接话形态多样性** —— 追问/确认代称/动作三形态合理混合；不复述 NPC 刚说的内容（作者口径 2）。
- 正例 ✅：「我知道了。」（确认代称）／「[ 记下路标。 ]」（动作推进，lucy c1）
- 反例〔构造，D 项已修仍需 judge 盯〕：NPC 刚说「东西在雨桶底下」，下一拍选项写「东西在雨桶底下？」

### 全局组

**S13 温度对齐** —— 暗黑 + 灰色基线；人物无纯善纯恶（AESTHETIC_PREFERENCES §3.1，量化值有意 TBD）。
- 正例 ✅（lucy c1）：露西帮玩家但只为把麻烦转走——「你去那里，把他留下的东西拿走，别再让它跟这间酒馆扯上关系。」
- 反例〔构造〕：NPC 出于纯粹善意倾囊相助。
- **judge v1 只做描述性输出，不打分、不进 gate**（校准值待作者积累后补）。

**S14 选项人称约定一致性** —— choice 节点选项与 beat 接话的第一人称约定统一（→ 决策 D 定约定，judge 查一致性）。
- 现状两套并存 ✅：choice 选项「我低声说，不提那些字。」（带"我"）vs beat 接话「那里怎么走？」（隐含）。

> 维度数 = 14（落在 handoff 要求的 10–20 区间）。判断"少改即可用"的 gate 子集建议 =
> S1/S2/S4/S9/S11/S12（≥4 分），其余作观测维度——gate 子集也请作者勾选确认。

## 2. 决策 B：10 条 AP 规则分层提案

| AP | 内容 | 建议分层 | 理由 |
|---|---|---|---|
| AP-1 | 对仗式/重复对应感 | **审美预设** | 排比/对仗是合法风格选项（演说腔、哥特腔可用）；"后半重复明示前半"的冗余内核由 judge 在 S1/S2 维度兜底 |
| AP-2 | 修辞失底（喻体无锚） | **普适结构** | 坏比喻在任何风格都是坏比喻——这是反"坏修辞"，不是反修辞 |
| AP-3 | 修辞方向/物理逻辑错误 | **普适结构** | 物理逻辑错误与风格无关 |
| AP-4 | 假靶子否定 | **普适结构** | 否定读者没预期的靶子 = 沟通失败，风格无关 |
| AP-5 | 总结代细节 | **审美预设** | 白描审美的核心条款；全知评论腔（狄更斯式）是合法的另一种预设 |
| AP-6 | 锚定未说明的标准 | **普适结构** | 读者无法 fill in 的对比基准 = 信息失败 |
| AP-7 | 旁白转述 NPC 对白（程序化） | **普适结构** | role_rules 工程契约（信息归属），非审美 |
| AP-8 | 选项第三人称意图标签（程序化） | **普适结构** | 上位讨论明点的普适例 |
| AP-9 | 读不懂的省略 | **普适结构** | 留白无线索 = 沟通失败 |
| AP-10 | NPC 引号内单字代称自己（程序化） | **普适结构** | AI 腔 artifact，任何风格都怪 |

即：**8 普适 + 2 预设（AP-1 / AP-5）**。

pass2 现有 narration 规则段同步拆分：
- 「长度 250-400 字 / 每句承担功能 / 不替 NPC 转述 / 玩家写"你" / 不替玩家总结选择结构」
  → **普适结构层**（工程与结构契约，保持现状）。
- 「白描为主：少抽象评价、少漂亮警句，不排比/不对仗/不堆成语/不押韵」
  → **白描预设层**内容，随预设可换。

### 预设开关机制（prompt 装配层参数化）

新增 `generator/prompts/style/` 子包：

```
generator/prompts/style/
  __init__.py            # build_style_block(preset="baimiao", role=..., anchors=...)
  presets/
    baimiao.py           # 白描预设 = 预设类 AP 条款（AP-1/AP-5）+ 白描文风段 + 锚点库引用
  anchors_v1.json        # 锚点库（作者批准后落地；见 §3）
```

- `build_style_block()` 输出"文风段 + 预设 AP 条款 + 按角色挑选的锚点"，替换
  pass2/beat_pacing/end 三处现在硬编码的白描句与 `ANTI_PATTERN_BLACKLIST_TEXT` 注入
  （普适条款 AP-2/3/4/6/9 仍直接注入，**不随预设动**）。
- 默认 preset = `baimiao`，行为与现状语义一致；换预设 = 换 presets/ 下一个文件 + 换锚点库，
  核心管线零改动——兑现"文风成为参数"的新初心，且不为本期增加任何新预设（只立机制）。

### 注入方式与 token 预算（ADR-018 按需注入精神）

按调用类型只注入相关角色的锚点，不全量倾倒：

| 调用 | 注入内容 | 估算增量（汉字≈token） |
|---|---|---|
| pass2（开场） | 开场旁白 ×1 + 对白 ×2 + 选项 ×3 | ~600 |
| pass2（中段） | 节拍旁白 ×1 + 对白 ×2 + 选项 ×3 | ~400 |
| beat_pacing | 节拍旁白 ×2 + 对白 ×2 + 接话 ×3 | ~500 |
| end 收束 | 收束旁白 ×1 + 收尾对白 ×1 | ~350 |

单场景 ~16 调用 → 输入增量 ~7–9k token。对照现状每调用已有 6–9k 固定输入开销、
单场景 $0.36–0.53，预估**成本增量 < 10%（约 +$0.03–0.05/场）**。施工后给实测数字。

## 4. 同维 judge（LLM-as-judge）形态

- **位置**：`generator/judge/`（新子包：`style_judge.py` + `report.py` + CLI 脚本 +
  `generator/prompts/judge/style_judge_prompt.py`）。**不进 /validator**（validator 保持确定性，
  ADR-008 边界铁律）；validator 的 AP-7/8/10 程序化检测不动。
- **输入**：组装后的 scene.json（与 render.py 同源）；按链分块（每调用 3–5 节点），
  est_output_tokens ≤ 2000 护栏沿用；走 `LLMProvider` + `budget.check_and_charge()`（ADR-011/012）。
- **打分**：拍板后的 taxonomy 逐维 1–5（S13 描述性除外），每个分数必须附原文引句证据；
  AP-1~6 + AP-9 违规检出 = `{ap_id, node_id, 引句, 理由}`（执行 7 条提示词版黑名单的
  judge 层承接，原计划）。
- **铁律写进 judge prompt**：只按给定条款打分/检出，**不得自创新标准**；拿不准 = 不报
  （作者口径 3：不为个案扩规则集；judge 是执行已有标准，不是立新标准）。
- **产出**：`judge_report.json`（机读：逐维分数 + 违规清单 + 汇总）+ `judge_report.md`
  （人读：对齐 REVIEW_REPORT 习惯——总表 + 逐项引句）。
- **成本**：每场景 ~4–6 次小调用，~$0.05–0.15。
